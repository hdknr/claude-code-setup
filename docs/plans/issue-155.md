# #155 — `test-check-all.py` が「コメントアウトされた CI ステップ」を走ると数える

## 0. 何を直すか

`scripts/test-check-all.py` の `test_ci_runs_every_registered_script()` は、
**`"run:" in l` を満たす行**からスクリプト名を拾う。
**`# - run: python3 scripts/check-foo.py` もこれを満たす**ので、
**CI のステップをコメントアウトしても検査は緑のまま**である。

守ろうとしているのは「**手元では緑、CI では 1 度も走っていない**」形で、
実際に `test-find-cycle.py`（#136 段 1）と `test-collect-guard-rejections.py`（#122）が
その状態で出荷されていた。**コメントアウトはその形に戻る最短経路である。**

## 1. 変更範囲

触る:

- `docs/plans/issue-155.md` — この計画ファイル
- `scripts/test-check-all.py` — 判別の実装・報告の分離・変異テスト・主張のマーカー
- `CLAUDE.md` — 一覧の `test-check-all.py` の行（**何を守るかは docstring を正とする**ので、指すだけ）

触らない:

- `.github/workflows/` — **実物の yaml は 1 バイトも書き換えない。**
  **コメントアウトを当てるのは複製に対してだけ**（`check-mutation-claims.py` が複製を作る）
- `scripts/check-all.py` — 収録の一覧は動かない（**この周はスクリプトを 1 本も足さない**）
- `plugins/` — 規範の本文も版も動かさない（**スクリプトだけの周なので version bump は発生しない**）
- `diagrams/` — 図は触らない

**#137 / #138 が別セッションで並行している。** **触る 3 ファイルはどちらとも重ならない**
（#137 は `collect-guard-rejections.py` 系と `plugins/`、#138 は `check-duplicate-counts.py` 系と
`check-all.py` / `plugins.yml`）。**`CLAUDE.md` だけが同じ箇条書きの別の行に当たる。**

## 2. 乗るデプロイ経路

**`scripts/` と `CLAUDE.md` のみ。** 公開サイト（`docs/`）のビルド対象に計画ファイルは載るが、
**プラグインの配布経路には乗らない**（`plugins/` を触らないため）。
経路は PR → main マージ → GitHub Actions。

## 3. verify の受入基準

### 3.1 不変条件と、それを破りうる経路

**不変条件 A: `check-all.py` に収録されたスクリプトは、CI の yaml で*実際に走る形*で
書かれていること。それを検査が判定できる。**

**経路は「差分」からではなく、「yaml でステップを走らなくする入口」から数える:**

| # | 経路 | いまの実装 | この周の後 |
| --- | --- | --- | --- |
| 1 | ステップを丸ごと削除する | 検出する | 検出する（**「そもそも無い」と報告**） |
| 2 | **`run:` 行をコメントアウトする**（`# run:` / `# - run:`） | **素通し** | **検出する（「コメントアウト」と報告）** |
| 3 | `- name:` のラベルにだけ名前を書く（`run:` が無い） | 検出する | 検出する |
| 4 | `check-X.py` が `test-check-X.py` に覆い隠される | 検出する | 検出する（**回帰させない**） |
| 5 | **行末コメントにだけ名前がある**（`run: echo  # scripts/x.py`） | **素通し**（生きた名前として数える） | **生きた名前として数えない** |
| 6 | `run: \|` のブロック本文で呼ぶ | 数えない（**偽陽性側に倒れる**） | **変えない**（§3.3） |
| 7 | `if:` を常に偽にする・`continue-on-error` で握り潰す | 見ていない | **見ない**（§3.3） |
| 8 | ワークフローファイルごと消す・`on:` を変える | 見ていない | **見ない**（§3.3） |

**不変条件 B: 「そもそも無い」と「コメントアウトされた」を区別して報告すること。**
**どちらも「CI では走らない」だが、直し方が違う**（前者はステップを足す、後者は `#` を外す）。

**不変条件 C: 判別の実装を壊すと、この回帰テストが赤になること。**
**いまの `MUTANTS` はこの経路に 1 件も当たっていない。**

**不変条件 D: 検査は実リポジトリを 1 バイトも書き換えないこと**（既存の性質を回帰させない）。

### 3.2 何を目視できたら通ったと言えるか

1. **`.github/workflows/plugins.yml` の生きたステップを 1 つコメントアウトすると、
   `python3 scripts/test-check-all.py` が赤になる。**
   **陽性対照つき**——**コメントアウトしていない状態では緑**であること。
   **実物を書き換えずに当てる**——`mutation-claim:` を置き、`check-mutation-claims.py` に
   複製上で当てさせる（**陽性対照はこの機構が構造的に取る**——緑を確かめてから変異する）。
2. **報告が 2 つに割れている**——「CI の yaml に無い」と「コメントアウトされている」が
   別の行に出る（経路 1 と 2 の両方を合成試料で踏ませて目視）。
3. **`SCAN_MUTANTS` が全件「契約を破る」**——判別の実装を 1 箇所ずつ壊して、
   合成試料の契約が破れること。
4. **`python3 scripts/check-all.py` が緑**（**1 本ずつ選ばない**。`CLAUDE.md` の規定）。
5. **`git status` が、触ると宣言した 3 ファイル以外を出さない**（不変条件 D の目視）。
6. **PR 側が緑**——`gh pr checks` で見る。**手元の緑を根拠に「緑」と報告しない。**

### 3.3 この環境では証明できないもの（未証明）

- **「CI で実際に走った」の証明にはならない。** 見ているのは yaml の**記述**だけで、
  **ジョブの `if:` 条件・`continue-on-error`・ステップ内での失敗握り潰し**は見ていない。
  **言えるのは「走る形で書かれている」まで**（Issue #155 の限界節がそう宣言している）。
- **`run: |` のブロック本文で呼ばれたスクリプトは拾わない。** いまも拾っておらず、
  **この周でも直さない**——**偽陽性（在るのに「無い」と言う）側に倒れる**ので、
  **黙って素通しする今回の欠陥とは向きが逆**である。該当は現在 0 件。
- **これらは受入基準に挙げない**ので、**BLOCKED ではない**
  （BLOCKED と呼べるのは §3.1／§3.2 に挙げた項目だけ。手順 5 の規定）。
  **「限界」として PR コメントに残す。**

## 6. 既知の限界・決着済みの論点

| 論点 | 決着 | 理由 |
| --- | --- | --- |
| `if:` / `continue-on-error` / 失敗握り潰しを見るか | **採らない** | Issue #155 が限界として宣言している。**見ているのは記述であって実行ではない** |
| `run: \|` のブロック本文を拾うか | **採らない** | **偽陽性側に倒れる欠陥**で、今回の欠陥（黙って素通し）とは向きが逆。該当 0 件 |
| YAML パーサ（PyYAML）を使うか | **採らない** | **このリポジトリのスクリプトは標準ライブラリのみ**（`CLAUDE.md`）。行単位のコメント判別で足りる |
| 判別を共有モジュール（`site_links.py` のような形）に出すか | **採らない** | **利用者が 1 本しか無い。**「式が 2 箇所にある」問題は発生しない |
| 新しい歯止めスクリプトを 1 本足すか | **採らない** | **#136 が止めた「再帰に終端が無い」がここで復活する。** 既存の回帰テストの中で閉じる |
| #138 の周と `check-all.py` / `plugins.yml` で衝突しないか | **衝突しない** | **この周は両方とも触らない**（§1） |
| ファイル境界で行が繋がる（末尾に改行の無い yaml） | **採って直した** | `"\n".join` にした。**手順 5 の Verifier の指摘**（実害は現時点で無い＝全ファイルが改行で終わる） |
| 引用された値をどう見分けるか | **値の先頭に立ち、同じ行で閉じた引用符だけ**（2 パス目で作り直した） | **行のどこの引用符も数えると、パリティが途中で反転して #155 と同じ向きの偽陰性になる**（1 パス目 HIGH・2 パス目 HIGH / MEDIUM の 3 形とも、根はこれ 1 つ） |
| 閉じない引用符をどう扱うか | **信じない（安全側＝コメント扱い）** | 信じると行末までが「値」になってコメントを飲み込む。**倒れてよいのは偽陽性側**（宣言済み） |
| 行末で殺した形（`run: echo skip  # python3 scripts/x.py`）を「コメントアウト」と数えるか | **数えない** | **注記で名前に触れただけの行と構文で区別できない。** 推測で倒すと逆向きの誤報を黙って出す。**赤にはなる**（不変条件 A） |
| 2 行に割ったコメントアウトをコメント側として拾うか | **拾わない** | 同上。**射程を docstring と契約に固定した**（守らない側の行） |

**決着の*理由*が誤っていると判断したなら、それは新しい反証である。**
