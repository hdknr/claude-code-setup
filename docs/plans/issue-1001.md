## 仕様の穴（推奨で決めた。`仕様の穴 = 推奨で決めて起票` の線）

Issue は「やること（たたき台）」で 2 つを「要確認」「決める」としている。実装に要るので、選択肢を挙げて推奨で決め、穴ごとに確認の Issue を立てる。

1. **振る舞いを変える周が正本に何を残すか**（1 パス目の `/code-review` CR1 で決め直した。最初は A を推していた）
   - A: 作業中の版の共有の Q&A 表（`docs/v<n>/shared/qa.csv`）に、周が起票元 `開発（#<Issue>）`・回答 `未回答`・状態 `確認中` の行を直接足す——**同じリポジトリでは、spec-loop の `scaffold.py --check`（抜ける条件 1）が 1 になり、#1000 の決まりで製品の CI がそれを当てるので、この周の PR が利用者の答えまで赤のままになる**（`/code-review` が実測）
