## 既知の限界・決着済みの論点

- **言い換えた重複は照らさない**——docstring の「守らないもの」（見るのは文がそのまま一致する行だけ）のまま。採らなかった（#998 で決着）。
- **重複を見つけたら違反 1 で JSON 全体を何も書かない**——#998 の既存の扱い（同じ JSON の中の重複・既にある質問との重複）に揃えた。重複の候補だけ飛ばして残りを書く形は採らなかった（扱いを 2 つにしない）。
- **改行は最初の行（見出し）の改行で決める**——行ごとに改行が混ざった表は、見出しの改行で足す。混ざった表は Excel も他の道具もふつうは作らない。
- **質問の文そのものに「（コードではこうなっていた: 」が入り、末尾が「）」の手書きの行は、その手前までの文で照らす**——ふつうは作らない書き方。
- **陽性対照**: 修正前の本体（`fd1afe51` の `plugins/spec-loop/scripts/`）に新しいテストを当てると、足した 3 試料（rows_rerun・rows_rerun_edited・rows_bom_crlf）だけが落ち、既存の 30 試料は通った（著者が scratchpad の写しで確かめた）。
- **著者が当てた変異**（`scripts/test-intake-code.py` の `MUTATIONS` の末尾 6 件）: 添え書きを外さずに照らす・`bare` が外さない・BOM を落として読む（`utf-8-sig`）・改行を揃えて読む（`read_text`）・足した行を LF で書く・末尾に改行の無い表に LF を足す。全部赤（`OK: 試料 33 件・変異 44 件`）。最初に入れた「BOM を落とす（`bom = False`）」は等価変異で素通りしたので、BOM を文字のまま残す形に本体を簡単にして変異を差し替えた。

- **1 パス目の指摘対応（CR1-2・CR1-4）**: 照合を 2 本にした——候補の質問 × 既にある行の質問から添え書きを外した文（`asked`）と、足す行の質問（添え書きつき）× 既にある行の質問のそのままの文（`asked_whole`）。足す行が無ければ表を書かない。
  試料 2 件（rows_rerun_note_in_behavior・rows_empty_keeps_bytes）と変異 2 件を足し、`OK: 試料 35 件・変異 46 件`。同じ候補の当て直しは `asked_whole` でも捕まるので、「添え書きを外さずに照らす」変異の試料は rows_rerun_edited（`code_behavior` を直した当て直し）に移した。
