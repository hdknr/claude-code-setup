## 設計の判断

- 外部の profile の画面の層に、4 つ目の行の種類 **`答え`** を足す。`表`・`列` で組み込みの profile の「誰が決めるか」の項目を名指し、`要約` と `リンク` が既定の答えを指す（本文は写さない）。
- `check-screens.py` は、項目の「誰が決めるか」の起票する表（`references/profiles.md` の表の 3 列目）で、利用者の部分（`shared/qa.csv`）は推奨つきの共有の候補、開発者の部分（`spec/qa-dev.csv`）は既定を採った内部の候補にする。
  「誰が決めるか」の表は今は本体の定数に写しが無いので、`PROFILES["web-spa"]["deciders"]`（項目 → 起票する表の並び）として写し、テストが原本と突き合わせる。
- 候補は `起票の候補: ` で始まる行で出す（今の起票の候補と同じ頭。req-loop は `screen-spec: 起票の候補: ` で始まる行を読む）。番号は振らない。出すのは表のパス・項目・決める人・行の ID・要約・リンクだけ。
- 候補は終了コードを変えない（今の起票の候補と同じ）。
- 起票した候補を出し続けないように、その候補の Q&A 表（共有か内部）の行のどれかの `質問` に行の ID が書いてあれば、その候補を出さない（G3）。
- 画面の層の `答え` の行が決まりに合わなければ検査の前に止める（4。今の画面の層の行と同じ扱い）。
- 複製の数: 決まりの原本（`references/profiles.md` の節）1・本体の定数と docstring 1（テストが原本と突き合わせる）・`tables.md` の起票の候補の説明 1・README の 1 文・CLAUDE.md の 1 句——**分けない理由**: 原本以外は指すだけにし、定数の写しはテストが見る（screen-spec の既存の形。#1458 と同じ）。
