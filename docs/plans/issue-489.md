## 仕様の穴（不在の線で推奨により決めた）

穴: プラグインの配布（main の `.claude-plugin/marketplace.json` の版が上がり、利用者が `plugin update`・`autoUpdate` で取る）を起こすマージを、
不在の周がマージしてよい反映に入れるか。

選択肢:

- **(a) 入れない**——`マージの反映:` の値は `ドキュメントのみ` のまま。このリポジトリの不在の cruise は各周が PR まで作って止まる。
  代わりに居る cruise を案内し、起動時の確認で「プラグインの配布」を名指しする
- **(b) 入れる・恒久の宣言**——新しい値 `ドキュメントとプラグインの配布` を足し、`.claude/dev-loop.md` の宣言と `マージ` の線（どの出所でも）で効かせる
- **(c) 入れる・宣言は事実、同意は cruise ごと**——新しい値 `ドキュメントとプラグインの配布` を足して事実（マージが何を起こすか）を `.claude/dev-loop.md` に宣言し、
  **`マージ` の線がその cruise・その周に限った利用者の確認（台帳の確かめた線か、その周の利用者の直接の指示）から来たときだけ効かせる**——
  `.claude/dev-loop.md` の `不在の線: マージ` だけでは効かない。cruise の起動時の確認で、この線が配布を起こすことを名指ししてから確かめる

**決めた値: (c)。** 理由:

- 利用者は 2026-10-28、cruise #474 に限って「関門を通り CI が緑で main と衝突しない PR は、配布を起こすマージも不在でしてよい」と確かめた
  （台帳 `issue-474` の線の出所に記録がある）。**許可は cruise 単位で、恒久の宣言ではなかった**——(c) はこの形をそのまま決まりにする
- (a) では、利用者がそう確かめても決まりの上では効かない（`本番反映` は広げられず、`マージの反映:` の出所は `.claude/dev-loop.md` だけ）。
  #489 が述べる「PR が溜まって衝突する」形が毎回残る
- (b) では、一度宣言すれば以後の不在の周がどれも配布を起こせる。配布は revert しても取った利用者のキャッシュ・`installed_plugins.json` が戻らない
  （CLAUDE.md の「キャッシュに在ることは、読み込まれることではない」）ので、その都度の同意に寄せる
- 宣言（事実）と同意（判断）を分けると、事実は PR を通る場所に 1 度だけ置け（#476 の決まりのまま）、判断は cruise ごとに利用者が持つ

**別の値なら直す場所**: (a) なら `.claude/dev-loop.md` の行を消し、`absent-lines.md` の新しい値の項と cruise の `SKILL.md` §2 の名指しを外す。
(b) なら `absent-lines.md` の新しい値の項から「`.claude/dev-loop.md` の `不在の線: マージ` だけでは効かない」を外す。
