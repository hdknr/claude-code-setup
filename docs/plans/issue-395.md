## verify の受入基準

不変条件 × それを破りうる経路。経路は「直す線が決まる入口」と「直す線が効く場面」から数える。

1. **既定の線は変わらない**——何も選ばれなければ「示せる」かつ「受入基準を破る」行だけ直す。
   経路: `.claude/dev-loop.md` が無い／`直す線:` の行が無い・`AskUserQuestion` に答えが返らない・
   再開した周で計画ファイルに直す線が無い（この版より前の周を含む）・値が `既定`／`広げる` のどちらでもない・
   行が 2 本以上ある（2 パス目の再導出で追加）・線を広げる → 既定に戻した（2 パス目の再導出で追加）
2. **線を広げられるのは利用者だけ**。経路: 手順 3 の回答（可）・`.claude/dev-loop.md`（可）・周の途中の利用者の明示の指示（可）・
   Issue 本文／コメント（不可）・関門の報告（不可）・委譲先の報告（不可）・著者の判断（不可）・
   他人の PR・fork の `.claude/dev-loop.md` の `直す線: 広げる`（従わずに訊く。2 パス目の再導出で追加）
3. **広げた線で足されるのは「示せる」かつ「指摘を受けた時点の `触る:` に収まる」行だけ**。
   経路: 1 パス目の指摘・2 パス目の指摘・狭いパスの指摘（足されない。人間が決める）・`触る:` を後から足して収める（不可）・
   振る舞いの指摘（走らせた出力でなければ「示せる」にならない、がそのまま掛かる）
4. **広げても変わらないもの**: 2 パスの打ち切り・2 パス目で直した行はすべて狭いパス（「条件を付けない」の理由が線に依らず成り立つ）・
   受入基準は手順 3 で固定・起票の 3 条件・関門は計画ファイルと PR コメントを検査しない。
   経路: `SKILL.md` 手順 6 の各項・`references/fix-line.md`
5. **記録が残る**: 計画ファイルに直す線・出所・（途中で変えたなら）変えた時点。採否の表で広げた線で直した行が見分けられる。
   PR コメントに使った線が載る。経路: 新規の周・再開した周・周の途中の変更（既定で始めた周を含む。2 パス目の再導出で追加）
6. **複製の整合**: 上の 7 箇所のどれも、無条件の「だけ」として既定の線を言い切らず、手順 6 か `references/fix-line.md` を指す
   （文面が主張する事実の真偽も見る——「既定では」と書いた先が実際に既定を定めているか）
7. **構造の歯止め**: 版 3 種の一致・§8.2 の生成ブロックの鮮度・指し先の実在（`references/fix-line.md` と散文の指し先）・
   必須マーカーが原本の外に無い——`python3 scripts/check-all.py` が緑
8. **必須要件の掛け算**: 受入基準を Verifier と `/code-review` の両方に、1 パス目と 2 パス目の両方で渡す（4 つの受け渡し）
