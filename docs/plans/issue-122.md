`measure-guard-os.sh` のヒアドキュメントに埋めていたが、**macOS 側も同じ probe で

**そうすると、観測された差が「OS の差」なのか「当てた形の差」なのか判別できない**

**だから probe の一覧を 1 ファイルに寄せ、外側は「コンテナに流すか、ホストで走らせるか」
だけを決める形にした。**

**受入基準も広げた**——3.2 に **P8**（両 OS で当てた形がずれる）を足した。

**触らないと決めた:**

  **この周の後も BLOCKED のまま残す。**

## 3. verify の受入基準

### 3.1 不変条件

| # | 不変条件 |
| --- | --- |
| **I1** | `SKILL.md` がガードについて述べる運用指示が、**Linux でも成り立つ**（あるいは、成り立たない点が名指しされている） |
| **I2** | 測定は**交絡を潰している**——陽性対照を取り、振る次元を 1 つに絞り、観測窓を書く |
| **I3** | 述べることが**測った範囲を超えていない**（境界を断定しない。#110 で 4 度壊れた型） |
| **I4** | **環境が記録されている**——OS・harness 版・git 版・観測日時 |
| **I5** | 収集スクリプトが**拒否イベントを落としていない**（`<tool_use_error>` の包みを剥がす。#112 でここが 2 度壊れた） |

### 3.2 I1 を破りうる経路（差分ではなく「測定が壊れる入口」から数える）

| # | 経路 | 守り方 |
| --- | --- | --- |
| **P1** | **Linux でガードがそもそも発火しない**（機能が無い・条件が違う）→ 拒否 0 件が出る。**主張が偽でも同じ出力**の典型 | **陽性対照**: macOS で拒否された形を Linux で流し、**拒否が出ること**を先に見る。出なければ「Linux では成り立たない」ではなく「**測定が成立していない**」と判定する |
| **P2** | **harness 版が違う**（macOS 側は 2.1.278）→ **OS の差と版の差が交絡する** | Dockerfile で**同じ版を固定**する。固定できなければ、その旨を明記して結論を弱める |
| **P3** | **認証形態が違う**（API キー / OAuth）→ ハーネスの経路が変わりうる | 使った認証形態を記録する。**これは潰せない可能性がある**（潰せなければ交絡として明記） |
| **P4** | **パスの形が違う**（`/Users` → `/root` 等）→ 理由節に埋まるパスが変わる | 理由節は**パスを伏せて**正規化する（前半 #133 と同じ手） |
| **P5** | **トランスクリプトの置き場所・形式が違う**→ 収集が黙って 0 件になる | **先にレコード件数を見る**。0 件なら収集の失敗と拒否 0 件を区別する |
| **P6** | **worktree 隔離セッションの作り方が違う**→ 隔離されていないセッションを測る | セッションが**隔離下にあること**を、拒否以外の手段で確かめる（陽性対照と同じ観測点） |
| **P7** | **コンテナが aarch64**（ホストが Apple Silicon）→ アーキテクチャと OS が同時に変わる | アーキテクチャを記録する。**振った次元が 2 つ**なので、結論に添える |
| **P8** | **両 OS で当てた形がずれる**（probe の一覧が 2 箇所にある）→ 観測された差が OS の差か probe の差か判別できない | **probe の一覧を `measure-guard-os-inner.sh` の 1 箇所に置く**。外側は流し先を選ぶだけ |
| **P9** | **標準出力で結末を判定する**→ ガードが発火したかではなく「モデルが拒否文を引用したか」を測ってしまう | **判定はトランスクリプトで行う**。実際に R7 でこの取り違えが起きた（下記） |

    - **揃わなかったものが 1 つ**: **git の版**（macOS 2.54.0 / 像 2.39.5）。

## 4.5 測った結果（2026-09-20）

### 環境（振った次元は OS だけ）

| | Linux | macOS |
| --- | --- | --- |
| `uname -sm` | `Linux aarch64`（OrbStack / `node:22-slim`） | `Darwin arm64` |
| harness | **2.1.278** | **2.1.278** |
| git | 2.39.5 | 2.54.0 (Apple Git-157) |
| 認証 | `setup-token` の長期トークン | 同じサブスクリプション |
| 当てた形 | **同じ `measure-guard-os-inner.sh`** | 同左 |

**揃わなかったのは git の版だけ。** ガードは harness の機能であって git の機能ではないが、
**揃っていないことは記録しておく。**

### 結末（probe 8 件。判定はトランスクリプト）

| probe | 当てた形 | Linux | macOS |
| --- | --- | --- | --- |
| R1 | `test "$(git …)" != "$(git …)" && …` | 拒否 | 拒否 |
| R2 | `S=probe; python3 <ROOT>/$S.py` | 拒否 | 拒否 |
| R4 | `F=/etc/hostname; sed -n 1,2p $F` | 拒否 | 拒否 |
| R5 | `git -C <共有チェックアウト> rev-parse` | 拒否 | 拒否 |
| R6 | `git -C . rev-parse` | 拒否 | 拒否 |
| R7 | **ファイル編集ツールで共有側のパスを編集** | 拒否 | 拒否 |
| C1 | `echo a && echo b` | **通過** | **通過** |
| C2 | `git rev-parse --git-dir` | **通過** | **通過** |

- **理由節（パスを伏せた）の集合は完全一致**——**両側 6 通り、差は 0 件**。
- **メッセージの形も一致**——R1〜R6 は**素・規則文あり**、**R7 だけ `<tool_use_error>` に
  包まれ、規則文を持たない**（`, but ` が無いので理由節も取れない）。**これが両 OS で同じ。**
- **陽性対照（C1 / C2）が両側で通っている**ので、**「拒否 0 件」と「測定の失敗」は
  区別できている。**

### 途中で 1 度、測り方のほうが壊れていた（P9）

**最初、probe の結末を*標準出力*に拒否文が出ているかで判定していた。**
その判定では **R7 が「Linux では通過、macOS では拒否」と出た**——
**しかしトランスクリプトでは両方とも拒否されていた。**
差は**拒否の後**にあり、**Linux 側はモデルが worktree 側のコピーに当て直して成功した**
（`/root/work/.claude/worktrees/R7/README.md`）のに対し、macOS 側は拒否文を引用して終えていた。
**つまり標準出力で測っていたのは「ガードが発火したか」ではなく
「モデルが拒否文を引用したか」だった。**

**これは、この周が受入基準に書いた交絡そのものである。** 一次ソース
（トランスクリプト）に当てていなければ、**「OS で挙動が違う」という誤った結論を出していた。**

### 言えること / 言えないこと

**言える:**

- **この 8 形・この harness 版において、OS は結末を変えなかった。**
  理由節もメッセージの形も一致した。
- **`SKILL.md` 手順 6 のガード関連の指示は、macOS だけの観測ではなくなった。**

**言えない（書いてはならない）:**

- **「ガードは OS に依らない」**——**当てたのは一握りの形**であって、境界ではない。
  #110 で 4 度壊れたのがこの型である。
- **「実機の Linux でも同じ」**——測ったのは**コンテナ**である。
- **「Windows でも同じ」**——**測っていない。BLOCKED のまま。**
- **「理由節は 6 通りである」**——**当てた形の数がそのまま出ているだけ**で、
  空間の大きさではない（#112 の未解決 1）。
