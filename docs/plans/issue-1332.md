## 設計の判断

- **原本は absent-lines.md の「`マージ前の判断 = 推奨で決めて起票`」の中の新しい段落**「満たしていない受入基準は、推奨を決める前にまず周が直す」（必須の印つき）。手順は 1 直す条件 → 2 直して陽性対照 → 3 当て直し 1 回と消えた条件 → 4 戻し先。
- **消えたら判定は `満たす`**——関門の記録に `関門: 当て直し <起点> <終点> 反証=<件数>` を書く。照合（`check-gates.py`）は `満たす` に出所を求めず、当て直しの範囲のコミットを見たとみなすので、照合は変えない。
  消えた基準はマージの前の判断に残らない（推奨を書かない・確認の Issue もフォローアップも立たない）。親は PR コメントの実物（陽性対照の両方の結果・当て直しの結果と振り分け）で確かめ、言い切れなければ満たしていないものとして扱う。
- **#1176 の理由（「直して 1 回の当て直しだけで判定を `満たす` に覆すと、2 パスの関門を通さずに周が自分の判定を変える」）は書き換える**——覆してよいのを、受入基準を変えない・陽性対照で示す・別ティアの Verifier が当て直すの 3 つがそろうときに絞る。
  当て直して消えなかったものは、今までどおり「直してからマージする」を推奨にしない（直しは済んでいて、直し直さない）。
- **複製の数**: この手順を述べる箇所は 8（absent-lines.md の原本と、同じファイルの「後退・未達を含む値」・「この線でも止まるもの」・「子がすること」・「親がすること」・古い値の名指し、dev-loop SKILL.md 手順 6、found-lines.md、cruise SKILL.md §2・§4 の委譲文・§4 の 4、公開ページ、`check-unattended-env.py` の名指しの文）。
  **分けない理由**: 受入基準が原本と cruise §4 の委譲文を名指しし、ほかは「満たしていない受入基準はいつも止まる／推奨は直してからマージしない」と書いていて、残すと原本と食い違う。原本以外は原本を指す 1 文に留める。

### 仕様の穴（推奨で決めた。`仕様の穴 = 推奨で決めて起票`）

Issue の「決めたいこと（未決定）」の 4 つ。確認の Issue は下の「未解決の判断・確認待ち」。
