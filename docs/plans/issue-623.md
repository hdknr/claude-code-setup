## 未解決の判断・決めたこと

- **D1（実装の選択）**: #624 NP-2 を直すには、容れ物の順（引用が外・項が内）を固定した読み方では足りない。容れ物を積む形に書き直した。
  `width_at`（#580）は除き、タブは `expand_tabs` で開く——#624 NP-1 の守る規則（`>` の直後のタブだけ印の空白 1 桁を使う）は、開いた空白の 1 つ目を
  `QUOTE_MARK` が剥がすことで同じ結果になる。NP-1 の変異は「`>` の直後でないタブからも 1 桁落とす」に写し、main の `width_at` に元の変異を当てた陽性対照も取る。
- **D2（実装の選択）**: NP-3 は「前後が空白の並びをすべて区切りから外す」のではなく、**`*` の並びだけの行**に絞った。前者は `a ** b` のような字のまま見える
  `**` を落とさなくなり、守る 3（対にならない `**` を落とす）を弱める。
- **D3（推奨で決めた・要確認を立てる）**: リストの項の中で閉じ忘れたコメントは、main では項が終わっても閉じていなかった（`list-comment-unclosed` が main では崩れ無し。
  GitHub も後ろの本文を見せないので、main は GitHub と合っていた）。容れ物を積む形では引用と同じく項の終わりで閉じ、見えない行の崩れを落とす。
  **最初は「#607 の承認の中」と書いたが誤りだった**（1 パス目の `/code-review` CR1-4）——#607 は「今のまま」を決めたもので、その背景は main がリストでも
  閉じていると思い込んでいた。**リストの形を変えるのは新しい判断**なので、利用者の直接の指示（2026-10-29）のとおり推奨で決めて要確認の Issue を立てた（**#649**）。
  推した理由: #607 と同じく、閉じ忘れたコメントそのものが誤りで、落ちれば気づける。引用とリストで読み方が分かれるほうが説明しにくい。
