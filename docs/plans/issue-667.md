`scan` の重さ（`i667-perf.py`。1 段落に N 行・1 行に `**` 2 つ）: main は N=500 で 0.013 秒・1000 で 0.049 秒・2000 で 0.184 秒・4000 で 0.718 秒
——**N を 2 倍にすると 4 倍**（行の探索を run ごとに先頭から 2 度回している）。

狭いパスの試料 3 本（#648 の狭いパス NP-1〜3）は、main の検査でも GitHub と一致する（どれも崩れ無し）——弱いのはテストで、検査ではない:
`- - a **x⏎   ===⏎   y**`（1 つの太字）・`  a⏎* * *  ⏎    x** y`（区切り線とインデントしたコード）・`a⏎> - - -⏎>     x** y`（引用の中の区切り線とインデントしたコード）。

**原因**: (1) 空行・空の項・表の行の端を `str.strip()` で判定しており、CommonMark が空白に数えない字（U+3000・NBSP・`\v`・`\f`）まで剥がす
——CommonMark の空行は空白とタブだけの行（CRLF の `␍` は改行の一部）。(2) 段落を割り込める番号を文字列 `"1"` と比べている——cmark は数値で比べる。
(3) `scan` が run ごとに `next(r for r in range(len(block)) if offsets[r + 1] > pos)` を 2 度回す。
