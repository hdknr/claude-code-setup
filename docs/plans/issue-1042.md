## 決めたこと

- **ヒアリングを行う条件は正本の状態から読む**——作業中の版が v1 で、`requirements/` にファイルが無く決定表も無いとき。ほかに、利用者が求めたとき。
  会話の記憶で決めない（`SKILL.md` の「守ること」の再開点と同じ）。**Q&A 表が空かでは決めない**——終えたヒアリングが表に跡を残さずに毎回繰り返すのと、
  feasibility・spec-review が先に起票すると始まらないのを避ける（1 パス目の `/code-review` の CR-2・CR-7 で、最初の「表が空」の条件を改めた）。
- **ヒアリングで利用者が決めたことは Q&A の行にせず要求に書き、行にするのは決まっていないことだけ（回答は `未回答`）**——
  回答の列に書いてよい 3 つ（`SKILL.md`）を広げない。
- **「今回の会で決めたい問」は最大 3 問。スクリプトも 3 を超えたら 2 で拒む**——元記事の「最大 3 問ずつ」と合わせ、上限を散文だけにしない。
- **`--focus` に渡せる番号は、資料に載る行（`DONE` でない行）だけ**——載らない番号・重複・空は 2 で拒み、出力を作らない（既存の出力に触らない）。
