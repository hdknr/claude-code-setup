## 調べたこと（実測。手順 2・5）

道具: `/opt/homebrew/bin/soffice`（Cask の libreoffice 26.8.0 の包み → `/Applications/LibreOffice.app/Contents/MacOS/soffice`。`soffice --version` は `LibreOffice 26.8.0.3`）・poppler 26.09.0。
**シンボリックリンクの日付は 2026-09-11 で、Issue の日（2026-11-20）より前**——失敗した日と同じ版の道具である。

1. **この PC の今の状態では、実機の段は 0 と 1 になる**——テストと同じ試料（`make_pptx` で作った `real-clean`・`real-bad`）・同じ環境（`PATH` だけ・一時の `HOME`・`LANG=C.UTF-8`・`-I`）で
   `check-pptx-render.py` を直に当て、収まる枚は 0（`見つからなかった`）・はみ出す枚は 1（`はみ出し（ページの外）` 2 件）。標準エラーも読んだ。
   **Issue の時点に `soffice --version` が何も出さなかったのに対し、今は版を出す**——道具の状態が違う。
2. **終了コード 2 は本体の「描画して確かめられなかった」である**（docstring と `render` の `RuntimeError`）。理由は本体の標準エラーに出るが、**テストは標準エラーを捨てていた**ので、
   Issue の時点では理由が残らなかった。**テストは 2 を「はみ出しを見つけた」（1）とは取り違えていない**が、2（確かめていない）を、判定が違う（NG）と同じ形で出していた——これを直す。
3. **切り分け**（どれも上の 1 の試料で）:
   - **版**: 失敗した日と同じ版（上）。版は失敗と成功を分けない。
   - **プロファイルのロック**: 本体は 1 回ごとに一時の `-env:UserInstallation` を使う。別のプロファイルで `soffice --headless` を起こしたまま当てても 0（`pgrep` で起きていることを確かめてから当てた）——ほかの `soffice` が動いていることでは落ちない。
     利用者のプロファイルで起きた GUI の LibreOffice との組は試していない（利用者のプロファイルに触れるため）。
   - **サンドボックス**: `sandbox-exec` で `(deny mach-lookup)` を掛けると、本体は **2（`描画に失敗した（soffice の終了コード 1）: Unspecified Application Error`）** になり、Issue と同じ `2 と 2` の形が出る。
     ファイルの書き込み（`~/Library`・`/private/var/folders`）とネットワークを拒んだプロファイルでは 0 のまま。陽性対照: 同じ `sandbox-exec` の拒否で `touch`（`Operation not permitted`）と `curl`（名前を引けない）が落ちることを見た。
     **ただし `(deny mach-lookup)` の下でも `soffice --version` は版を出した**——Issue の「何も出さずに終わった」とは形が違う。**元の失敗の原因は特定していない**（そのときの環境を再現する手段が無い）。
   - **時間切れ**: #1317 の周の記録（`docs/plans/issue-1317.md`）に、同じ段が実機の LibreOffice の 300 秒の時間切れで落ちた回がある。テストの `subprocess.run` は 300 秒で `TimeoutExpired` を投げ、
     テスト自身が例外で止まる形だった（本体の soffice の待ちも 300 秒で、どちらが先かは揺れる）。
