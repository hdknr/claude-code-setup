## 失敗（実物）

main（`380db76`）の検査と GitHub の描画（`gh api -X POST /markdown -f mode=gfm`、2026-10-30）を同じ試料に当てた:

| 試料 | GitHub | main の検査 |
| --- | --- | --- |
| Q1 `a⏎:--:⏎foo **x⏎bar** y`（Issue の形。`--:`・`:--`・`:-` も同じ） | 1 列の表。`foo **x`・`bar** y` は別の行で `**` は字のまま | 崩れ無し（見逃し） |
| Q2 `a⏎   :--:⏎foo **x⏎bar** y`（3 桁の字下げ） | 1 列の表 | 崩れ無し（見逃し） |
| Q3 `a \| b⏎:---⏎c \| d⏎--- \| ---⏎foo **x⏎bar** y`（#580 の周の実装役が挙げた形） | 1 つの段落（`<strong>` で太字。`:---` が表を開けなかったので、その段落ではもう開かない） | 5・6 行目を崩れとする（誤検出） |
| Q4 `a⏎:--:⏎\|--\|⏎foo **x⏎bar** y`（Issue の 2 つ目の形） | 1 列の表（`\|--\|` は表の行） | 4・5 行目（一致。ただし `\|--\|` を見出しにした別の表として読んでいる） |
| Q5 `> a⏎:--:⏎foo **x⏎bar** y`（引用の段落の続き） | 引用の段落（太字） | 崩れ無し（一致） |
| Q6 `a⏎    :--:⏎foo **x⏎bar** y`（4 桁の字下げ） | 段落（太字） | 崩れ無し（一致） |

**原因**: 表の区切りの行の判定（`blocks` の `"|" in inner and TABLE_DELIM.match(inner)`）が `|` を要る。GitHub（cmark-gfm）の
区切りの行は `|` を要らない——`TABLE_DELIM` 自体は `|` の無い形にも当たる。Issue の言う「2 つの条件」のもう 1 つ（`is_delim` の `"|" in text`）は
#580（`c6ca680`）が `is_delim` ごと消したので、**残るのは 1 つ**である。

`|` の無い `---`（コロンの無い形）は GitHub では表にならない（setext の下線）。**`SETEXT` の判定が表より前にあるだけでは足りない**——
容れ物の中でタブで字下げした `>⇥---`・`- a⏎  ⇥--` は `SETEXT`（` {0,3}`）に当たらず表の判定へ来る（1 パス目の `/code-review` CR1-1 が示した）。
1 パス目は **`|` かコロンのどちらかを要る**形にしたが、2 パス目の `/code-review`（CR2-1・CR2-4）が、それでは下線が段落を終わらせないことを示した。**根の原因は `SETEXT` が容れ物の後ろのタブを数えないこと**なので、setext の判定を `width_at` の桁で行い、区切りの行の条件は `TABLE_DELIM` だけに戻した。
