## 6. 既知の限界・決着済みの論点

| 論点 | 決着 | 理由 |
| --- | --- | --- |
| **`except Exception` で足りるのでは** | **採らない** | **P5**（`KeyboardInterrupt` / `SystemExit`）が漏れる。**歯止めは中断されたときこそ残骸を残す** |
| **呼ぶ側（`main`）の `try` を `make_sandbox` の前に移す** | **採らない** | **`box` がまだ存在しないので `finally` で畳む対象が無い。** 呼ぶ側を 2 箇所（本体とテスト）直すことになり、**3 箇所目の呼び手が現れたら同じ漏れが戻る** |
| **`tempfile.TemporaryDirectory` に置き換える** | **採らない** | **正常系では退避先を*返して生かす*のが仕様**で、context manager の寿命と合わない。**変更が P8 の側に倒れる** |
| **`$TMPDIR` を掃除するだけで済ませる** | **採らない** | **症状を消して原因を残す。** #157 は**「歯止めが自分で後始末を落とす」形**として起票されている |
| **`snapshot` を触らずに、専用の検査だけ足す** | **採らない** | **`守る` と `MUTATIONS` の 1 対 1**（既存の検査）が、**変異ループで殺せない変異を許さない**。**P9 のとおり観測の側を足す必要がある** |
| **実 `$TMPDIR` の件数を受入条件にする**（#157 の受入条件案の文言） | **採らない。I6 を書き換えた** | **実測で同じコマンドが赤にも緑にもなった**（§3.3 の表）。**測っている当人と測られている当人が同じ置き場所を共有している。** **落としたのではなく、成り立つ形に替えた** |
| **残っている古い退避先を掃除する** | **採らない** | **症状を消して原因を残す。** **掃除は `$TMPDIR` の共有状態を触る操作**でもあり、**他のセッションの走行中の退避先を消しうる** |
| **外から殺されたときも残さないようにする**（シグナルハンドラ等） | **採らない** | **`SIGKILL` は捕まえられないので、一般には閉じない。** **この周の範囲外**——**§3.3 に「この修正の外にある」と明記した** |

**決着の*理由*が誤っていると判断したなら、それは新しい反証である。**

## 7. 訂正（#161）— §5「2 パス目 #5」の測定値

**この節は、この計画ファイルが main に入ったあとで足した。** 4 パス目の `/code-review` が
反証したもので、**#157 の受入基準とは別の話なので #161 として別の周で直した。**

§5 の **#5** は「**当て先も追随させたうえで `except Exception:` に狭めると、*観測のほう*が
ちょうど 1 件赤になる**」と書いている。

**その測定は `a16f180` 時点のもので、そのときはまだ P10（`.resolve()` が落ちる）の probe が
無かった。** **3 パス目（§5 の #7）で P10 を足した結果、同じ操作が観測を 2 件赤にするように
なった**——**`.resolve()` の経路は `OSError` ＝ `Exception` なので狭めても捕まって畳まれる**のに、
**`observe_leak` の `left(parent)` が累積していて、中断の経路が残した退避先を数えていた**
（掃除は外側の `finally` で 1 度きり）。

**性質**: **測定は当時正しく、いまは偽である。** **同じ周の中で、後から足した probe が、
前に取った測定の前提を静かに入れ替えた。**

**#161 で `left()` を「数えたら掃く」形にしたので、いまは狭めると観測の赤は 1 件に戻る**
（**#161 で陽性対照つきに当て直した**——直す前は 2 件、直したあとは 1 件）。
**ここで数えているのは `leak[...]` の観測の検査だけである**——**同じ suite には
観測でない歯止めもあり、それらは別に落ちうる**（**#161 の 2 パス目の `/code-review` が
ここを混ぜて「いまは偽」と報告し、再実測で退けた**）。
**§5 の #5 の記述はそのまま残してある**——**いつまで正しかったかが読めなくなるので、
上書きしない。**
