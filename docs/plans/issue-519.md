## 失敗（実物）

dev-loop プラグインの Markdown（`evals/` を除く 16 本）を GitHub の Markdown API（`gh api -X POST /markdown`、`mode=gfm`）で
ファイルごとに描き、`<pre>`・`<code …>`（属性つきを含む）を除いた本文に `*` が字のまま残る行を数えると、base `7d950d1` で
`SKILL.md` 26 行・`references/resume.md` 1 行・`README.md` 1 行・`agents/dev-loop-verifier.md` 1 行・`prompts/verifier.md` 1 行（計 30 行。Issue の数と一致）。
ほかの 11 本は 0 行（著者が実走して確かめた）。

型の仕分け（1 行ずつ描いて確かめた）:

- **太字の崩れ**（29 行）——CommonMark の flanking の規則で、`**` の片側が句読点（`「` `」` `（` `）` やバッククォート）、反対側が文字のとき、
  開き／閉じが成立しない（#496・#516 と同じ形）。`SKILL.md` の「手順 5 の**「実行されない主張は…」**と**「緑を…」**」の行は、
  中央の `」**と**「` が開き・閉じとして組み、`と` 1 字だけが太字になっていた。
- **入れ子のバッククォート**（1 行。`SKILL.md` 301 行 `（\`- \\\`scripts/*.py\\\` — 歯止め\`）`）——太字は正しく描かれており、
  崩れているのはコードスパン（GFM はコードスパンの中でバックスラッシュのエスケープを効かせない）。`*` は `scripts/*.py` のグロブの字。
  **`**` の空白では直らない別の型**で、この周の範囲の外（下の `触らない:`）。
