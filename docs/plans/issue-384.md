## 設計の決定（著者が決めたもの。関門に渡す）

- **A の判定対象**: `docs/plans/issue-<N>*.md` で N ≥ 175 のもの全部。内容（`## 手順 8` の節など）で判定しない——
  `issue-373.md` も `issue-309.md` も手順 8 の節も件数の行も持たないので、内容で判定すると直すべきものが対象から外れる。
  175 は件数の行の規定が入った 1.35.0（`4e3c805`）の後に始まった最初の周で、175 未満の計画ファイルは件数の行を 1 本も持たない
- **周の途中の計画ファイルも対象になる**——PR を作った時点で件数の行が要る。手順 8 の「マージの前に書く」は PR の CI がその関門になる。
  起票の決定が後で変わったら行を直す（B）
- **入れ子の判定**: 件数の行の次の空行でない行が字下げされていたら落とす（後ろの字下げした項を件数の行が子として飲む形——#317 の崩れ方）。
  字下げした件数の行そのものはパターンに当たらないので「形が崩れた行」として落ちる
- **形が崩れた行**: 行頭（字下げ・箇条の印・太字を許して）`この周の起票` で始まるのにパターンに当たらない行を落とす。
  文の途中で「この周の起票」に言及する行は見ない
- **フェンスの中は数えない**（`strip_fences` を共有）
- **F**: 狭いパスの差分は「起点 → 指摘対応の最後のコミット（終点）」の 2 点 `git diff <起点> <終点>`。終点は指摘対応をコミットした直後に
  再開点に記録する。取り込み（`git merge origin/main`）の順番は縛らない——取り込みは版の衝突のために要ることがあり（CLAUDE.md）、
  順番で縛ると狭いパスを待つ間マージが止まる。2 点の範囲なら取り込みの前後に依らず他人の作業が混ざらない
- **B の書き分け**: 「マージ後の起票」＝その周の手順 8 の起票の判断（採否の表・残課題から人間が承認したもの）がマージの後に来たもの。
  「周の外で起票」＝その周の手順 8 以外（別の周・別のセッション・後日の人間の指示）で起票し、本文がその周を元の周に挙げるもの。
  括弧は件数の行の現在の値の理由だけを書き、決定が変わったら古い注記を消して書き直す。「（現時点）」のような暫定の語を書かない
- **D**: 主語を「人間、または人間の指示で Claude のセッション」にする
