## 決めたこと（Issue が「決める」とした点。著者の判断——人間レビューで覆してよい）

- **D1 版**: ページが `docs/v<n>/` の下なら、**`v1`〜`v<n>` のうちその番号を持つ最も新しい版**。版の外のページ（`docs/` 直下）は
  **すべての版のうち最も新しい版**。版は重ね合わせないので、v2 で問い直していない番号は v1 の節にしか無い——
  「その版」だけを見ると、v2 のページから v1 の質問を指せない。
- **D2 どの版にも無い番号**: リンクにせず警告（`--strict` で落ちる）。
- **D3 見出し**: リンクにしない（ATX の `#` 見出しと Setext の下線の上の行）。見出しの文字がリンクになると、目次と permalink が崩れる。
- **D4 置き換えないところ**: フェンス（```` ``` ```` と `~~~`）・インラインのコード・既存のリンク（`[...]` の中と `(...)` の中）・
  HTML のタグとコメント・自動リンク `<...>`・Q&A 表のページ（`qa` の印を持つページ）。
- **D5 リンク先**: `qa.md`（雛形の Q&A 表のページ）へのページからの相対パス（`posixpath.relpath`）。`use_directory_urls` に依らない
  （MkDocs は `.md` へのリンクを書き出し先に合わせて書き換える）。`qa.md` が無ければリンクにしない（警告は出さない——Q&A 表を
  持たないサイトで本文に `Q-` があっても誤りではない）。
- **D6 番号の形**: `qa-csv.md` に合わせて `Q-` に 3 桁以上の数字。前後が英数字・`-`・`_` なら番号とみなさない（`XQ-001`・`Q-0012x`）。

### 指摘対応で分かったこと

- **雛形の `mkdocs.yml` は superfences を入れていないので、アドモニション・箇条書きの中のフェンスはコードとして描かれない**
  （段落になる。`scratchpad/build.py` で組んで確かめた）。フックはそこをコードとみなして番号を残す——**リンクを付けない側に倒れる**ので
  受入基準 2 は破らない。superfences を入れた正本では、そのままコードになる。
- **字下げ 4 以上のフェンスを、容れ物（アドモニション・箇条書き・引用）の中か、ただの字下げコードの中かは見分けない**——
  字下げコードの中に ``` が 1 行だけあると、そこから先がフェンスとみなされ、閉じるまで番号がリンクにならない（リンクを付けない側）。
