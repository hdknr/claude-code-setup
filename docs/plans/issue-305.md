# Issue #305 — 「この周の起票」の件数が、束ねた起票と書式の揺れで過小に出る（#303・#304 のまとめ）

## 決めたこと（前提）

- **A. 周の外で束ねて起票した Issue は、根拠に挙がった元の周の*全部*に数える**（2026-10-20、人間が
  `AskUserQuestion` で選択。対案の「最初の周だけ」「別の記録」は採らない）。各周で +1 し、同じ行の括弧に
  「周の外で起票」と書く——#287 の「マージの後で起票が増えたら、計画ファイルの行を直す PR を出す」と同じ扱い。
  **周ごとの信号は正しく出るが、全周を足すと Issue の実数より多くなる**（数えたいのは周ごとの値なので、それでよい）。
- **A'. 起票済みの Issue を束ねただけの Issue（#294・#305 の形）は、どの周にも数えない。** 束ねられた側が
  もう元の周で数えられているので、数えると二重になる（人間の追加の指摘から。2026-10-20）。
- **A''. 「元の周」は、Issue の本文がその周の関門の指摘（残課題）や周の中で起きたことを根拠に挙げている周。**
  件数の記録そのものの誤りを根拠にした Issue（#287）は、どの周の関門の指摘でもないので数えない。
- **手順 6 の「残課題を束ねた Issue は作らない」は、周の中の起票を縛る。** 周の外で人間が束ねることは禁じない。
  束ねたら、その起票をした側が元の周の計画ファイルの行を直す。
- **B. 書式は `- この周の起票: N 件` で行頭から始め、装飾なしとする。** 理由・番号は後ろの `（…）` に書く。1 ファイルに 1 行。
  集める側のパターンは `^- この周の起票: [0-9]+ 件`（1 本）。
- **C. 既存の計画ファイルを B に揃える**（集める側で揺れを吸収するとは決めない。吸収する箇所が集める側の数だけ増えるため）。

| E | 版が 3 種類で揃い、歯止めが全部緑 | bump 漏れ・生成ブロックの鮮度 | `python3 scripts/check-all.py` |

組み合わせ: A × B（束ねた起票を足した行も B の書式に従う）。B × C（パターンを書いたのと同じ式で揃いを検査する）。

確かめるコマンド（C）:

```bash
for f in docs/plans/issue-*.md; do
  n=$(grep -cE '^- この周の起票: [0-9]+ 件' "$f")
  m=$(grep -c 'この周の起票: ' "$f")
  [ "$m" -gt 0 ] && [ "$n" -ne 1 ] && echo "NG $f $n"
done
```

（`m` は `この周の起票: ` を含む行の数。散文で言及しているだけの行——issue-175 の 133 行——も `m` に入るが、
判定するのは `n` が 1 かどうかだけ。）
