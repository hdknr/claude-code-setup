**P20 は、4 パス目の修正そのものが作った行き止まりである。** detached の再開を
`git switch -c` へ送るようにしたが、**同名のローカルブランチが既にあると

（当て直しで反証）。**判別した**——**どの worktree もそのブランチを持たない状態**で

持っているか」の 1 つだけ）。**P13 は detached を生まない**（`worktree add <既存ブランチ>` は
`fatal: '<名前>' is already used by worktree at …` で止まるだけ）。

（6 パス目で反証）。**実測**（2026-09-18）——**ローカルブランチが無ければ `switch -c` は通る**:
`git worktree add <path> remotes/origin/leftover` → detached（`git symbolic-ref -q HEAD` は rc=1）、
`git switch -c leftover` → **rc=0**（`Switched to a new branch`）。
本文が案内する `remotes/origin/<名前>` の形は**ローカルブランチが無いときにこそ使う**形なので、
**その場合は行き止まりにならない。**

**行き止まりになるのは、同名のローカルブランチが残っている場合だけ**である。
**その発生源としてこの一覧に載っているのは P17**（upstream 無しで `-d` が落ちて残ったブランチ）
なので、**P20 は P17 × P19 として読める**——**新しい入口ではない。**

### 交絡を潰した手順（**この周は実験を 3 つした**）

**3 つとも「陽性対照を同じ観測点で取る」形で潰した**——否定的な結果（拒否される・失敗する）は
実験が壊れていても同じ形で出るため。

1. **AC3（`:457` detached HEAD）**: `git branch -m` が exit 128 で fatal。
   **陽性対照** = 同じ形の worktree でブランチの上にいるときは `-m` が exit 0 で通った。
   → 失敗は **detached であること**に帰せられる（「worktree では `-m` が使えない」ではない）。
   **観測窓**: git 2.54.0 (Apple Git-157) / macOS、各ケース 1 回。
   スクリプトは scratchpad の `e457/run.sh`（実環境に触らないことをパスのアサートで担保）。
2. **AC2（`:423` `EnterWorktree` の `path`）**: 配下でないパスは拒否。
   **陽性対照** = 同じセッションから**配下の**パスは入れた。
   **両方の probe を `git worktree list` に登録した状態で測った**ので、
   拒否は「未登録だから」でも「worktree の中からは切り替え不可だから」でもない。
   → **配下かどうか**が効いている。**観測窓**: 1 セッション・各 1 回。
   **`name` での新規作成が worktree の中から不可かは測っていない**（道具の説明文のみ）。
3. **AC7（手順 6 の PR 前チェック）**: **この実験は交絡していた。1 パス目で反証され、
   2 パス目の前に測り直した。**
   - **当初**: 複合コマンドが拒否された。陽性対照 = 素の `git rev-parse --git-dir` は通った。
     → 「拒否は**複合の形**で起きている」と結論した。
   - **これは誤り。** 陽性対照が**非複合**だったので、被験コマンドとは
     **複合・コマンド置換・`test` の被演算子・git の呼び出し回数の 4 つが同時に違い**、
     **どれが効いたかを 1 つも判別していなかった**（「主張が偽でも同じ出力が出る配置」）。
   - **測り直し**（2026-09-17、同一の隔離セッション、各 1 回。陽性側と陰性側を同じ観測点で）:
     **7 形を、振る次元を 1 つずつ変えて測った**（複合の有無・コマンド置換の有無・
     `test` の被演算子かどうか）。**通る形と拒否される形の両方が出た**ので、
     陽性対照は同じ観測点で取れている。
     → ここで「効いているのは X」の形で結論した。**その X はここに書かない**（同上）。
   - **規範も狭めた**——「複合コマンド 1 本にまとめない」は広すぎ、
     **同じ差分が追加した `git symbolic-ref … && echo … || echo …` が自分の規範に違反していた。**
   - **その狭めた結論も広すぎた。手順 5 の当て直しで反証され、もう一度測り直した**
     （2026-09-17、同一の隔離セッション、各 1 回）。**「効いているのは X」は 7 形から言える
     十分条件であって、境界の全体ではなかった**——`test` もコマンド置換も使わず、
     **`git` を一度も名指ししない形でも拒否される**:
       - `for s in 1 2; do echo "v=$s"; done` → **通る**（ループ ＋ 変数展開）
       - `A=--help; python3 scripts/<名前>.py $A` → **通る**（計算値がスクリプトより後）
       - `S=<名前>; python3 scripts/$S.py` → **拒否**（計算値がスクリプトの位置・ループ無し）
       - `for s in <名前>; do python3 scripts/$s.py; done` → **拒否**（同上 ＋ ループ）
       - `python3 - <<'EOF'` に `git` を含む本文 → **拒否**（`feeds python text naming git`）
