### 交絡を潰した手順（**この周は実験を 3 つした**）

**3 つとも「陽性対照を同じ観測点で取る」形で潰した**——否定的な結果（拒否される・失敗する）は
実験が壊れていても同じ形で出るため。

1. **AC3（`:457` detached HEAD）**: `git branch -m` が exit 128 で fatal。
   **陽性対照** = 同じ形の worktree でブランチの上にいるときは `-m` が exit 0 で通った。
   → 失敗は **detached であること**に帰せられる（「worktree では `-m` が使えない」ではない）。
   **観測窓**: git 2.54.0 (Apple Git-157) / macOS、各ケース 1 回。
   スクリプトは scratchpad の `e457/run.sh`（実環境に触らないことをパスのアサートで担保）。
2. **AC2（`:423` `EnterWorktree` の `path`）**: 配下でないパスは拒否。
   **陽性対照** = 同じセッションから**配下の**パスは入れた。
   **両方の probe を `git worktree list` に登録した状態で測った**ので、
   拒否は「未登録だから」でも「worktree の中からは切り替え不可だから」でもない。
   → **配下かどうか**が効いている。**観測窓**: 1 セッション・各 1 回。
   **`name` での新規作成が worktree の中から不可かは測っていない**（道具の説明文のみ）。
3. **AC7（手順 6 の PR 前チェック）**: **この実験は交絡していた。1 パス目で反証され、
   2 パス目の前に測り直した。**
   - **当初**: 複合コマンドが拒否された。陽性対照 = 素の `git rev-parse --git-dir` は通った。
     → 「拒否は**複合の形**で起きている」と結論した。
   - **これは誤り。** 陽性対照が**非複合**だったので、被験コマンドとは
     **複合・コマンド置換・`test` の被演算子・git の呼び出し回数の 4 つが同時に違い**、
     **どれが効いたかを 1 つも判別していなかった**（「主張が偽でも同じ出力が出る配置」）。
   - **測り直し**（2026-09-17、同一の隔離セッション、各 1 回。陽性側と陰性側を同じ観測点で）:
     複合のみ（git あり・なし）・コマンド置換のみ・`>/dev/null` ＋ `&&` ＋ `||` は**すべて通る**。
     `test "$(git …)" != "x"` と `test "$(git …)" != "$(git …)"` は**どちらも拒否**。
     → 効いているのは **`git` のコマンド置換が `test` の被演算子に来ること**。
   - **規範も狭めた**——「複合コマンド 1 本にまとめない」は広すぎ、
     **同じ差分が追加した `git symbolic-ref … && echo … || echo …` が自分の規範に違反していた。**
   - **その狭めた結論も広すぎた。手順 5 の当て直しで反証され、もう一度測り直した**
     （2026-09-17、同一の隔離セッション、各 1 回）。**「効いているのは X」は 7 形から言える
     十分条件であって、境界の全体ではなかった**——`test` もコマンド置換も使わず、
     **`git` を一度も名指ししない形でも拒否される**:
       - `for s in 1 2; do echo "v=$s"; done` → **通る**（ループ ＋ 変数展開）
       - `A=--help; python3 scripts/<名前>.py $A` → **通る**（計算値がスクリプトより後）
       - `S=<名前>; python3 scripts/$S.py` → **拒否**（計算値がスクリプトの位置・ループ無し）
       - `for s in <名前>; do python3 scripts/$s.py; done` → **拒否**（同上 ＋ ループ）
       - `python3 - <<'EOF'` に `git` を含む本文 → **拒否**（`feeds python text naming git`）
     **上 2 つが陽性対照**で、2 番目と 3 番目の差は**計算値の位置**の**1 次元だけ**。
     **ループは効いていない**（3 番目は `plain command` として拒否された）。
     → 当時はここで **「根は『走らせるものが `git` でないと示せない』こと」**と結論した。
   - **その「根」も誤りだった。2 パス目の `/code-review` が反証した**（2026-09-18）。
     **`git -C <自分の worktree の外>` は、まぎれもなく `git` だと示せているのに拒否される**
     （理由は `redirects git to the shared checkout via -C`）。
     **根を「`git` でないと示せないこと」に置くと、自分の陽性対照と矛盾する**
     ——上の表の 2・3 行目も `git` そのもので、そちらは通っている。
     **さらに `sed -n 1,5p $F` という 5 つ目の理由も、この周中に出た。**
   - **3 度目は帰納をやめて引用に替えた。** 拒否メッセージは**2 文構成**で、
     **1 文目（理由）は形ごとに違うが、2 文目は 5 形すべてで文字通り同一**:
     `Refusing to run it — a worktree-isolated session's git operations must target its
     own worktree.` **これはガードが自分で述べている規則**なので、測った形からの帰納ではない。
     **理由の側は数え上げない**——**パスを重ねるたびに増えている**（1 パス目 3 → 2 パス目 5）。
   - **この再発は 1 パス目と同じ型である**——**測った形の集合から境界の全体を述べる**。
     **1 パス目は「複合」で広げすぎ、手順 5 の当て直しでは「`test` の被演算子」と狭めて断定し、
     2 パス目には「根は `git` でないと示せないこと」と 1 段上で断定した。3 度とも反証された。**
     **振れ幅の問題ではなく、断定の形の問題**だった。**1 段上げても同じ型のままである。**
   **観測窓**: 1 環境・1 harness 版、各形 1 回（2026-09-17 に 11 形、**2026-09-18 の 2 パス目に
   `-C` の 2 形と `sed` の 1 形**）。**`-C` は陽性対照つき**——自分の worktree のパスなら通り、
   外なら拒否される、の**1 次元**。**他の harness 版・`test` 以外の比較の形
   （`[ ]`・`case`・`if`）・`python3` / `sed` 以外のプログラムは測っていない。**

**横に洗ったか**: **2 回洗った。**

1. **1 パス目の後**: **この周の実験はすべて「拒否される／失敗する」型の否定的結果**なので、
   3 つ全部に陽性対照を付けた。**ただし「陽性対照を付けた」と「判別している」は別だった**
   ——実験 3 は陽性対照がありながら判別していなかった。実験 1（detached の `branch -m`）と
   実験 2（`EnterWorktree` の `path`）は**振った次元が 1 つだけ**なので判別している。
2. **当て直しの後**: 問いを変えて洗い直した——**判別の有無ではなく、結論の*範囲*が
   測った集合を超えていないか**。
    - **実験 1 は超えていない。** 「失敗は detached であることに帰せられる」は
      **単一次元の陽性対照が支える因果の帰属**で、境界の特徴づけではない。
    - **実験 2 も超えていない。** 「配下にしか入れない」は標本 2 つからの一般化に見えるが、

    - **超えていたのは実験 3 だけ**——**標本だけから機構を特徴づけた唯一の主張**だった。
