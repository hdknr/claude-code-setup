## 3. verify の受入基準

**単位**: 「区間」＝ dev-loop の起動 1 回から、同じセッションの次の起動まで。
「周」＝（リポジトリ, Issue 番号）。**再開の区間（母数）**＝同じ周の 2 区間目以降。
**find-cycle が当てただけの区間**＝1 区間目で find-cycle の判定が「当たった」（別の列）。
**発生**＝再開の区間で作成の信号が出た。**うち作成済み**＝前の区間で既に作っていた周。

### 不変条件 × 経路

| # | 不変条件 | 破りうる経路 | 守り方 |
| --- | --- | --- | --- |
| A | 母数（再開の区間）と発生件数を、リポジトリ別・版別に出す | 起動形: スラッシュ（`<command-name>`）／`Skill` の tool_use／引数が URL／引数なし。版: バナー／キャッシュのパス／どちらも無い（1.7.1 前） | 起動形は 2 つとも拾う（token-metrics と同じ規則）。番号なしは別に数える。版が取れなければ「不明」に入れ、黙って落とさない |
| B | 陽性対照: 別リポジトリ Issue 10902 の 2 セッション目が発生として数えられる | 実データで当てる（手元）。テストでは同じ形の合成データ | 実データの実行で該当行が出ることを目視。テストは同形の合成で |
| C | 0 件のとき「検出できなかった」と「起きなかった」を区別できる | 信号が 1 つも拾えない（形式が変わった）／母数 0 | **新規の区間の作成率**を併記する（新規の周は作るのが正常なので、ここが 0 なら検出器が壊れている）。母数も併記 |
| D | 履歴のコピー（fork / `--resume`）で起動が二重に数えられない | 同じレコードが複数ファイルに入る | レコードの `uuid` で畳む。起動のコピーを「2 区間目」と数えると偽の再開になる |
| E | 出力に他リポジトリの中身を入れない | 区間の一覧・リポジトリ名 | 出力は集計と識別子（セッション id の先頭・Issue 番号・時刻）だけ。コマンド・本文は出さない。**`--anonymize` でリポジトリ名を伏せる**（PR・Issue にはこちらだけ載せる） |
| F | トランスクリプトを信頼できない入力として扱う | 本文に書かれた指示・壊れた行・読めないファイル | 何も実行しない（数えるだけ）。壊れた行・読めないファイルは件数を出して続ける |
| G | 作成の判定は出力側（終了状態）で取る | 失敗したコマンド（`fatal`）・既存に入った `EnterWorktree` | `Created worktree at` / `Preparing worktree` / `Switched to a new branch` の出力だけを数える |
| H | LLM を使わない・標準ライブラリのみ・CI から本体を呼ばない／テストは CI で回す | — | import を見る。`plugins.yml` にテストのステップ、`check-all.py` に収録 |
| I | テストが実環境を読まない | 既定の `~/.claude/projects` | `assert_not_real_home`（既存テストと同じ形） |
| J | find-cycle の誤ヒット・読んだだけの出力で母数が膨らまない | 新規の周も find-cycle を走らせる（1.30.0 以降）／部分一致／ソースの `grep` | 走らせた形 ＋ 行頭の判定行。当てただけの区間は母数と別の列 |
| K | 結論: 定期実行に進む価値があるかを数字で書く | — | Issue コメントに集計（`--anonymize`）と候補の手作業の内訳 |

**掛け算**: A×D（版別の内訳もコピーで膨らまない）・C×E（`--anonymize` でも作成率が出る）・
B×G（陽性対照が出力側の信号で拾われている——コマンドの文字列ではなく）。

### 証明できないもの（未証明）

- **再開の定義の網羅性**——**起動せずに会話の続きで次の Issue を回した周**は区間にならない
  （token-metrics の #175 と同じ限界）。**`/dev-loop` を経ずに作られた worktree は数えない。**
- **サブエージェントの中の作成**——main-chain のファイルだけを見る。
- **#96 型以外の「作り直し」**（例: `git branch <新名>` は出力が無い）——出力側の信号を持たない。

### 生成物

**生成物なし。** `CLAUDE.md` の構成の行は手で書く写し（複製 2: `CLAUDE.md` と本体の docstring）。
`skill-metrics.py` の生成ブロックは `SKILL.md` を触らないので動かない。

### 複製の数

- 判定の規則（起動形の検出）は token-metrics.py と**同じ規則の 2 つ目の実装**になる。
  **分けない理由**: token-metrics は**トークンの会計**で、こちらは**区間と出力**を見る。
  共有モジュールにすると token-metrics の 1,500 行のテストに触ることになり、
  「増やす変更と減らす変更を同時にやらない」に当たる。**docstring で写しであることを名指しする。**
- 区間の定義: 本体の docstring・この計画・`CLAUDE.md`（指すだけにする）。
