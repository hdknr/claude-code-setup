## 失敗（実物）

main（`03b62d9`）の検査に次を当て、GitHub の Markdown API（`gh api -X POST /markdown -f mode=gfm`）で描いて、
`<pre>`・`<code …>` を除いた本文に `**` が字のまま残るかと突き合わせた（#525 の周と同じ方法）:

- `| a | b |⏎|---|---|⏎| 1 | 2 |⏎foo **x⏎bar** y` — GitHub は `foo **x`・`bar** y` を表の行にし `**` が字のまま。検査は 0 件（**見逃し**）。
  同じ形: 引用の中の表・リストの項の中の表・1 列の表・外側の `|` の無い区切りの行・見出しの行だけの表・3 つ字下げした行・`===` の行・行だけのインライン HTML。
- 原因: 先頭が `|` の見出しの行は、表の区切りの行の判定（段落が 1 行のとき）より先に「表の行」として 1 行の段落に出されるので、
  区切りの行が来たとき段落が空で、表の状態（`table`）が立たない。
- 同じ判定の裏側（**誤検出**）: 先頭の `|` が無い表で立った `table` は空行まで続き、見出し・引用・項・フェンス・インデントしたコードで終わらない——
  `a | b⏎--- | ---⏎c | d⏎# h⏎foo **x⏎bar** y` で検査は 2 件、GitHub は見出しのあとを段落として太字に描く。
