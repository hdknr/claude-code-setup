## 設計の判断

- **原本は `parallel.md` の新しい節**（「通知だけを頼りに待たない」の次）。`SKILL.md` §3・§4 は短く指す。複製の数: 見張りの規定を述べる箇所は `parallel.md`（原本）・`SKILL.md` §4 の 2・
  `docs/plugins/dev-loop-cruise.md` の 3 箇所、張り直しは `SKILL.md` §3 の 4 と公開ページの 2 箇所。**分けない理由**: 原本に細部を置き、ほかは指す・要点だけで、数え直す整合は少ない。
- **受入基準の「§5 の待ち方」**: 現行の `SKILL.md` §5 は「割って続ける」で、待ち方の規定は §4 の 2（`子の報告が終わりの報告でなければ…` の段）と `parallel.md` にある。そこに足した。
- **見張りの形は、既存の「通知だけを頼りに待たない」の待ち（出力ファイルの終わりの印の行・pid のシェルの消滅）と同じ条件**で、終わった後に 2 分待って前進を見る。前進の見方は `ledger.md` の同項の写し。
- **スクリプトにしない**: `until` ループと `stat` を数行並べる形で、既存の待ちも `parallel.md` の bash ブロックである。テストが要る判定（終了コードで分岐する）は無い。
  代わりに、偽の出力ファイルと偽の worktree（`git init`）で 4 通り（終わりの印・pid の消滅・上限・前進あり／なし）を走らせて確かめた（A5）。
- **張り直しは訊かない**: 利用者の答えは起動時にもらってある（記録 `張った`）。記録が `張らない`・無いなら張り直さない（答えを広げない）。
