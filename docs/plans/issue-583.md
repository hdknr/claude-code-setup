## 決めたこと（Issue の「何を決めるか」の 3）

**台帳（`ledger.py`）に、会話の中で決めた方針の項目を足さない。** 理由:

1. **線の項目（`LINES`）に当たる方針は、もう台帳に置ける**——親 Issue の `cruise:` の行に書いて、起動時・再開時の確かめ（§1・§2）で台帳の `lines` に入る。
   #474 の「人間の判断が要るものは推奨で決めて要確認を立てる」は、いまの `仕様の穴 = 推奨で決めて起票` に当たる。
2. **当たらない方針は自由文で、効き方が決まっていない。** 台帳に置くと、compact の後の親がそれを「進めてよい」の出所として読む——
   台帳の `note` を出所にしない（`absent-lines.md` の「線を広げられるのは利用者だけ」）のと同じ理由で、出所にできない。
3. **会話の中の利用者の指示は、もう置き場所がある**——その指示を使う周の計画ファイル（`absent-lines.md` の同じ節の 1 項目め）。

compact で会話から指示が落ちたら、親は台帳の線と `.claude/dev-loop.md` だけで進む——**狭める向きに倒れる**（止まる場面が増えるだけで、許していないことはしない）。
**この決定は推奨で決めたので、確認の Issue を立てる**（`仕様の穴 = 推奨で決めて起票`。#812）。
