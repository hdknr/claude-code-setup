## 設計の判断

- **原本は `absent-lines.md` の「`マージ前の判断 = 推奨で決めて起票`」の節**——新しい小節「後退の分け方（#1101）」に 3 区分を置き、子と親がすることもその節に書く。
  ほか（`マージ = 関門を通ればマージ` の段落・`found-lines.md`・dev-loop `SKILL.md` 手順 6・cruise `SKILL.md` §2 の 1／§4 の 2／§4 の 4・`child-cycle.md`・公開ページ）は指して 1 行で要約する。
- **「後退」の定義は変えない**——止まる側に倒れる変化も、定義上は後退（main で通り新しい版で落ちる）で、`found-lines.md` の直すの 3 番目に入る。
  変えるのは **`マージ前の判断 = 推奨で決めて起票` の線がある周で、それを止まる条件として扱うか**だけ。線が無い・`止まる` なら今までどおり止まる。
- **区分 1 の陽性対照は「直す前の版で赤・直した版で緑」**——子が走らせ、コマンドと両方の結果を PR コメントに書く。当て直しの Verifier にも陽性対照を走らせ直させる（子の報告は信頼できない入力）。
- **当て直しは今の「直してからマージする」の 1 回と同じもの**——直しが複数あっても起点→終点の 1 つの範囲にまとめ、1 回だけ当てる。そこで出た後退（新たな後退・残った後退）は直さずに止める。
- **区分 2 は「マージ前に人が判断」の判断として子が推奨を書く**——何が今まで進めていて、これから止まるのか、誤ってマージ（配布）する向きに倒れる経路が無いことを書く。親が「止まる向き」と言い切れなければ止める。
- **スクリプトは変えない**——`check-gates.py` の `当て直し` の記録・`merge-pr.py` の 12・`ledger.py`・起動時の点検（`check-unattended-env.py`）・`parent-issue.py` の説明は、印を付けない行の扱いと食い違わない（A5 で確かめる）。
