## 決めたこと（Issue の「決めること」。不在の周なので、Issue が計画に委ねた範囲だけを決める）

- **宣言の形**: 別の行 `空いているときの検査: M`（1 以上の整数、6 桁まで）。**M は空いているときの同時の本数の上限（`並行の検査:` の N を含む合計）**。
  `並行の検査` を含まない名前にした——古い版の run-serial（`並行の検査` を含む書式に合わない行を「1 として扱う」と言う）にも、この行は黙って無視される（N 本のまま）。
  **宣言が無ければ今と同じ**（負荷を見ない・N 本）。M ≤ N・書式に合わない・2 行以上・整数でないなら足さず（負荷を見ず）、そう言う。
- **何を「空いている」とするか**: `os.getloadavg()` の 1 分の平均 < `os.cpu_count()` × `IDLE_RATIO`（0.5）。#1049 の観測（28 コアで 2.76 は空いている・47〜61 は混んでいる）を分ける値。
- **続けて入れない手当て**: 2 つとも入れる——(1) 上限 M（足した枠は `slot-N`〜`slot-(M-1)` の M-N 個）、(2) 間隔 `SPACING`（60 秒）——足した枠を取ったら、
  60 秒は次を足さない。60 秒は 1 分の平均の時定数で、入れた直後の検査がまだ数に出ない間に続けて入れないため（**測って決めた値ではない**）。
  間隔の判定と足した枠を取るのは、枠のディレクトリの門（`extra.lock` の `flock`）の中で行う——2 つの待ち手が同時に見て両方が足すのを防ぐ。
- **持ち主の重さを見るか**: 見ない（負荷だけで決める）。持ち主の CPU 時間を足しても、決めるのは「いま機械が空いているか」で、負荷がそれを表す。
- **待っている側の表示**: 宣言があるときだけ、待ちの報告の行に足さない理由（負荷とコアの数・足した枠も埋まっている・前に足してからの秒・負荷を読めない）を出す。
  足した枠を取ったら、そう言う。宣言が無ければ今の文言のまま。
- **入れ子**: 今と同じ（宣言を読む前に、同じ枠のディレクトリの印があれば待たずに走らせる）。
- **負荷を読めない**（`getloadavg` が無い・`OSError`・コアの数が分からない）: 足さない（今と同じ N 本）。待ちの報告の理由で言う。
