# 基盤の層の profile と、案件の基盤要件の表との照合

組織の開発ガイドのような外部の設計パターンを、パターンの持ち主のリポジトリに profile として置き、案件の基盤要件の表（spec-loop の `shared/infra.csv`）の行がその行を指す（#1312）。
**この文書は、platform-spec が持つ決まり——基盤の層の表の形・受け付ける形式の版の範囲・案件の設定・`profile の行` の書き方・照合・版の差分——の原本である。**
照合の本体 `scripts/check-infra-profile.py` と版の差分の本体 `scripts/check-profile-diff.py` の定数はここの写しで、写しがずれていないかは、このプラグインを置いているリポジトリ（hdknr/claude-code-setup）のテスト
test-check-infra-profile.py・test-check-profile-diff.py が突き合わせる。
**何を守り何を守らないか・終了コードは、スクリプトの docstring を正とする。**

profile の置き場所・`profile.csv` の列・層の表の先頭 3 列・形式の版の比べ方・リンクの書き方・手元の clone の探し方は spec-loop の決まり（spec-loop の `references/external-profile.md`）で、ここでは写さない。
platform-spec は spec-loop の `scripts/external-profile.py` を読み込んで profile を読む（`references/spec-loop.md`）。

## 基盤の層の表

profile の `profile.csv` に、層の名前は `基盤` で 1 行置き、`ファイル` が基盤の層の表を指す（例: `infra.csv`）。

| 列 | 書くもの |
| --- | --- |
| `ID` | 行の鍵。案件の `infra.csv` の `profile の行` がこれを指す。層の中で重ねない |
| `要約` | 選択の短い要約（例: 「AWS（東京リージョン）・ECS」）。本文は写さない |
| `リンク` | 本文（ガイドのページの節）を指す。書き方は spec-loop の決まり |
| `項目` | 案件の `infra.csv` のどの項目の案か（`言語`・`DBMS`・`ホスティング環境` など。綴りは案件の表と同じ） |

- 見出しの行は、この 4 列をこの順・この綴りで置く（見出しの前の空の行は飛ばして読む）。違えば読まない（判定できなかった）。
- profile は案を出すだけで、決めるのは発注者のまま——案件の基盤要件は spec-loop の共有の Q&A 表で発注者が決める（spec-loop の `references/tree.md` の「基盤要件」）。

## 形式の版の範囲

基盤の層の `形式の版` は、次の範囲のものだけを読む（比べ方は spec-loop の決まり）。

| 下限（この版を含む） | 上限（この版を含まない） |
| --- | --- |
| `1` | `2` |

- 形式の版 1 の表は、上の 4 列である。列を変えるときは形式の版を上げ、この範囲と照合を同じ周で直す。

## 案件の設定

使う profile とその版を、正本の版の中の `shared/platform/settings.csv` に置く。見出しの行は `項目,値` で、1 項目 1 行。

| 項目 | 値 |
| --- | --- |
| `リポジトリ` | profile を置いたリポジトリ（`<持ち主>/<名前>`）。手元の clone の探し方はこの名前で引く |
| `profile` | `spec-profile/` の下の profile の名前 |
| `タグ` | 読む版（profile のリポジトリのタグ） |
| `確かめたタグ` | 任意（#1457）。下の「版の差分と関門」で新しい版との差分を見て、発注者が採らないと決めた新しい版のタグ |

- `リポジトリ`・`profile`・`タグ` の 3 つは全部置き、値を空にしない。`確かめたタグ` は任意で、置くなら値を空にしない。ほかの項目を置かない。
- 値の形: `リポジトリ` は `<持ち主>/<名前>`（どちらも `.`・`..` でない）、`profile` は `/` を含まない名前、`タグ`・`確かめたタグ` はタグの名前に使える形（`v1~1` のような版の記法・`-` で始まる名前・`HEAD` は書けない）。違えば照合は設定の形の違反として止まり、profile を読みに行かない。
- `shared/` に置くので、spec-loop の 2 つのサインオフが比べる範囲に入る——タグを変えれば、`infra.csv` の `profile の行` が指す中身が変わるので、承認を取り直す。
- spec-loop の版の重ね方ではファイルの単位で重なる——v2 以降で値を変えるなら、ファイルごと置く。
- 設定を置かない案件は platform-spec を使っていない（spec-loop は今までどおり動く）。

## `profile の行` の書き方

案件の `infra.csv` の末尾の任意の列 `profile の行`（列の名前の原本は spec-loop の `references/tree.md` の「基盤要件」）に、基盤の層の `ID` を書く。

- 複数は `・` で区切る（例: `HOST-1・HOST-2`）。区切った間・前後を空にしない。
- 空のセルは「profile の行を指さない」（標準から外れた行・profile に無い項目）。
- `profile の行` を書いたら、上の案件の設定も置く。

## 照合

```bash
python3 <platform-spec の base ディレクトリ>/scripts/check-infra-profile.py <正本の docs> [--upto <n>] [--clone <profile の手元の clone>] [--spec-loop <spec-loop のプラグインの根>]
```

- spec-loop の重ね方で重ねた全体の `shared/infra.csv` と案件の設定を読み、設定のタグの時点の基盤の層に、`profile の行` の ID が在るかを照らす。
  無い ID（別のタグにだけ在る ID も）は、表の行と ID を名指しする。
- 手元の clone は spec-loop の探し方で探す——引数 `--clone`・環境変数・正本の根の `CLAUDE.md` の行。正本の根は `docs` の親である。
- 読むだけで、正本にも clone にも書かない。

## 版の差分と関門

profile の新しい版（タグ）が出たら、案件が `profile の行` で指している行のうち、変わった行・消えた行・リンクの切れた行を、基盤要件の変更として共有の Q&A 表に起票する候補にする（#1457。#1312 の「版を上げたときの差分」）。

```bash
python3 <platform-spec の base ディレクトリ>/scripts/check-profile-diff.py <正本の docs> [--upto <n>] [--new <タグ>] [--clone <profile の手元の clone>] [--project <正本の根>]
```

- **古い版は案件の設定の `タグ`、新しい版は `--new` か、手元の clone のタグのうち、設定のタグと名前の形（接頭辞（最初の数字より前）と末尾の綴り（最後の数字より後ろ）が文字どおり同じで、真ん中が数字を設定のタグの区切りの文字（区切りを持たない `v3` なら `.`）で区切った並び——桁と個数は問わない。`v3`・`v1.0` なら `v10`・`v1.1.0`、`v1.0-lts` なら `v1.1-lts`、`2024-10-01` なら `2025-03-01`）が同じで、その profile の `profile.csv` を持つものの中で版の順（git の `v:refname`。`v10` は `v9` より後ろ）が最も後ろのもの。**
  別の profile・層の版名（`zz-screen-v1`）・プレリリース（`v10-rc1`）・末尾の綴りの違う版（`v1.0-lts` に対する `v1.2-rc`）は、名前の形が違うので数えない（数えなかった、その profile を持つタグは出力に名指す）。設定のタグが自分の名前の形に当たらない（区切りが 2 文字以上続く `v1.0-lts2`・`v2.0.0-rc1`）なら、ほかのタグを新しい版に数えない（比べずに 0）。`v2.0.0-rc1` は末尾の無い後ろの版（`v2.1.0`）も数えないので、`--new` で名指す。設定のタグの末尾が綴りだけで、末尾の同じ後ろの版が無いなら、末尾の無い後ろの版を数える（`v2.0.0-beta` の次の `v2.1.0`）。末尾の同じ後ろの版があれば、末尾の無い版より先にそれを新しい版にする（`v1.0-lts` の次は、`v10` があっても `v1.1-lts`）。末尾の無いタグが後ろかは数字の並びで比べ（利用者の git の `versionsort.suffix` に依らない）、同じ数字なら設定のタグより後ろ（`v2.0.0-beta` の次の `v2.0.0`）、前（`v1.9.0`）なら数えない。綴りがプレリリースか版の線かは見分けないので、別のものと比べたいなら `--new` で名指す。接頭辞を変えた版（`v9` の次を `release-10` にした）は、設定のタグを上げるか `--new` で名指す。
  新しい版が `タグ` か `確かめたタグ` と同じなら比べない（候補は 0 件）。
- **候補の種類**は次の 3 つ。指していない行の変化と、新しい版で足した行は候補にしない。

| 種類 | いつ |
| --- | --- |
| `変わった` | 指した ID の行の、どれかの列の値が 2 つの版で違う |
| `消えた` | 指した ID が新しい版の基盤の層に無い（層ごと無いときも） |
| `リンクが切れた` | 指した ID の `リンク` が新しい版で切れている（切れたかの決まりは spec-loop の `references/external-profile.md`） |

- 候補は表の行・項目・ID・種類と、比べた 2 つの版を名指し、`起票の候補: ` で始まる行に出す。**番号を振らない**——起票するのは feasibility（spec-loop の feasibility の `SKILL.md`）で、番号を振るのは正本の Q&A 表に書く人である。
- **profile は案を出すだけで、決めるのは発注者のまま。** 発注者が新しい版を採るなら、設定の `タグ` を上げ、`profile の行` と表の行を直す。採らないなら、その版を設定の `確かめたタグ` に書く。どちらも `shared/` の変更なので、2 つの承認を取り直す。
- **関門**: spec-loop の `scripts/profile-gate.py` が、proposal と scaffold の前にこのスクリプトを子のプロセスで呼び、候補が残っていれば止める（spec-loop は platform-spec に依存しない。関門の決まりは spec-loop の `references/tree.md` の「基盤要件」の「外部の profile の関門」）。
- 読むだけで、正本にも clone にも書かない。終了コードと、何を守り何を守らないかは、スクリプトの docstring を正とする。
