# 版のディレクトリと重ね合わせ

プロジェクトが完成した**あと**のバージョンアップでは、要件の**差分だけ**を回す。
そのために正本リポジトリの `docs/` を**版ごとのディレクトリ**に分け、v2 以降には**前の版からの差分だけ**を置く。

> **移行中**: このファイルの決まりに従っているのは、いまは同梱の `scripts/merge-versions.py` だけである。
> ほかの決まり（`tree.md`・`signoff-tags.md` など）・スクリプト・スキルは、まだ `docs/` 直下の構成を読む。
> 版の構成に移すのは [#262](https://github.com/hdknr/claude-code-setup/issues/262)。

## ツリー

```
docs/
├── v1/                     # 最初の版。全体の仕様（中の構成は tree.md の docs/ と同じ）
│   ├── shared/
│   ├── requirements/
│   ├── spec/
│   ├── feasibility/
│   └── proposal/
└── v2/                     # v1 からの差分だけ
    ├── shared/qa.csv       # 新しい質問と、答えを変えた質問だけ
    ├── requirements/       # 足した・変えた要件のファイルだけ
    ├── spec/spec_ir.json   # 足した・変えた機能だけ
    ├── removed.csv         # 消したもの（下の「削除」）
    ├── feasibility/        # この版の差分の見積り
    └── proposal/           # この版の変更の提案書の手書き部分
```

- **版は `docs/` 直下の `v<n>`**。`n` は 1 から始まる整数で、先頭に 0 を付けない（`v2` は可、`v02` は不可）。
  **番号は 1 から欠けずに続ける。** **`v` の次が数字で、形に合わない名前（`v2-draft`・`v02`）は誤り**——
  黙って飛ばすと、その版の要件が消える。ほかの名前のファイル・ディレクトリ（`index.md` など）は版として読まない。
- **作業中の版は、番号が最大の版。** 作業中かどうかを書いたファイルは置かない。
- **リリースした版は凍結する**——直さない。リリースは git のタグ `release-v<n>` で示す。

## 重ね合わせ

**v<n> の時点の全体 ＝ v1 に v2、…、v<n> の差分を順に重ねたもの。** 重ね合わせは同梱のスクリプトが作る
（**手で作らない**）:

```bash
python3 <spec-loop の base ディレクトリ>/scripts/merge-versions.py docs build/merged
python3 <spec-loop の base ディレクトリ>/scripts/merge-versions.py docs build/merged-v1 --upto 1   # v1 だけ
```

出力は**版に分ける前の `docs/` と同じ形**（`shared/`・`requirements/`・`spec/`）で、`tree.md` の決まりどおりに読める。
**commit しなくてよい**（同じ入力から同じバイトを作る）。

### 重ねるもの

| 置き場所 | 単位 | 変更 | 削除 |
| --- | --- | --- | --- |
| `shared/qa.csv` | 行（`No`） | 同じ `No` の行を置く | `removed.csv` に種類 `Q&A` |
| `spec/spec_ir.json` | 機能（`features` の要素の `id`） | 同じ `id` の機能を**ケースまで丸ごと**置く | `removed.csv` に種類 `機能` |
| `spec/spec_ir.json` | `features` 以外のキー（`title` など） | 同じキーを書く | できない |
| `shared/`・`requirements/`・`spec/` のほかのファイル | ファイル（版のディレクトリからのパス） | 同じパスのファイルを置く | `removed.csv` に種類 `ファイル` |

- **追加は、新しい `No`・`id`・パスで置く。** **番号は版をまたいで重複させない**——新しく足すものは、前の版までの続きの番号にする。
  **同じ番号は「変更」の意味になる**（新しいもののつもりで前の版の番号を書いても、機械には見分けられない）。
- **行・機能の並びは、前の版の順を保つ。** 置き換えはその場で、追加は版の順に末尾へ。
- v2 以降の `spec_ir.json` は**差分だけ**なので、`features` 以外のキーは省いてよい。`features` は配列で置く（空でもよい）。
  中身の決まり（`spec-ir.md`）は、**重ね合わせた全体**に当てる。
- 各版の `qa.csv` は、それだけで `qa-csv.md` の決まりを満たすこと（同梱の検査を版ごとに通す）。
- **`feasibility/`・`proposal/` は重ねない。** 版ごとのもの（その版の差分の見積り・変更の提案書）で、出力にも入らない。
- **`.` で始まる名前は読まない**（`.DS_Store` など）。**シンボリックリンクは置かない**（版の外を読ませない）。

### 削除（`removed.csv`）

**置かないことは「変えていない」の意味である。** 消すときは、その版の `removed.csv` に書く。

| 列 | 書くもの |
| --- | --- |
| `種類` | `ファイル`・`Q&A`・`機能` のどれか |
| `対象` | `ファイル` なら版のディレクトリからのパス（`requirements/discount.md`）、`Q&A` なら `No`（`Q-003`）、`機能` なら `id`（`F-002`） |
| `理由` | なぜ消すか（空にしない） |

- 文字コードは UTF-8（BOM はあってもよい）。1 行目は見出し行で、上の列名と同じ文字列・同じ順。
- **消すものは、前の版までの全体に在ること。** 無いものを消そうとするのは誤り（綴りの誤りを黙って通さない）。
- **同じ版で、置きつつ消さない。** 同じ対象を 2 度書かない。
- **v1 には置かない**（消すものが無い）。
- **`shared/qa.csv` と `spec/spec_ir.json` はファイルとしては消せない**——行・機能の単位で消す。

## 出力先

- **書く前に、前の出力を消して作り直す。** ただし、スクリプトが作った印（`.merged-versions`）の在るディレクトリしか消さない。
  印の無い、空でないディレクトリには書かない——引数を取り違えて正本を消さないため。
- **`docs/` の中には書かない**（次の重ね合わせで入力に混ざる）。**`docs/` を含む場所にも書かない**（前の出力と一緒に入力を消す）。
- **出力先にシンボリックリンクは使わない**（印で持ち主を確かめられない）。
- **印は最後に書く。** 書いている途中で失敗したら、書きかけを消す。
- 決まりに反する入力・無い／読めない入力からは何も作らず、**前の出力は消す**（古い全体を今のものと取り違えないため）。
- **重ねた結果で、同じパスがファイルとディレクトリの両方になるのは誤り**（`requirements/a` と `requirements/a/b`）。
- どれかの版に `shared/qa.csv` があれば、行がすべて消えても**見出し行だけの `shared/qa.csv` を書く**（出力を `docs/` と同じ形に保つ）。
