# 初回ヒアリング（req-loop の手順 0）

**決定表の骨組みを作る前に、まだどこにも書かれていない目的（誰の課題か・何を改善するか・成功の判定。#1154）と関係者（誰が何に答え、誰の合意が要るか。#1161）と業務の前提・判断の基準・優先順位を、利用者との対話で聞き出す段**（#1042）。
req-loop の質問は決定表の空欄・TBD・決まっていない分岐から生まれるので、**仕様のどこかに枠があるものしか聞けない**。
1 往復はレビュー会 1 回分（数日〜数週）なので、深い前提が出るまで何周もかかる。その遅さを、最初の実行の対話で補う。

型は、インタビュー型プロンプティング（「AI に指示する前に、AI に質問させろ」）の 3 つ——役割と目的を明文化する・自明な質問を禁じて質問数を絞る・終了条件を決める——に合わせてある。

## 行う条件

**次のどちらかのときだけ行う。** どちらでもなければ飛ばして手順 1 へ進む。

- **作業中の版が v1 で、`docs/v1/requirements/` にファイルが 1 つも無く（下の階層も見る。`.` で始まる名前——`.gitkeep`・`.DS_Store`——は数えない）、
  `docs/v1/shared/decision_table.csv` も無い**——要求がまだ 1 行も書かれていない。
  **Q&A 表に行があるかでは決めない**——`feasibility`・`spec-review` が先に `Q-F-`・`Q-S-` の行を起票していても、要求が無ければ行う。
- **利用者がヒアリングを求めた**（v2 以降でもよい。書くのは作業中の版）。

**行うかどうかは正本の状態から決める**——会話の記憶・作業メモで「もう聞いた」としない（`SKILL.md` の「守ること」の再開点の例外として、そこに書いてある）。
**ヒアリングを終えたら、利用者が何も明示しなかったときも `requirements/hearing.md`（聞き取りの記録）を必ず書く**（下の「落とし先」）——
これが次の実行で繰り返さない印になる。**落とし先へ書くのは、利用者が終えると言ってからにする**——途中で実行が終われば何も書いていないので、
次の実行でもう一度始めから行う（途中まで書いた要求を「終えたヒアリング」と読み違えない）。

## 型

1. **役割と目的を最初に言う。** 何のための聞き取りか（要求確定のため）・終わったら何が残るか（要求の文書・決定表の骨組み・Q&A 表の質問）・
   いつ終えるか（下の 7）を、最初の問いの前に利用者に伝える。
2. **先に読み、書いてあることは聞かない。** 正本の既存の文書（`requirements/`・`shared/`）と、利用者が渡した資料を先に読む。
   **書いてあること・自分で決められること（書き方・ファイルの分け方）・利用者に見える結果が変わらないこと
   （実現の手段・内部の値。線は `spec-scope.md` の「振り分けの区分」）は聞かない。**
3. **1 回に聞くのは最大 3 問。** 会話の文で聞き、**選択肢を付けない**——前提・判断の基準・優先順位は、選択肢から選ばせると出てこない。
   判断の基準を聞くときは、**どちらを選ぶかだけでなく、なぜそう判断するかも聞く**（例: 「取りこぼしと重複のどちらを避けたいですか。それはなぜですか」）。
4. **目的の 3 点を、業務の前提より先に聞く**（#1154）——**誰の課題か**（誰が困っているか）・**何を改善するか**・**成功の判定**（改善できたと何で・いつ・どの値で判断するか）。
   目的の表（`requirements/purposes.csv`。形は `tree.md` の「目的と成功の判定」）に書いてあることは聞かない（上の 2）。
   成功の判定は「稼働の後に何を測れば、作った意味があったと言えるか」の形で聞き、**値まで出なければ値を推測で置かない**（下の「落とし先」）。
   目的が先に決まれば、続く前提・判断の基準・優先順位の問いをその目的に照らして絞れる。
5. **関係者を、目的の次に聞く**（#1161）——**誰がどの質問に答える権限を持つか**（業務の分野・機能ごと）・**誰の合意が要るか**（要求確定・予算・提案書の決裁）・
   **連携先のシステムの持ち主は誰か**。関係者の表（`shared/stakeholders.csv`。形は `tree.md` の「関係者の表」）に書いてあることは聞かない（上の 2）。
   **部署・役職で聞き、個人名を表に書かない。** 表に出ない決め手の人（非公式の影響力）を聞き出して書かない——その人の判断が要ると利用者が言ったら、
   答える範囲・合意を持つ関係者として表に載せるかを訊く（`tree.md` の「関係者の表」）。
   誰が答えるかが先に決まれば、続く問いを答えられる人に向けて書ける。
6. **答えに応じて深掘りする。** 次の 3 問は、前の答えで出てきた前提・例外・条件から作る。同じことを言い換えて聞き直さない。
7. **利用者が「十分」と言ったら終える**（それに類する明示でよい）。聞くことが尽きたら、スキルの側から「ここで終えてよいか」を訊いてよいが、
   **利用者が終えると言うまで終えない**。利用者はいつでも打ち切れる。

## 落とし先

**どれも、利用者が終えると言ってから書く**（上の「行う条件」）。
**v2 以降（利用者が求めたヒアリング）は、前の版にあるファイル（`requirements/` の文書・決定表・聞き取りの記録）を作業中の版の同じパスに写してから足す**
——同じパスはファイルごと置き換わるので、写さずに骨組みだけを置くと前の版の行が消える（`SKILL.md` の「差分モード」・`versions.md` の「重ねるもの」）。

- **聞き取りの記録を `requirements/hearing.md` に書く（必ず）**——いつ・誰から聞いたか・書いた先（要求の文書・決定表）・起票した行の番号。
  **利用者が何も明示しなかったら、そう書く**（「明示したことは無い。決まっていないことは Q-R-001〜Q-R-005 に起票した」）。
  2 度目のヒアリング（利用者が求めたとき）は、同じファイルに節を足す。
- **利用者が明示したこと**（業務の前提・判断の基準・優先順位・決まっている業務ルール）は、作業中の版の `requirements/` の文書に書く。
  **利用者の言葉から意味を足さない**——言い換えで条件を足したら、それは推測である。いつ・誰から聞いたかを添える（`ヒアリング 2026-11-16（業務部 山田）`）。
  文章は `writing-style.md` の記法で書く。ファイルの分け方はスキルが決める。
- **目的と成功の判定は、目的の表（`requirements/purposes.csv`）に書く**（#1154。列と id の形は `tree.md` の「目的と成功の判定」）——
  利用者が明示した目的を `G-` の行に、成功の判定を `K-` の行に。**利用者が言わなかった欄は空か未決定の印のまま残し、推測で埋めない**
  （成功の判定の値が出なかった、など。手順 3 がそこから起票する）。`機能` の列は機能一覧ができてから埋める（ヒアリングの時点では空でよい）。
- **関係者は、関係者の表（`shared/stakeholders.csv`）に書く**（#1161。列と id の形は `tree.md` の「関係者の表」）——利用者が明示した関係者を 1 行ずつ、部署・役職の名前で。
  **言われなかった欄（答える範囲・合意など）は空か未決定の印のまま残し、推測で埋めない**（手順 3 がそこから起票する）。個人名と非公式の影響力は書かない。
- **場合分けが出たら、決定表（`shared/decision_table.csv`）の骨組みを置く**——条件の列と、聞き取りで出た場合の行。
  **利用者が結果まで明示しなかった欄は空のまま残す**（手順 3 がそこから起票する）。
- **決まっていないこと・条件付きの答え・利用者が「あとで決める」としたこと**は、手順 3 の決まりで Q&A 表に起票する。
  起票元は `要求確定（ヒアリング）`（番号の印は `R`。`qa-csv.md` の「起票元」）。選択肢・推奨・推奨の理由を付け、回答は `未回答`、状態は `確認中`。
- **聞き取りで利用者が決めたことは Q&A 表の行にしない**——要求の文書に書く。Q&A 表は未決定事項の台帳である（`qa-csv.md`）。

## 守ること

- **回答を推測で埋めない**（`SKILL.md` の「守ること」）。ヒアリングでも、回答の列に書いてよいものは増えない。
  **聞き取りの流れ・「ふつうはこうする」から、利用者が言っていないことを要求に書かない。**
- **ヒアリングを終えたら、同じ実行の中で手順 1 から先へ進み、資料を作って止まる**——利用者が求めて行ったヒアリングでは、表に回答が未反映の行・
  確かめた結果のある暫定の行が残っていることがあるので、手順 1・2 を飛ばさない（初回の条件で行ったなら、手順 1・2 は自分の起票の分しか無い）。
  ヒアリングをしたことと、書いた先（要求の文書・決定表・起票した行の番号）を手順 5 の報告に足す。
- **聞いた中身は会話にしか無い**——聞き取りの記録・要求の文書・Q&A 表に落としたものだけが残る。落とさなかったことは、次の実行には届かない。
