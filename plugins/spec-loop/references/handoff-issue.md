# dev-loop に渡す Issue の本文

`scaffold` が登録する Issue の本文の形。**2 つのプラグインの境界は、この Issue と、そこから指すファイル**
（`spec_ir.json`・Red テスト）である。dev-loop は **Issue 1 件を読むだけで周を始められる**こと——
受入基準・Red テスト・Q&A の回答・仕様の原文を、本文から辿れること——を目的にする。

**本文は同梱のスクリプトが作る。手で書かない・登録の前に書き換えない。** 中身を変えたいなら
`spec_ir.json`（か仕様・Q&A 表）を直して作り直す。

## 1 機能 = Issue 1 件

`spec_ir.json` の機能（`spec-ir.md`）ごとに 1 件。題は `<機能の id>: <機能の title>`（`F-001: 注文の割引額を計算する`）。

## 印

本文の先頭の 2 行。**dev-loop はこの印で、spec-loop から来た Issue だと知る。**

| 印 | 意味 |
| --- | --- |
| `<!-- spec-loop-handoff: v1 -->` | spec-loop から渡した Issue である。`v1` は本文の形の版 |
| `<!-- spec-loop-feature: <機能の id> -->` | どの機能か（同じ機能を 2 度登録していないかを確かめるのに使う） |

## 節

本文はこの順に節を持つ。

| 節 | 書くもの |
| --- | --- |
| `## 仕様` | 機能の id と題・`spec_ir.json` のパスと sha256・仕様の原文のパス・API（メソッドとパス、OpenAPI の `operationId`）・型の名前 |
| `## 受入基準` | ケースごとに 1 行: ケースの id・何を確かめるか・**Red テストの名前**・根拠の Q&A の No。**この表の Red テストがすべて緑になること**が受入基準 |
| `## Red テスト` | テストのファイルのパスと sha256・回し方・実装を置く場所（モジュール名と関数名） |
| `## Q&A の回答` | この機能とケースが根拠にした Q&A の No・質問・回答・反映先（**生成した時点の Q&A 表から写す**。No だけにしない） |
| `## 仕様の穴を見つけたら` | 実装で決めず、Q&A 表に起票元 `開発` で起票して差し戻すこと（規定の本体は dev-loop の側にある） |

## sha256 で固定する

本文は `spec_ir.json` と Red テストのファイルの sha256 を持つ。**手元のファイルの sha256 が本文と違えば、
その Issue は手元の仕様と別の時点のものである**——dev-loop は実装に入る前にそれを確かめ、違えば差し戻す。

## 置き場所

生成した本文の出力先は `tree.md` の「生成物の置き場所」。
