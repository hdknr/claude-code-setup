# 性能の要求（`shared/nfr.csv`）

**性能は「数字のある性質」か「要求なし」のどちらかで渡す**（#852）。要求の無い機能を速くするのは、受入基準に結びつかない作り込みである。
非機能要求の回答（`docs/v<n>/shared/nfr.csv`。置き場所は `tree.md`）のうち性能の行を、`spec-review` が仕様の性質に書き、
`scaffold` が Issue の本文の性能予算と性能テストに写す。**行の無い機能は、下の既定の原則で受ける。**

## 列

`nfr.csv` は UTF-8 の CSV で、見出しの行はこの順・この綴り:

| 列 | 書くもの |
| --- | --- |
| `No` | `N-` に 3 桁以上の数字（`N-001`）。表の中で重複させない |
| `対象` | 何の性能か（利用者の言葉で。「注文の割引の計算」） |
| `指標` | 性能の行なら下の「指標」のどれか。ほかの種類の非機能要求（可用性・保存期間など）の行は、ほかの語を書いてよい |
| `上限` | 性能の行なら正の数（`300`・`0.5`。整数部の先頭に 0 を付けない——`0300` は書かない） |
| `単位` | 性能の行なら `ms` |
| `条件` | どの負荷・どの量のときの上限か（「ピーク 50 req/s」「明細 1000 行」）。負荷を問わないなら「負荷を問わない」と書く |
| `根拠` | **その数字の根拠**——今の負荷・年間のピークの実測・業務の締め切り（「2025 年の年末のピークが 42 req/s」）。空にしない |

### 指標

1 回の呼び出しの応答時間（呼んでから返るまで）を集めた値:

| 指標 |
| --- |
| `p50` |
| `p95` |
| `p99` |
| `最大` |

- **重ね合わせではファイルごと置き換わる**——v2 以降で `nfr.csv` を置くなら、前の版の行も含めた表の全体を置く（`shared/` のほかのファイルと同じ。`versions.md`）。
- **数字を変えるときは、新しい `No` の行にする**（古い行は表から外してよい）。同じ `No` の数字を書き換えると、
  それを指す機能の中間表現は変わらないので、`scaffold` は Issue の本文を作り直さない（変わらない機能の本文は作らない。`handoff-issue.md`）。
  新しい `No` を指すように中間表現の `nfr` を差し替えれば、機能は変更になって本文が作られる。

## 仕様に書く（spec-review）

`spec-review` は仕様を書き下すとき（手順 2）に、重ね合わせた全体の `shared/nfr.csv` を読む。

- **性能の行ごとに、その行を受ける機能の仕様に、外から確かめられる性質として書く**——「`条件` で、`指標` が `上限` ms 以内」
  （例: 「ピーク 50 req/s で、割引の計算の p95 が 300 ms 以内（`N-001`）」）。**行の `No` を添える**——数字の根拠は表の `根拠` の欄が持つ。
- **数字・根拠は仕様の側で決めない。** `根拠` が空の行・`上限` に数字の無い行・どの機能が受けるか読めない行は、仕様に書かずに
  共有の Q&A 表に起票する（利用者が答える。起票の形は `qa-csv.md`）。**根拠の無い桁上げ**（今の負荷の 10 倍を念のために上限にする、など）を足さない
  ——判定役の Domain Checker が見る。
- **実現の手段は書かない**——キャッシュ・並列化・索引の追加は、性能の性質を満たす作りの 1 つにすぎない（`spec-scope.md` の「縦の線」）。
- **性能の行が無い機能には、性能の性質を書かない**——下の既定の原則で受け、機能ごとに「要求なし」と書き足す必要もない。

## 既定の原則 — 要求の無い機能は最適化しない

**性能の要求（`nfr.csv` の性能の行）の無い機能は、速さのための最適化をしない。最適化は、計測で予算を超えたと示せたときだけ。**

- 範囲の文書（`spec-scope.md`）の「原則 1 本で受ける」と同じく、**機能ごとに場面を足さず、この 1 本で受ける**。
- 性能の行のある機能も、**上限の中なら最適化しない**——最適化してよいのは、性能テストか計測で上限を超えたと示せたときだけ。
- `scaffold` は、性能の行を指さない機能の Issue の本文の性能予算に「要求なし」と書く（`handoff-issue.md` の「作らないもの」）。

## Issue と性能テストに写す（scaffold）

- **どの行がどの機能に効くかは、中間表現の機能の `nfr`（`No` の配列）に書く**（`spec-ir.md` の「性能の要求」）。
  `scaffold.py` は、指した行が `nfr.csv` に在り、性能の行の形（上の列と指標）を満たすかを確かめ、満たさなければ何も作らない。
  **指していない行は見ない**——ほかの種類の非機能要求の行は、列の形が違っても止めない。
- `nfr` を持つ機能だけ、**性能テスト** `scaffold/perf/perf_<機能>.py` を作る（置き場所は `tree.md`）。実装の関数を、その機能のケースの入力で
  1 回ずつ一定の回数呼び、1 回の時間から指標を出して上限と比べる。実装が無ければ失敗する。
- **性能テストは `条件` の負荷を再現しない**——同時の呼び出しを作らないので、緑でも負荷の下で上限を守る証明にならない。
  **だから受入基準（Red テストの表）に入れず**、Issue の本文の `### 性能予算` に、最適化してよいかを決める計測の道具として置く
  （本文の形は `handoff-issue.md` の「作らないもの」）。負荷の下で上限を守るかは、負荷試験・本番の計測で確かめる。
