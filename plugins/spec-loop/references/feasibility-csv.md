# スケジュールと見積りの表（`docs/v<n>/feasibility/`）

予算責任者に見せる**スケジュール**と**見積り**の正本。どちらも CSV で置き、
ガントチャートと提案書の費用・期間の表は**この 2 つから生成する**（手で写さない）。

決まりどおりかどうかは、プラグインに同梱の検査で確かめる:

```bash
python3 <spec-loop の base ディレクトリ>/scripts/check-feasibility-csv.py docs/v<n>/feasibility/schedule.csv docs/v<n>/feasibility/estimate.csv
```

**2 つのファイルに共通の決まり**: 文字コードは UTF-8（BOM はあってもよい）。1 行目が見出し行で、
見出しは下の表の列名と**同じ文字列・同じ順**。**どの列も空を許さない**（`前提` を除く）。

## `schedule.csv` — スケジュール

| 列 | 書くもの |
| --- | --- |
| `No` | `T-` に 3 桁以上の数字（`T-001`）。表の中で重複させない |
| `工程` | 工程の名前（`基本設計`） |
| `開始` | 開始日。`YYYY-MM-DD` |
| `終了` | 終了日。`YYYY-MM-DD`。**開始日より前にしない**（同じ日は 1 日の工程・節目） |
| `前提` | 先に終わっている必要がある工程の `No` を ` / ` でつなぐ（`T-001 / T-002`）。無ければ空 |

- **`前提` に書いた工程は表の中にあること。自分自身を書かないこと。`前提` をたどって自分に戻らないこと**
  （循環。同じ日の工程どうしだと下の日付の決まりを通ってしまうので、別に見る）。
- **工程は、`前提` に書いた工程の終了日より前に始めない**（終了日と同じ日に始めるのはよい）。
- ガントチャートは**表の行の順**に上から並べる。

## `estimate.csv` — 見積り

| 列 | 書くもの |
| --- | --- |
| `No` | `E-` に 3 桁以上の数字（`E-001`）。表の中で重複させない |
| `区分` | 下の「区分」のどれか |
| `項目` | 費用の項目（`画面の開発（12 画面）`） |
| `金額` | 円。**半角数字だけ**（カンマ・単位・小数を書かない）。0 はよい |
| `根拠` | 金額の根拠——規模の数え方、または根拠にした Q&A の番号（`Q-F-001`。内部の Q&A 表の `D-S-001` も——費用だけが変わる内部の選択。`qa-csv.md` の「層」）・決定表の行 |

**根拠の無い金額は書かない。** 列を空にできないのはそのためである。

### 区分

| 区分 | 意味 |
| --- | --- |
| `開発費` | 一度だけかかる費用 |
| `運用費（月額）` | 毎月かかる費用 |

提案書の費用の表は、区分ごとの合計をこの表から出す。

## 例

```csv
No,工程,開始,終了,前提
T-001,要件定義,2026-11-02,2026-11-27,
T-002,基本設計,2026-11-30,2026-12-25,T-001
T-003,予算の合意,2026-12-25,2026-12-25,T-002
```

```csv
No,区分,項目,金額,根拠
E-001,開発費,画面の開発（12 画面）,4800000,画面一覧の 12 画面 × 40 万円
E-002,運用費（月額）,サーバ（冗長構成）,120000,Q-F-001 の回答 B
```
