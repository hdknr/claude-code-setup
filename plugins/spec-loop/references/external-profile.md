# 外部の profile（#1455）

組織の開発ガイドのような外部の設計パターンを、パターンの持ち主のリポジトリに **profile** として置き、platform-spec と screen-spec がそれを読む。
**spec-loop が持つのは、中身を知らずに済む部分だけ**——探し方・タグの時点の読み出し・形式の版の範囲の判定・リンクの検査・2 つのタグの間の差分（#1312・#1314 の「決めたこと」）。
層ごとの値の意味（語彙・既定・`infra.csv` との照合・起票の候補）は、使う側のプラグインが持つ。

**このファイルが決まりの原本である。** 読むのは `scripts/external-profile.py` で、その定数はここの写し（このプラグインを置いているリポジトリの回帰テスト `test-external-profile.py` が突き合わせる）。
**何を守り何を守らないか・終了コードは、スクリプトの docstring を正とする。**

## 置き場所

パターンの持ち主のリポジトリに置く。1 つのリポジトリに複数の profile を置ける（`<名前>`）。1 つのタグに基盤と画面の層をまとめられる。

```text
spec-profile/<名前>/
├── profile.csv        # 層,形式の版,ファイル,重ねる先
├── infra.csv          # ID,要約,リンク, …基盤の層の列
└── screens/*.csv      # ID,要約,リンク, …画面の層の列
```

読むのは**タグの時点の中身だけ**である——clone の作業ツリーやブランチの先端は読まない。

## `profile.csv`

| 列 | 書くもの |
| --- | --- |
| `層` | 層の名前（例: `基盤`・`画面`）。同じ層を 2 行書かない |
| `形式の版` | その層の表の形式の版。数字を `.` で区切る（`1`・`1.2`） |
| `ファイル` | 層の表のファイル。`spec-profile/<名前>/` からのパスで、`*` を使ってよい（`screens/*.csv`——`*` はディレクトリをまたがない）。当たるファイルが 1 つも無ければ読めない |
| `重ねる先` | その層を重ねる組み込みの profile の名前（例: 画面の層の `web-spa`）。空でよい。意味は使う側が持つ |

## 層の表

**どの層も、先頭の列を `ID,要約,リンク` に固定する。** それより後ろの列の名前と意味は層ごとに使う側が決め、spec-loop は解釈しない（そのまま持って比べるだけ）。

| 列 | 書くもの |
| --- | --- |
| `ID` | 行の鍵。層の中で重ねない（層のファイルが複数でも）。2 つのタグの差分はこれを鍵に取る |
| `要約` | 行の要約。本文は写さない |
| `リンク` | 本文を指す。空でよい |

### `リンク` の書き方

- **リポジトリの中のファイルは、リポジトリの根からのパスで書く**（先頭の `/` はあってもなくてもよい）。例: `docs/guide/auth.md#セッション`。
- **節は `#` の後ろに、GitHub が見出しに付ける id で書く**——小文字にし、文字・数字・空白・`-`・`_` のほかを外し、空白を `-` にしたもの。同じ見出しが重なれば 2 つ目から `-1`・`-2`。
  照らすのは指す先が `.md` のときだけで、ATX 見出し（`#` で始まる行。コードフェンスの外）から作る。
- **百分率で符号化した形（GitHub の URL からコピーした `docs/%E6%97%A5.md#%E8%AA%8D%E8%A8%BC` など）も書ける**——戻してから照らす。
- **スキームを持つもの（`https://…` など）は外の URL として扱い、在るかを見ない。**
- タグの時点にファイルが無い・節が見出しに無い・リポジトリの外（`..` で根より上）を指すなら、そのリンクは**切れた**。

## 形式の版の範囲

**受け付ける範囲は、使う側のプラグインの `references/` に、層ごとに下限と上限の表で置く**（screen-spec の「対応する spec-loop の版」と同じ形）。

| 下限（この版を含む） | 上限（この版を含まない） |
| --- | --- |
| `1` | `2` |

- **数字は ASCII の `0`〜`9` だけ**（全角の数字は読めない）。
- **桁ごとに数で比べ、足りない桁は 0 として比べる**——`1.10` は `1.9` より大きく、`1` と `1.0` は同じ。
- 範囲の外の層は読まない（判定できなかった）。

## 探し方

profile のリポジトリ（`<持ち主>/<名前>`）の**手元の clone** を、次の順に探し、最初に見つけたものを使う。
判定役がネットワークに出ずに非公開のリポジトリを読めるよう、手元の clone だけを見る。

1. 引数 `--clone <パス>`
2. 環境変数 `SPEC_PROFILE_CLONE`（clone のパス 1 つ。リポジトリを問わず効く）
3. 案件の根の `CLAUDE.md` の行（行頭から。コードフェンスの中は読まない。コロンは全角でもよい。`~`・`~<名前>` で始まる値はホームに展開し、展開できなければ（無い利用者の名前など）止める（1・2 のパスも同じ）。`./~dir` のように `~` で始まらない値は展開しない。相対パスは案件の根から）:

   ```text
   外部の profile の clone: <持ち主>/<名前> <手元の clone のパス>
   ```

   リポジトリごとに 1 行。同じリポジトリの行を 2 行書かない。

- **上で名指ししたものが git のリポジトリでなければ、下には進まずに止める**（名指しを黙って別のものに替えない）。
- どれも無ければ止める（判定できなかった）。**`gh` で取りには行かない**——clone を作って 3 の行を書く。
- タグが手元に無ければ止める——clone で `git fetch --tags` してから読み直す。
