# サインオフのタグ

承認は **git のタグ**で記録する。タグはコミットを指すので、
「誰が、どの時点の中身を承認したか」が正本リポジトリの履歴に残る。

| 承認する人 | タグ | 例 |
| --- | --- | --- |
| 利用者（要求の確定） | `req-signoff-v<n>` | `req-signoff-v3` |
| 予算責任者（範囲・開発費・運用費・期間の合意） | `budget-signoff-v<n>` | `budget-signoff-v2` |

- `<n>` は 1 から始まる整数で、取り直すたびに 1 つ上げる。**付け直さない**（同じ名前のタグを
  別のコミットに動かさない）。古い承認の記録が消えるため。
- 2 つの番号は**独立に数える**。`req-signoff-v3` と `budget-signoff-v2` が組になってよい。

## 2 つの承認が同じ範囲を見ていたか

開発に進む前の関門では、**最新の 2 つのタグの時点で `docs/shared/` が一致するか**を確かめる:

```bash
git diff --quiet req-signoff-v3 budget-signoff-v2 -- docs/shared/
```

一致しなければ、2 つの承認は別の範囲を見ていたことになる。**どちらかを取り直す。**
CI で走らせるなら、タグを取得できるよう履歴をすべて取る（GitHub Actions なら
`actions/checkout` に `fetch-depth: 0`）。

**タグはスキルが付けない。** 承認は人間の判断なので、スキルの仕事は
「どのコミットを承認してもらうか」をそろえて止まるところまでである。
