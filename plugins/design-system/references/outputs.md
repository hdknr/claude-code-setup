# 生成物

design-system が表から作るものの原本である（#1613）。どれも**最新の版**（spec-loop の決まりで番号が最大の版——作業中の版を含む）を重ねた全体から作り、表を手で写さない。

| 生成物 | 置き場所 | コミット | 読む人・道具 |
| --- | --- | --- | --- |
| 索引 | `spec-profile/<名前>/` | する | 案件の screen-spec（#1606・#1608）・spec-review の Domain Checker の照合先（#1605）・案件の `design/sources.csv` の初期値（#1607）・UI プロファイル（#1612） |
| トークン | `tokens/<名前>.tokens.json` | する | UI プロファイルの実装・デザインツール |
| 描画キット | `kit/` | する | screen-spec の UI モック（#1614）・ドキュメントのサイト |
| ドキュメントのサイト | `site/` | しない | レビュー会と承認で人が読む（#1611） |

`<名前>` は `settings.csv` の `名前`（`references/tree.md` の「設定」）。

## コミットする理由と鮮度

利用者と決めた（#1613 の D3）——**使う側はタグの時点を git で読むだけで、design-system のプラグインを要らない**。
spec-loop の `scaffold/`（コミットして `--check` で鮮度を見る）と同じ形である。

- 生成器（子の Issue）は `--check` を持つ——作り直したものを書かずに比べ、違えば非 0。**同じ入力から同じバイト**（時刻を書かない）。
- **`release-v<n>` のタグを付ける前に `--check` を通す**——タグの時点の生成物がその版の表と合うことを保証するのはこれだけである。
  デザインシステムのリポジトリの CI でも回す（雛形の CI——#1610）。
- 版の間は、生成物は作業中の版の表を映す。使う側は作業中の時点を読まない（下の「使う側が読む時点」）。

## 使う側が読む時点

**使う側が名指すのは `release-v<n>` のタグだけ**である（Issue #1613 の「版の管理」）。リリースしていない作業中の版は名指さない——承認前の中身なので。

## 索引（`spec-profile/<名前>/`）

**spec-loop の外部の profile の置き場所と形**（spec-loop の `references/external-profile.md`）で書く——使う側は spec-loop の `external-profile.py` で手元の clone のタグの時点を読む。
`profile.csv` の層と形式の版（初めは `1`）は次の案で、使う側の Issue（#1606・#1605・#1607）が確定させる。どの層も先頭の列は `ID,要約,リンク`（spec-loop の決まり）。

| 層 | 元の表 | `ID` | 後ろの列（案） | 使う側 |
| --- | --- | --- | --- | --- |
| `部品` | `components.csv` | `部品ID` | `名前`・`項目の種類` | screen-spec の項目の `部品` の語彙（#1606）・UI プロファイルの対応（#1612） |
| `パターン` | `patterns.csv` | `パターンID` | `screen-spec の項目` | screen-spec の「誰が決めるか」の既定の答え（利用者が決める部分。#1612） |
| `規則` | `rules.csv` | `規則ID` | `区分`・`対象` | Domain Checker の照合先（#1605） |
| `参照` | 生成物そのもの | 固定の ID | なし | 案件の `design/sources.csv` の `全体` の行（#1607）——`tokens/<名前>.tokens.json` と `kit/` を指す |

- **`重ねる先` は空**——デザインシステムは screen-spec の組み込みの profile に重ねるものではない（UI プロファイルとは別の概念——親 #1609）。
- **`リンク` は、行の散文の頁（`references/tree.md` の「散文」）の節**。散文が無い行は表のファイルを指す。パスは版のディレクトリの中のファイル（その行を最後に置いた版）——spec-loop の決まりでタグの時点に在るかが確かめられる。
- 本文は写さない（spec-loop の決まり）。

## トークン（`tokens/<名前>.tokens.json`）

`tokens.csv` を DTCG（W3C Design Tokens Community Group）の形式の JSON にする——`トークン` の `.` をグループの入れ子に、`種類` を `$type`、`値` を `$value`（別名は `{…}` のまま）、`説明` を `$description` に。

- DTCG の仕様の版と、テーマ・モードの書き方は表と同じく子の Issue で決める（`references/tree.md` の「決めていないこと」）。
- 別名の循環・行き先の無い別名は検査が止める（`references/review.md` の「機械の検査」）——生成器は検査を通らない表から作らない。

## 描画キット（`kit/`）

**トークンから作った CSS と、部品ごとの参照の描き方**。サイトの部品の見本と、screen-spec の UI モック（#1614。利用者と決めた）が同じものを使う——原本を 1 つにする。

| ファイル | 中身 |
| --- | --- |
| `kit/kit.css` | トークンを CSS のカスタムプロパティにしたもの（`--color-text-primary`）と、部品の描き方が使うクラス |
| `kit/kit.js` | 部品ごとの描き方。**素の JS で、技術に依存しない**（React などを使わない） |

描き方の約束（#1614 の screen-spec の UI モックに埋め込めること。screen-spec の `references/mock.md` の「出力」と「描き方の差し替え」に合わせる）:

- **外を読まない**——`kit.js` も `kit.css` も、ネットワーク・外のファイル・CDN・外のフォントを参照しない。モックは HTML 1 枚に埋め込む。
- **同じ入力から同じバイト**——時刻・乱数を書かない。
- **大域に置く名前は 1 つだけ**にし、部品の `名前` から描き方を引く形にする（モックの描き方の差し替え `ctx.item` が返せるように）。描く先は呼ぶ側が渡す要素だけで、文書のほかの場所を触らない。
- 描き方は部品の仕様の行（バリエーション・状態）を引数で受ける。表に無い部品・状態を求められたら、誤りを示す要素を返す（黙って既定の描き方にしない）。
- 描き方はデザインシステムの**参照の実装**であって、UI プロファイルの実装の代わりではない——UI プロファイルは自分の技術で実装する（`references/handoff.md`）。

- **フォントを埋め込むか**（ライセンスと大きさ）は #1614 で決める。
- **画面の配置は描画キットの外**——モックの画面の配置は今までどおり汎用（#1614）。

## ドキュメントのサイト（`site/`）

**人間がレビューするのはこの文書である**（利用者と決めた——#1611）。決まりの本体は #1611 で原本にする。ここに置くのは、ほかの原本との境目だけ:

- 最新の版（作業中の版を含む）を重ねた全体から作り、全頁に作業中かリリース済みかを示す（`release-v<n>` のタグの有無）。
- 前の版から変えた行に印と根拠の Q&A の番号を付ける——版の差分は spec-loop の `diff-versions.py` を読み込む（行の単位の差分は `references/spec-loop.md` の「spec-loop に要る口」の 1 が入ってから）。
- 部品・パターンの見本は描画キットで描く。
- **既定は非公開**——サーバー無しで開ける静的なサイトにし、公開は利用者が選ぶ任意の手順にする。
- **承認はサインオフのタグの時点から作ったサイトで行う**——生成器はタグ（コミット）を受けてその時点の表から作れるようにする。
- 見出しの id を GitHub の付け方に揃える（索引の `リンク` が節を指すので）。
