# UI プロファイルへの引き渡し

デザインシステムの版を上げたとき、変わったものを UI プロファイルの実装に渡す Issue の原本である（#1613）。spec-loop の scaffold の代わりで、design-system が自分で作る。

## 前提

- **UI プロファイル**は実装の方式で、組織ごとの外部の profile として screen-spec の組み込みの profile に重ねる（親 #1609）。実装するデザインシステム（リポジトリ・名前・対応するタグか版の範囲）を名指し、**部品と実装の対応**を持つ——形は #1612 で決める。
- 引き渡しの単位はデザインシステムの部品で、実装の部品ではない——粒度の違い（デザインシステムの 1 部品を 2 つの実装で作る、など）は UI プロファイルの対応が吸収する。

## いつ作るか

**`release-v<n>` のタグを付けた後**に、前のリリース（`release-v<n-1>`）の時点の全体と比べて作る。v1 は全部が追加。
比べるのは spec-loop の `diff-versions.py`（行の単位の差分——`references/spec-loop.md` の「spec-loop に要る口」の 1）。

## 単位

| Issue | 作る条件 | 受入基準の元 |
| --- | --- | --- |
| 部品ごとに 1 件 | その部品の `components.csv` の行か、`部品ID` がその部品の `component-specs.csv` の行が、足された・変わった・消えた。**その部品の仕様の行が指すトークンが変わった**ときも——**別名を解いた値で比べる**（仕様の行が指す `color.text.primary` の行が変わらなくても、別名の先の `color.blue.600` の値が変われば変わったとみなす。別名でたどり着くトークンを全部見る） | 部品の仕様の行（バリエーション × 状態）ごとに「実装の見た目・キーボード操作・読み上げがこの行と合う」。消えた部品は撤去 |
| トークンで 1 件 | `tokens.csv` の行が 1 つでも足された・変わった・消えた | 実装のトークン（テーマの設定など）が `tokens/<名前>.tokens.json` と合う |
| パターンごとに 1 件 | `patterns.csv` の行が足された・変わった・消えた | 実装のパターンの振る舞いが行と合う |

規則（`rules.csv`）だけの変更は Issue にしない——判定役と人のレビューで扱う。規則が変わった版では、各 Issue の本文に変わった規則を並べる。

## 本文

先頭の行に印 `<!-- design-system-handoff: v1 -->` を置く（dev-loop が spec-loop から来た Issue を見分ける `<!-- spec-loop-handoff: … -->` と同じ形）。本文の節:

| 節 | 中身 |
| --- | --- |
| `## デザインシステム` | リポジトリ・`release-v<n>` のタグ・前のリリースのタグ |
| `## 変わったもの` | 追加・変更・削除と、変わった表の行（前と後の値）。根拠の Q&A の番号 |
| `## 受入基準` | 上の表の「受入基準の元」から 1 行ずつ |
| `## 参考資料` | 索引の行・タグの時点の散文の頁・描画キットの見本（参照の実装） |
| `## 実装との対応` | UI プロファイルの対応（#1612）でこの部品に対応する実装。**対応が無ければ「対応を足す」を受入基準の先頭に置く** |

- 本文は生成器が作り、手で直さない。デザインシステムのリポジトリの版の外（`build/`。コミットしない）に書く。
- **登録の前に利用者に確かめる**（spec-loop の scaffold と同じ）——登録先は UI プロファイルの実装のリポジトリで、デザインシステムのリポジトリではない。どのリポジトリに登録するかを利用者が選ぶ。
- 受け取った側の dev-loop が印を見て本文の読み方を変えるかは、dev-loop の側の子の Issue で決める（spec-loop の印の読み方は dev-loop の `references/spec-gap.md`）。

## 決めていないこと

| 事項 | どこで決めるか |
| --- | --- |
| UI プロファイルの対応の形（どの層・どの列） | #1612 |
| 1 つのデザインシステムを複数の UI プロファイルが実装するときの登録（リポジトリごとに同じ本文を登録するか） | 引き渡しの子の Issue |
| dev-loop が印を読むか | dev-loop の側の子の Issue |
