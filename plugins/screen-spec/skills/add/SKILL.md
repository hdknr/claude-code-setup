# add スキル

<!-- skill-version: 0.2.0 -->
> **このスキルの版: 0.2.0**（プラグイン `screen-spec`）。
> 手元で読まれている版がリポジトリの最新より古いなら、
> `/plugin marketplace update` → `/plugin update screen-spec@claude-code-setup` の順に実行し、
> Claude Code を再起動する（[#63](https://github.com/hdknr/claude-code-setup/issues/63)）。

画面設計書に画面を 1 つ足すスキル。
**採番と書き込みは同梱のスクリプトがし、スキルは行の中身を利用者と決める**——表の行と雛形を手で書かない。

**呼び出し形**: `/screen-spec:add`（プラグイン提供のスキルは常にプラグイン名で名前空間化される）。
**素のスキルとしては置けない**——決まりとスクリプトをプラグイン直下に置いて `../../` で指しているため。

## 決まり

**画面の表の列・種別・採番・`add` が足すものは `../../references/tables.md`、仕様書の雛形と書き方は `../../references/prose.md` を正とする**
（このスキルと同じプラグインの中にある）。**行の中身を決める前に `../../references/tables.md` の「画面（`screens.csv`）」を読む。**

## 守ること

- **Q&A 表を書かない。Q&A の番号を振らない**——決まっていない欄は spec-loop の未決定の印（`../../references/tables.md` の「書き方の共通の決まり」）だけを書き、
  番号を添えない。番号の無い印は検査が「起票の候補」として出し、spec-loop の req-loop・spec-review が番号を振って起票する（`../../references/spec-loop.md`）。
- **行の中身を推測で埋めない**——利用者の言葉・spec-loop の要求（`requirements/`・Q&A 表の回答）に書いてあることだけを書く。無ければ利用者に訊くか、未決定の印にする。
- **表の行と雛形を手で書かない**——下の手順 2 のスクリプトが置く。スクリプトが 0 以外で終わったら、手で置き直さずに出力を利用者に見せて止まる。
- **commit しない**——足したファイルと検査の結果を利用者に見せて終える。

## 手順

### 1. 行の中身を決める

画面の表の 1 行に要るもの——`画面名`・`種別`・`主たる利用者`・`目的と背景`・`できること`・`根拠` と、要るときだけ `親画面`（種別が `tab`・`dialog`）・`機能`・`帳票`・`参考資料`——を、
利用者の言葉と spec-loop の要求から決める。

- `根拠` は Q&A の番号・業務ルール・機能の番号（`F-001`）。**Q&A の番号は Q&A 表に在るものだけ**を書く。
- `機能`・`帳票` は spec-loop の機能一覧・帳票の `id`。
- 案件の最初の画面は種別 `top`（入口）にする——検査は入口から遷移で辿る。

### 2. 足す

```bash
python3 <このスキルの base ディレクトリ>/../../scripts/write-screens.py add <docs> --name <画面名> --kind <種別> --user <主たる利用者> \
  --purpose <目的と背景> --can <できること> --basis <根拠> [--parent <親画面>] [--features <機能>] [--reports <帳票>] [--refs <参考資料>]
```

`<docs>` は spec-loop の正本の `docs`（版のディレクトリの親）。複数の値は `、` で区切る。
終了コードと意味はスクリプトの docstring を正とする。**0 以外なら、何も書かれていない**——出力を利用者に見せて止まる（3 で「init を先に」なら `/screen-spec:init`）。

### 3. ワイヤーフレームを書き出す

spec-loop の図の決まり（spec-loop の `references/tree.md` の「図」）のとおり、spec-loop の `render-diagrams.py` で書き出す（draw.io が要る）。
書き出せない環境なら、書き出していないことを利用者に伝える——書き出しを手で作らない。

### 4. 確かめる

```bash
python3 <このスキルの base ディレクトリ>/../../scripts/check-screens.py <docs>
```

結果を利用者に伝える。とくに次の 2 つは、足した直後にはふつうに出る:

- **入口から辿れない**（違反）——2 つ目からの画面は、それを開く項目（ボタンなど）と遷移の行が要る。`add` は画面の行だけを足すので、
  項目と遷移の行は利用者と決めて表に足す（`../../references/tables.md` の「`init` と `add`」）。
- **未決定の印・起票の候補**（未決定）——手順 1 で印にした欄。spec-loop で起票する。

### 5. 終える

足した画面ID・置いたファイル（スクリプトの出力の `書いた:` の行）・検査の結果を利用者に伝える。
仕様書の散文の節（状態・他システム連携・同時編集・表示ルール・未決の論点）は雛形の既定の文のままなので、利用者と書き直す（`../../references/prose.md` の「雛形」）。
