# MkDocs のフック

画面の表を MkDocs のサイトで見せるフックの決まりの原本である（計画は #1081 の「MkDocs」、実装は #1098）。
フックの本体（`scripts/mkdocs-pages.py`）と正本に登録する薄いフック（`templates/mkdocs/screen_spec_pages.py`）の定数はこの文書の写しで、
写しがずれていないかは、このプラグインを置いているリポジトリ（hdknr/claude-code-setup）のテスト test-screen-spec-pages.py が突き合わせる。
表の形は `references/tables.md`、仕様書の節は `references/prose.md`、モックは `references/mock.md`。

フックがすることは 4 つ:

1. **表を仕様書の節に出す**——仕様書の「表で持つ」節の印 `<!-- screen-spec: 表 -->` を、その画面の行の表に置き換える（表に置いた次元を、節に手で二重に書かない）。
2. **版ごとのモックをサイトに置く**——ビルドのときに、表のある版ごとにモックを生成し（`build-mock.py --upto <n>` と同じもの）、`docs/mocks.md` の版ごとの節にリンクを出す。
3. **未決定の飾り**——フックが出す表のセルのうち、spec-loop の未決定の印を含むセルの頭に `⚠️` を付ける。**正本には書かない**（`⚠️` は見せるときの飾りで、印の代わりにならない——`references/tables.md`）。
4. **案件の雛形を出さない**——版の `requirements/screens/templates/` の下（`init` が置く仕様書の雛形）はサイトのページにしない（`{{画面ID}}` を持ち、リンクが解決しないので `mkdocs build --strict` が落ちる）。

## 登録

**`mkdocs.yml` を書き換えない。** spec-loop の MkDocs の雛形（spec-loop の `init-mkdocs.py`）が置くフックには、ほかのプラグインのフックを登録する口
（正本の `hooks/spec_loop_plugins/`）がある。このプラグインのフックをそこへ登録する:

```text
python3 scripts/write-screens.py mkdocs <docs ディレクトリ> [--spec-loop <spec-loop のプラグインの根>]
```

| 決まり | 値 |
| --- | --- |
| 登録するファイル | `templates/mkdocs/screen_spec_pages.py` |
| 登録する入口 | spec-loop の `scripts/init-mkdocs.py` の `--hook` |

- 書くのは spec-loop の `init-mkdocs.py` で、**在れば変えない**——`init-mkdocs.py` を回し直しても登録は消えない。新しくするなら、登録したファイルを消してから登録し直す。
- 正本に写すのは、このプラグインを探して本体に渡す部分だけである——表の出し方・モックの作り方は、このプラグインの更新で届く（写し直さない）。
- 前の版の spec-loop の雛形を写した正本のフックは口を持たない——`init-mkdocs.py` がそう言う。取り込む手順は spec-loop の `references/tree.md` の「ドキュメントのツール」。

## このプラグインの見つけ方

正本に登録したフックは、ビルドのたびに次の順に探し、最初に見つけたものを使う。

| 順 | 探す先 |
| --- | --- |
| 1 | 環境変数 `SCREEN_SPEC_PLUGIN`（このプラグインの根） |
| 2 | Claude Code の設定のディレクトリ（`CLAUDE_CONFIG_DIR`、無ければ `~/.claude`）の `plugins/installed_plugins.json` の `screen-spec@<マーケットプレイス>` の `installPath` |

- 2 は、正本のディレクトリを `projectPath` に含む `project` の記録を先に、無ければ `user` の記録を採る。1 つに決まらなければ見つからないと同じ。
- 1 で名指ししたものが screen-spec でなければ（`.claude-plugin/plugin.json` の `name`）、2 へは進まずに止める。
- 見つからなければ、**警告し（`mkdocs build --strict` は落ちる）、仕様書の表の印とモックのページに注意書きを置く**——黙って空にしない。
- spec-loop は、このプラグインの見つけ方（`references/spec-loop.md`）で探す——環境変数なら `SCREEN_SPEC_SPEC_LOOP`。
- **Claude Code の入っていない環境（正本の CI）でビルドするなら、claude-code-setup を取得して、`SCREEN_SPEC_PLUGIN` に `plugins/screen-spec`、`SCREEN_SPEC_SPEC_LOOP` に `plugins/spec-loop` を渡す。**

## 表を節に出す

- 対象のページは、版のディレクトリの `requirements/screens/` の直下の Markdown（`docs/v<k>/requirements/screens/<slug>.md`）だけである。ほかのページの印は変えない（案件の雛形 `templates/spec.md` など）。
- 表は、v1 から**後の版が同じ名前の仕様書を置く手前の版**まで（置く版が無ければ最後の版まで）を spec-loop の重ね方で重ねたものを使い、`仕様書` がそのファイルの名前の画面の行を出す——版は差分だけを置くので、仕様書を写さずに表だけを変えた版の行も、前の版の仕様書のページに出る（その範囲で画面を消していれば、v1〜v<k> で重ねたものを出す）。当たる画面が無い・重ね合わせが決まりに反するなら、警告して印を注意書きにする。
- 印は、その印の上の最も近い `## ` の見出し（節）で何を出すかが決まる。散文の節・節の外の印は、警告して注意書きにする。コードブロックの中の印は変えない。
- **共有の層だけを出す**——出す列は下の表の列だけ（`references/mock.md` の「共有の層だけを出す」の列の中）。どのセルからも内部の層の Q&A の番号（`D-`）を外す（`build-mock.py` と同じ外し方）。
- 当たる行が無ければ「この画面に当たる行は無い」と書く。

| 節 | 行 | 種類 | 列 |
| --- | --- | --- | --- |
| `1. 基本情報` | 画面 | — | `画面ID`・`画面名`・`種別`・`親画面`・`主たる利用者`・`ステータス`・`参考資料`・`機能`・`帳票`・`根拠` |
| `2. 画面概要` | 画面 | — | `目的と背景`・`できること` |
| `3. レイアウト` | 項目 | — | `まとまり`・`並び順`・`番号`・`項目名`・`種類` |
| `4. データ表示` | 項目 | `表示`・`一覧`・`一覧の列` | `番号`・`項目名`・`種類`・`中身`・`例`・`根拠` |
| `5. 操作とアクション` | 遷移元 | — | `番号`・`きっかけ`・`操作`・`条件`・`遷移先`・`結果`・`根拠` |
| `6. 入力とバリデーション` | 項目 | `入力` | `番号`・`項目名`・`必須`・`入力チェック`・`エラーメッセージ`・`例`・`根拠` |
| `8. 権限とデータの見える範囲` | 遷移元（条件あり） | — | `番号`・`きっかけ`・`条件`・`遷移先`・`根拠` |
| `12. 一覧・表の能力` | 項目 | `一覧`・`一覧の列` | `番号`・`まとまり`・`項目名`・`種類`・`並び替え`・`絞り込み` |
| `13. 画面遷移` | 遷移元・遷移先 | — | `番号`・`遷移元`・`きっかけ`・`遷移先`・`条件` |

- **行**: `画面` はその画面の行を「項目・内容」の 2 列の表にする（`1. 基本情報` には、遷移先がその画面の遷移の遷移元を「呼び出し元」として足す）。
  `項目` はその画面の項目（`種類` が書いてあればその種類だけ）を、`まとまり` が最初に出た順に、同じ `まとまり` の中は `並び順` の順に並べる。
  `遷移元` は遷移元がその画面の遷移、`遷移元（条件あり）` はそのうち `条件` が空でないもの、`遷移元・遷移先` は遷移元か遷移先がその画面の遷移を、表の順に並べる。
- ロール別の可否は spec-loop の `requirements/roles.csv` が正で、`8. 権限とデータの見える範囲` には遷移の `条件` を出すだけである（可否を書き直さない）。

## 版ごとのモック

| 決まり | 値 |
| --- | --- |
| サイトの中の置き場所 | `mock/v<n>/index.html` |
| モックのページの名前 | `画面モック（表から生成）` |
| モックのページの形式 | `HTML（screen-spec が生成）` |

- ビルドのとき（MkDocs の `on_files`）、v1〜v<n> を重ねた全体に画面の表がある版ごとに、`build-mock.py` と同じものを作り、`<docs の親>/build/mock/v<n>/index.html` に書いて、サイトの上の場所に置く（commit しない——#1081 の決めること 7）。
- **モックの中の仕様書へのリンクは、サイトの仕様書のページを指す**（`build-mock.py` だけで作ったモックは Markdown のファイルを指す）。
- `docs/mocks.md` の版ごとの節には、spec-loop のフックの口（`spec_loop_mocks`）を通して、手で書いたモックのリンクと並べて出す。
- 作れなかった版（重ね合わせが決まりに反する・3 つの表が揃っていない・描き方のファイルが版の中に在る・spec-loop やこのプラグインが見つからない）は、警告し、モックのページのその版の節に理由を出す。
  表の検査の違反・未決定では止めない（`build-mock.py` と同じ）。
- サイトの同じ場所に正本のファイルが在れば、置かずに警告する。
