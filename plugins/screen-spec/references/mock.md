# UI モックの生成器（`build-mock.py`）

画面・項目・遷移の表から、UI モック（HTML 1 枚）を生成する `scripts/build-mock.py` の決まりの原本である（計画は #1081 の「UI モック」）。
生成器の定数はこの文書の写しで、写しがずれていないかは、このプラグインを置いているリポジトリ（hdknr/claude-code-setup）のテスト test-build-mock.py が突き合わせる。
表の形は `references/tables.md`、散文の仕様書は `references/prose.md`、spec-loop の見つけ方と版の範囲は `references/spec-loop.md`。

モックは**表から生成する参考資料で、受入基準ではない**。承認の対象は表で、モックは生成物として commit しない（#1081 の決めること 7）。
**モックに出る画面の名前・項目・ボタン・条件・根拠は、どれも表の中身である**——モックにだけある画面・ボタンを作らない。

## 走らせ方

```text
python3 scripts/build-mock.py <docs ディレクトリ> [--upto <n>] [--since <コミットかタグ>] [--spec-loop <spec-loop のプラグインの根>]
```

- v1〜v<n>（`--upto` を省くと作業中の版——番号が最大の版）を spec-loop の重ね方で重ねた表から作る。重ね方・spec-loop の見つけ方・対応する版の範囲は `check-screens.py` と同じもの（読み込む）。
- `--since` に基準の時点（前回の会のコミットかタグ）を渡すと、その時点から変えた画面・項目・遷移に印を付ける（下の「差分の印」）。
- **表の検査の結果に依らず作る**——辿れない画面・遷移の無いボタン・未決定のセルがあっても作る。検査は `check-screens.py` を先に回す（#1081 の「回答の反映 → 起票 → 検査 → モックの生成」の順）。
  この値は推奨で決めて確認の Issue で利用者に確かめる。

## 出力

| 決まり | 値 |
| --- | --- |
| 出力の置き場所 | `<docs の親>/build/mock/v<n>/` |
| 出力のファイル | `index.html` |

- 出力は HTML 1 枚だけで、ほかのファイルを書かない（正本の git の index も書き換えない——git は任意のロックを取らない形で呼ぶ）。表を JSON にして埋め込み、描き方の JS も埋め込む。
- **外のファイル・CDN を読まない**——`<script src>`・`<link>`・画像・フォントを書かない。ファイルを開くだけで、オフラインでも見られる。
- 時刻を書かない——同じ入力からは同じバイトを作る。

## 共有の層だけを出す

説明の欄にも埋め込む JSON にも、共有の層だけを出す（req-loop がレビュー会で扱うのは共有の層だけ）。

- **埋め込む列は次の表の列だけ**——ここに無い列（profile の列のうち開発者が決めるもの——パスなど）は、表にあっても埋め込まない。

| 表 | 埋め込む列 |
| --- | --- |
| 画面 | `画面ID`・`画面名`・`種別`・`親画面`・`主たる利用者`・`ステータス`・`参考資料`・`目的と背景`・`できること`・`機能`・`帳票`・`仕様書`・`根拠` |
| 項目 | `番号`・`画面ID`・`まとまり`・`並び順`・`項目名`・`種類`・`中身`・`例`・`必須`・`入力チェック`・`エラーメッセージ`・`並び替え`・`絞り込み`・`根拠` |
| 遷移 | `番号`・`遷移元`・`きっかけ`・`操作`・`条件`・`遷移先`・`結果`・`根拠` |
| Q&A | `No`・`質問`・`選択肢`・`推奨`・`回答`・`状態` |

- **Q&A の行は共有の層（`Q-`）だけを埋め込む**——レビュー会の進め方に載せる行と、画面・項目・遷移のセルから指される行。内部の層（`D-`）の行は埋め込まない。

- **どのセルからも、内部の層の Q&A の番号（`D-`）を外す**（番号だけを囲んでいた括弧と、余った区切りも外す）。番号の形は spec-loop の `check-qa-csv.py` を読み込む。

## 描き方

種別（`references/tables.md` の「種別」）で決める。値は項目の `例` を最初の値にし、モックの中だけで覚える（どこにも保存しない）。

| 種別 | 描き方 |
| --- | --- |
| `list` | 種類 `一覧` の項目を表にする。列は同じ画面の種類 `一覧の列` の項目のうち、`まとまり` がその一覧の `項目名` のもの（`並び替え` が `はい` の列に印、`絞り込み` が `はい` の列に入力欄）。`例` で 1 行を描き、一覧の項目を `きっかけ` にする遷移があれば行を押せる |
| `form` | 種類 `入力` の項目を入力欄にする（`必須` が `はい` なら印。入力チェックとエラーメッセージは説明の欄） |
| `dialog` | 親の画面を描き、その上に重ねる |
| `tab` | 親の画面の中のタブにする。タブを選ぶとその画面になる |
| `detail`・`top` ほか | 項目を `まとまり` ごとに `並び順` で並べる |

- 一覧の表は、`list` のほかの種別の画面でも同じに描く（種類 `一覧` の項目を持てば）。
- **種類 `ボタン` の項目は、それを `きっかけ` にする遷移で動く。** 遷移が 1 つならその行き先へ、2 つ以上（条件の違い）なら遷移の番号・条件・行き先を並べて選ばせる。
  ボタンのほかの項目（`表示`・`一覧の列`）も、それを `きっかけ` にする遷移があれば押せる（同じ動き。中身の無い項目は `項目名` を出して押せる大きさにし、列の無い一覧は `項目名` の 1 行を持つ）。
  `入力` の項目は入力欄を入力に使い、隣に置く「→ 項目名」で遷移する。
- **タブの中のタブ**（親画面がタブの `tab`）は、開いた画面までの道筋のタブを選んで描く。親画面が巡っている表（検査の違反。`tab` でも `dialog` でも）でも、同じ画面を 2 度描かずに止まる。
- **表に無い遷移を呼ぶと「遷移が表に無い」と出す**——遷移の無いボタンは灰色にし、押すとそう出す。描き方のファイルが表に無い遷移の番号を呼んでもそう出す。
- **`#screen=<画面ID>` で開くと、その画面が出る**（`dialog` は親の上に、`tab` は親の中で選ばれて）。表に無い画面ID なら「画面が表に無い」と出す。省くと、種別 `top` の最初の画面（無ければ表の最初の画面）。

## 説明の欄

画面の横に出す。

- いまの画面の目的と背景・できること・主たる利用者（とステータス・根拠）
- 項目の中身と根拠（入力の項目は入力チェックとエラーメッセージも）
- ボタンにカーソルを当てると、遷移の番号・行き先・操作・条件・結果・根拠
- 通った遷移の履歴
- 散文に置いた次元（`references/prose.md` の「散文」の節）は、仕様書の節へのリンクとして出す——リンクの先は、その画面の `仕様書` を持つ最も後の版の Markdown のファイル（相対のパス）で、節の名前を添える。重ねた全体に無い（`removed.csv` で消した）仕様書は指さない

## 差分の印

2 つの差分に印を付ける。どちらも、変わった画面・項目・遷移にだけ付け、変わっていないものには付けない。

| 差分 | 比べるもの | 付ける版 |
| --- | --- | --- |
| 前の版から | v<n-1> の時点の全体と v<n> の時点の全体（spec-loop の `diff-versions.py` の `compare` を読み込む——写さない） | v2 以降（v1 には付けない） |
| 基準の時点から | `--since` の時点の `docs` を同じ版（その時点に無ければその時点の最大の版）まで重ねた全体と、いまの全体（`diff-versions.py` の `compare_maps`） | `--since` を渡したとき |

- 単位は行の単位で重ねる表の鍵（画面ID・項目と遷移の番号）。足した・変えた・消したの言葉は `diff-versions.py` のもの（`追加`・`変更`・`削除`）。同じ中身の置き直しは変更に数えない。
  **埋め込む列だけを `D-` を外して比べて同じなら、変更に数えない**——内部の層の番号や埋め込まない列（パスなど）だけが変わった行に印を付けると、共有の層には何も変わって見えない所に印が出て、内部で何かが変わったことだけが漏れる。
- **前の版からの印も、項目に付ける**（#1081 は版の間の差分を「画面と遷移」と書いている。項目だけを変えた版でも変わった所を触って確かめられるように、推奨で決めた——確認の Issue で利用者に確かめる）。
- **変えた根拠**: 変わった行（消した行は前の行）のセルにある共有の層の Q&A の番号。消した行は、`removed.csv` の理由に書いた番号も足す（基準の時点からの差分は v1〜v<n> の `removed.csv` のうち、その行を名指しした最も後の版の理由）。
- 印は、画面の見出し・画面の選択・項目の下（それを `きっかけ` にする遷移の印も）・ボタンにカーソルを当てたときの説明・画面の説明の欄の「変わったもの」に出す。
  描き方の差し替えの画面は、項目の下の印を描かない（説明の欄には出す）。
- **消したもの**: 差分で消えた画面・項目・遷移を「消したもの」の一覧に並べる。選ぶと、前の行の中身（埋め込む列だけ・`D-` を外す）と理由（`removed.csv`）と根拠を説明の欄に出す。
  その画面の項目・その画面を遷移元にする遷移の削除は、画面の説明の欄の「変わったもの」にも出す。
- **基準の時点の取り出し**: `docs` の git で `--since` の値をコミットに解決し、その時点の `docs` を一時ディレクトリに取り出して重ねる（終わったら消す。正本も git の index も書かない）。
  解決できない・`docs` が git の外・その時点に `docs` が無いなら 2、その時点の重ね合わせが決まりに反するなら 1。

## レビュー会の進め方

モックの上の「レビュー会の進め方」の一覧に、今回の会の質問を Q&A 表の順に並べる。

- **今回の会の質問**は、共有の層の Q&A のうち `状態` が `反映済み` でない行——req-loop がレビュー会の PPTX に載せる行と同じ選び方（spec-loop の `qa-to-pptx.py` の `read_pending`）。
- 質問ごとに、質問の文・選択肢（推奨に印）・行の分け方（下）と、**その質問の画面**を出す。選ぶと最初の画面に飛ぶ（`#screen=`）。画面が 2 つ以上なら、それぞれへ飛ぶ印も並べる。画面に掛からない質問はそう出す。
- **その質問の画面**（「質問 → 画面」の逆引き）: 画面の行・その画面の項目・その画面を遷移元にする遷移のどれかのセルに、その質問の番号がある画面（画面の表の順）。

## 未回答・未反映

| 行の分け方 | 決め方 |
| --- | --- |
| `未回答` | `回答` が `未回答`（spec-loop の `check-qa-csv.py` の `NO_ANSWER`）か空 |
| `未反映` | `回答` があり、`状態` が `確認中`——「回答はあるが未反映」（spec-loop の `references/qa-csv.md`） |
| `暫定反映` | `回答` があり、`状態` が `暫定反映` |
| `反映済み` | `回答` があり、`状態` が `反映済み` |

- **未回答の質問に掛かる項目・遷移**（セルにその質問の番号がある。共有の層だけ）には「推奨案（X）で描いている。Q-… は未回答」と出す（推奨が `なし` なら「推奨なし（表の値で描いている）。Q-… は未回答」）。
  項目の下と、ボタンにカーソルを当てたときの説明に出す。画面の説明の欄には、その画面に掛かる未回答の Q&A（質問の文・選択肢・推奨）を並べる。
- **画面に掛かる Q&A の行**（その画面の逆引きと同じ範囲。共有と内部の層）**に `未反映` が残っていたら、生成器が警告する**（標準出力に `警告:` で始まる行。モックは作る——終了コードは 0）。
  モックの画面の説明の欄にも、その画面に掛かる共有の層の `未反映` の行を出す（内部の層の行は出さない）。

## 描き方の差し替え

汎用の描き方で表せない画面は、案件ごとに描き方を差し替えられる。

| 決まり | 値 |
| --- | --- |
| 置き場所 | `<docs の親>/screen-spec/renderers/`（版の外） |
| ファイルの名前 | `<画面ID>.js` |
| 版の中で止める名前 | `renderers` |

- **版の外に置く**（#1081 の決めること 10）。どれかの版のディレクトリ（`docs/v<k>/`）の下に `renderers` という名前のディレクトリが在れば、生成器は何も書かずに止める（1）——
  版の中に置くとサインオフで比べる範囲に入り、見た目だけの変更でも 2 つの承認の取り直しになる。
- ファイルは素の JS で、**関数の本体**として書く（生成器が `function (ctx) { … }` で包んで埋め込む）。画面名の見出し・説明の欄・タブは生成器が描き、ファイルはその画面の中身を描く。
- **差し替えても、名前・ボタン・遷移は表から読む**——`ctx` が表を渡す:

| `ctx` の名前 | 中身 |
| --- | --- |
| `ctx.screen` | その画面の行（列の名前 → 値） |
| `ctx.items` | その画面の項目の行（`並び順` の順） |
| `ctx.root` | 描く先の要素 |
| `ctx.button(番号)` | その画面のボタンの項目を、表の遷移で動くボタンにした要素（表に無い・ボタンでない項目なら、誤りを示す要素） |
| `ctx.item(番号)` | その画面の項目を既定の描き方で描いた要素 |
| `ctx.value(番号)` | 項目のいまの値（モックの中で覚えた値か `例`） |
| `ctx.follow(遷移の番号)` | 遷移をたどる（表に無ければ「遷移が表に無い」） |

- 表に無い画面ID のファイル・`.js` でないファイルは埋め込まず、警告する（止めない）。
- 描き方のファイルは 1 つずつ別の `<script>` に置く。ファイルが失敗したら（構文の誤りで読み込めないときも）、その画面にその旨を出して既定の描き方で描く——ほかのファイルは巻き込まない。

## 何で作ったかの印

生成した HTML に次を出す（見える文字と `<meta>`）。表が同じでも生成器の版で見た目は変わるので、承認したときのモックが何で作られたかを後から辿れるようにする。

| 印 | 中身 |
| --- | --- |
| 版 | `v<n>` |
| 表の出どころ | `docs` の git のコミットと、そのコミットを指すタグ（サインオフのタグなど）。`docs` に未コミットの変更があればそう書く。git の外ならそう書く |
| 生成器 | screen-spec の版（`.claude-plugin/plugin.json`） |
| 描き方のファイル | `screen-spec/renderers/` を最後に変えたコミット（未コミットの変更があればそう書く）。差し替えが無ければ「差し替え無し」 |

## 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 書いた |
| 1 | 決まりに反する——重ね合わせ（基準の時点の重ね合わせを含む）が spec-loop の決まりに反する・3 つの表が揃っていない・見出し行が決まりと違う・描き方のファイルが版の中に在る。書かない |
| 2 | 判定していない——引数の誤り・`docs` が無い・`--upto` の版が無い・`--since` を解決できない（git の外・その時点に `docs` が無いときも）・読めない・書けない・想定外の例外 |
