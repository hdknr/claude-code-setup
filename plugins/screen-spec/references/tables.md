# 画面・項目・遷移の表

画面の仕様は、表（画面・項目・遷移の 3 つの CSV）と散文の仕様書の組み合わせで持つ。この文書は表の形と、`scripts/check-screens.py` が表に当てる検査の原本である
（散文の仕様書の決まりは `references/prose.md`、spec-loop との境目は `references/spec-loop.md`）。
検査の本体の定数はこの文書の写しで、写しがずれていないかは、このプラグインを置いているリポジトリ（hdknr/claude-code-setup）のテスト test-check-screens.py が突き合わせる。

## 置き場所

spec-loop の正本リポジトリの版のディレクトリ（`docs/v<n>/`）の下に置く。

```text
requirements/screens/
├── data/
│   ├── screens.csv         # 画面（台帳を兼ねる）
│   ├── screen-items.csv    # 項目
│   └── transitions.csv     # 遷移
├── settings.csv            # 案件ごとの設定（下の「案件ごとの設定」）
├── common.md               # 画面横断の共通仕様（任意。形は references/prose.md の「共通仕様」）
├── templates/
│   └── spec.md             # 案件の仕様書の雛形（init が置く。add が使う）
├── wireframes/
│   └── <画面ID>.drawio     # ワイヤーフレーム（add が雛形を置く。書き出しの .svg を隣に置く）
└── <slug>.md               # 画面ごとの仕様書（screens.csv の 仕様書 の列が指す。add は <画面ID>.md で置く）
```

`init`・`add` のスキル（同梱の `scripts/write-screens.py`）がこの形で置く（下の「`init` と `add`」）。

- 3 つの表は spec-loop の版の重ね方で行の単位で重なる（v2 以降は足した行と変えた行だけを置く。消すときは `removed.csv` に種類 `画面`・`項目`・`遷移`）。
  重ね方の本体は spec-loop のプラグインの versions.md の「行の単位で重ねる表」で、検査はその重ね方（spec-loop の `merge-versions.py`）を読み込んで重ねた全体に当てる——写さない。
- 3 つのうち 1 つでも置いたら、3 つとも置く（行が無くても見出し行だけは置く）。どれも無ければ検査するものが無い（0）。
- 文字コードは UTF-8（BOM はあってもよい）。1 行目は見出し行で、下の列名と同じ文字列・同じ順。見出し行は版の間で変えない（#1105）。

## 案件ごとの設定（`settings.csv`）

案件ごとに決める値を、`requirements/screens/settings.csv` に置く。`init` が置き、ファイルの単位で重なる（spec-loop の版の重ね方。v2 以降で値を変えるなら、ファイルごと置く）。
見出し行は `項目,値`。

| 項目 | 値 | 既定（`init` の引数を省いたとき） |
| --- | --- | --- |
| `画面IDの接頭辞` | `add` が採る画面ID の頭。英大文字で始まり、英大文字と数字が続き、`-` で終わる（`S-`・`SCR-`）。spec-loop の成果物の表の番号の頭（`F-` など）と重ねず、画面ID が Q&A の番号の形（`Q-`・`D-`）や未決定の印（`TBD-`・`TODO-`）にならないもの | `S-` |
| `profile` | 実現方式の profile の名前（このプラグインの `profiles/` にあるもの）か `未設定` | `未設定` |

- `profile` の初期値は、`init` のスキルが spec-loop の基盤要件（`shared/infra.csv`）のフロントエンドの行（`項目` が `frontend`・`フロントエンド`）から推し、利用者に確かめて決める。
  このプラグインに profile がまだ無い（#1094 で足す）ので、いまは `未設定` だけを置ける。
- 検査（`check-screens.py`）は設定を見ない——画面ID が接頭辞で始まるかも見ない（手で置いた画面ID を止めない）。

## `init` と `add`

**`init`**（`write-screens.py init`）は、作業中の版（いちばん大きい `v<n>`）の `requirements/screens/` に、3 つの表（見出し行だけ）・`settings.csv`・`common.md`・`templates/spec.md` を置く。
重ねた全体か作業中の版にどれか 1 つでも在れば、何も書かない。版が 1 つも無ければ何も書かない（版を作るのは spec-loop）。

**`add`**（`write-screens.py add`）は、画面を 1 つ足す。足すものは次の 3 つで、**項目と遷移の行は足さない**（ボタンと遷移は画面の中身で、利用者と決めて表に足す）。

- 画面の表の 1 行——作業中の版の `screens.csv` に足す（無ければ見出し行と一緒に置く）。`ステータス` は `下書き`、`仕様書` は `<画面ID>.md`。ほかの列は引数のまま。
- 仕様書 `<画面ID>.md`——重ねた全体の `templates/spec.md`（案件の雛形）から作る。無ければこのプラグインの雛形（`templates/spec.md`）から作る。雛形の決まりは `references/prose.md` の「雛形」。
- ワイヤーフレーム `wireframes/<画面ID>.drawio`——このプラグインの雛形（画面の枠と、画面ID と画面名の見出しだけ）から作る。書き出し（`.svg`）は spec-loop の `render-diagrams.py`。

**採番**: 画面ID は `<接頭辞><番号>`。番号は 3 桁以上の 0 埋めで、**どの版の 3 つの表の鍵（重ねる前の生の行。`removed.csv` で消した鍵も、前の版の行に在るので含む）の、同じ接頭辞の番号の最大の次**——
消した画面の番号を使い直さない（版の比べで、消した画面と足した画面が同じ鍵になる）。

`add` は Q&A 表を読むだけで書かず、Q&A の番号を振らない（`references/spec-loop.md` の「Q&A の番号を振らない」）。
書いた後の行が検査を通るか（機能・帳票の在りか・入口から辿れること）は見ない——`add` のスキルが書いた後に検査を走らせる。

## 書き方の共通の決まり

- 複数の値を書くセル（`機能`・`帳票`・`根拠`）は、値を `、` で区切る。
- `根拠` はどの行でも空にしない。Q&A の番号（`Q-R-003`・`D-S-001` など。形は spec-loop の Q&A 表の番号）・業務ルール・機能の番号（`F-001`）を書く。
- 未決定のセルには spec-loop の未決定の印（`TBD`・`TODO`・`未定`・`要確認`）と、その件の Q&A の番号を書く（例: `未定（Q-R-012）`）。印のあるセルは値の決まりに当てない。
  `⚠️` は MkDocs で見せる飾りで、印の代わりにならない（`⚠️` だけのセルは警告する）。印に添えた Q&A の番号も、Q&A 表に在ること（`根拠` と同じく照らす）。
- 下の表の「空でよい」が「いいえ」の列を空にすると「必須の欄が空」になる（要る情報がまだ無い）。

## 検査（`check-screens.py`）

```text
python3 scripts/check-screens.py <docs ディレクトリ> [--upto <n>] [--spec-loop <spec-loop のプラグインの根>]
```

v1〜v<n>（省略すると作業中の版まで）を spec-loop の重ね方で重ねた全体に当てる。ファイルは 1 つも書かない——Q&A の番号も振らない（下の「起票の候補」）。

| 検査 | 違反（1） | 未決定（3） | 警告（止めない） |
| --- | --- | --- | --- |
| 形 | 見出し行が上の列と違う・決まった値でない（種別・ステータス・項目の種類・はいといいえ・並び順）・種別と親画面の組・種類に合わない列に値がある | 必須の欄が空 | — |
| 表どうし | 画面ID・項目と遷移の番号が表をまたいで重なる・項目と遷移が表に無い画面を指す・親画面が無い・`きっかけ` が遷移元の画面の項目でない・`仕様書` を 2 つの画面が指す | — | — |
| 辿れること | 入口（種別 `top`）の画面が無い・入口から遷移で辿れない画面がある（`tab` は親の画面が辿れれば辿れる）・それを `きっかけ` にする遷移の無いボタン | — | 未決定のセル（遷移の `遷移元`・`遷移先`・`きっかけ`、画面の `種別`・`親画面`、項目の `画面ID`）があって決められないもの——未決定の種別・遷移元から辿れるかもしれない画面と、遷移先の未決定な遷移が行きうる画面。きっかけの未決定な遷移の数を超える遷移の無いボタンは違反 |
| 根拠 | `根拠` と散文に書いた Q&A の番号が重ねた Q&A 表（共有の `shared/qa.csv` と内部の `spec/qa-dev.csv`）に無い・`根拠` の機能の番号が `features.csv` に無い | — | 回答のある Q&A の行・`removed.csv` で消した Q&A の行を指す（反映を確かめる） |
| 成果物の表 | 画面の `機能` が `features.csv` に・`帳票` が `reports.csv` に・遷移の `操作` が `roles.csv` に無い（表そのものが無いときも） | — | — |
| 未決定の印 | — | 表のセル・散文に spec-loop の未決定の印がある | `⚠️` だけで印の無いセル・行 |
| 散文 | `references/prose.md` のとおり | — | — |

- 未決定の印の判定は spec-loop の `check-spec-exit.py` の `find_markers` を、Q&A の番号の形は spec-loop の `check-qa-csv.py` を読み込む（写さない）。
- 出力は 1 行 1 件で、行頭に `違反: `・`未決定: `・`必須の欄が空: `・`警告: `・`起票の候補: ` のどれかを置く。表のセルは `<表のパス> <鍵> <列>`、散文は `<パス>:<行>` で場所を示す。
- 起票の候補: Q&A の番号を添えていない未決定の印（表のセル・散文の行）を、そのまま出す。番号を振って Q&A 表に起票するのは spec-loop の req-loop・spec-review である（番号は起票したループの印ごとに振るので、ループの外で振ると並行するループと番号がぶつかる）。

### 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 違反も未決定も無い（警告はあってもよい）。画面の表が 1 つも無いときも 0 |
| 1 | 違反がある（未決定も併せて出す）。重ね合わせが決まりに反する（spec-loop の重ね方の違反）ときも 1 |
| 3 | 違反は無いが、未決定の印か必須の欄の空がある |
| 2 | 判定していない——引数の誤り・`docs` が無い・読めない・想定外の例外 |
| 4 | 検査の前に止めた——spec-loop が見つからない・spec-loop の版が対応の範囲の外（`references/spec-loop.md`） |
