# 散文の仕様書（検査が見る分）

画面ごとの仕様書（`requirements/screens/<slug>.md`。画面の表の `仕様書` の列が指す）のうち、`scripts/check-screens.py` が見る形の原本である。
雛形・目次・N/A の書き方の例・レビュー観点は `init`・`add` のスキルの段（#1093）で足す。表の形は `references/tables.md`。
検査の本体の定数はこの文書の写しで、テスト test-check-screens.py が突き合わせる。

## 表と仕様書の相互のつながり

- 画面の表の `仕様書` が指すファイルが在ること。
- 仕様書の最初の `# ` の見出しに、その画面の `画面ID` を書くこと（例: `# S-001 受注一覧`）。
- `requirements/screens/` の直下の Markdown のうち `common.md` のほかは、どれかの画面の `仕様書` から指されていること（表から指されない仕様書を残さない）。

## 節

仕様書は、次の `## ` の見出しをこの順に持つ（13 次元と未決の論点）。この順を崩さなければ、間にほかの `## ` の見出し（profile の節「実現方式: web-spa」など）を置いてよい。

| 見出し | 表で持つか |
| --- | --- |
| `## 1. 基本情報` | 表で持つ |
| `## 2. 画面概要` | 表で持つ |
| `## 3. レイアウト` | 表で持つ |
| `## 4. データ表示` | 表で持つ |
| `## 5. 操作とアクション` | 表で持つ |
| `## 6. 入力とバリデーション` | 表で持つ |
| `## 7. 状態` | 散文 |
| `## 8. 権限とデータの見える範囲` | 表で持つ |
| `## 9. 他システム連携` | 散文 |
| `## 10. 同時編集` | 散文 |
| `## 11. 表示ルール` | 散文 |
| `## 12. 一覧・表の能力` | 表で持つ |
| `## 13. 画面遷移` | 表で持つ |
| `## 未決の論点` | 散文 |

- 「表で持つ」節は、表に置いた次元を手で二重に書かない——本文に表を出す印 `<!-- screen-spec: 表 -->` を置く（MkDocs のフックが、その画面の行を表として節に出す。フックは #1098）。
  印だけの節は空ではない。散文の節に印を置いても、空の節のまま数える。
- 空の節は違反である。書くことが無い節は `N/A` と書き、続けて理由を書く（例: `N/A。他のシステムとやりとりしない`）。`N/A` だけで理由の無い節も違反である。
  HTML のコメント（表を出す印のほかのもの）は中身に数えない。
- 本文に書いた Q&A の番号は、画面の表の `根拠` と同じく重ねた Q&A 表に在ること。未決定の印も表のセルと同じく数える（`references/tables.md` の「検査」）。
- `common.md` は節を見ない（形は #1093 で決める）。Q&A の番号と未決定の印だけを見る。
