# 実現方式の profile

画面の仕様のうち、実現方式（React の SPA・デスクトップアプリなど）で変わる部分を、core（`references/tables.md`・`references/prose.md`）に足す形で持つ——この文書はその原本である。
`scripts/check-screens.py` の profile の定数はこの文書の写しで、テスト test-check-screens.py が突き合わせる。雛形（このプラグインの `profiles/<profile>/`）がこの文書に合うかは、テスト test-write-screens.py が見る。

## 選び方

- 案件の profile は、案件ごとの設定（`settings.csv` の `profile`。`references/tables.md` の「案件ごとの設定」）で選ぶ。値は下の「profile の一覧」の名前か `未設定`。
- **`未設定` なら、profile の列と節を求めない**——表の見出し行は core の列だけで、仕様書・共通仕様に profile の節が無くてよい。
- **profile は表を置く最初の版で決める。** profile の列は表の見出し行に入り、見出し行は版の間で変えない（spec-loop の重ね方が止める）ので、後の版で profile を変えられない。
  方式がまだ決まらなければ、profile を置いて列と節に下の「方式が未定のとき」の書き方をしておく。

## 足すもの

profile は次の 3 つを足す。

1. **表の列**——core の列の後ろに、下の表の順で足す。見出し行は core の列＋profile の列で、`未設定` なら core の列だけ。
2. **仕様書の節**——画面ごとの仕様書の末尾（`## 未決の論点` より後ろ）に `## 実現方式: <profile>` を 1 つ置き、下の「仕様書の小見出し」を `### ` で全部持つ。
3. **共通仕様の節**——共通仕様（`common.md`）を置いたなら、`## 実現方式: <profile>` を 1 つ置き、下の「共通仕様の小見出し」を `### ` で全部持つ。

- 小見出しはどれも空にしない。書くことが無ければ `N/A` と理由を書く（例: `N/A。一覧の画面ではない`。core の節と同じ。`references/prose.md` の「節」）。小見出しの順は問わない。
- 表と散文の書き方（未決定の印・Q&A の番号・「決定」「確定」を使わない）は core と同じ。

## 方式が未定のとき

方式が決まる前でも、core だけで要求を確定できるように、profile の列と節は `N/A。実現方式が未定` と書いておける。

- **節**——節の中身が `N/A。実現方式が未定` で始まれば、小見出しを求めない（続けて、いつ・何で決めるかを書いてよい）。
- **列**——セルに `N/A。実現方式が未定` と書けば、値の決まりに当てない（必須の列でも空の扱いにしない）。
- **この言い回しは未決定の印に数えない**——spec-loop の未決定の印 `未定` を含むが、検査は言い回しを伏せてから印を探す（spec-loop の `未定義` と同じ扱い）。
  方式が決まらないことは要求の確定を止めない（#1081）。決まったら書き直す（レビュー観点。`references/prose.md`）。

## 外部の profile

組織の開発ガイドのような外部の設計パターンを、組み込みの profile の**上に重ねて**読む（#1314・#1458）。外部の profile は組み込みの profile を置き換えず、
値の語彙・種別ごとの既定の値・列を足し、節の既定の答えを起票の候補にする（#1459）。置き場所（パターンの持ち主のリポジトリの `spec-profile/<名前>/`）・`profile.csv`・探し方（手元の clone）・タグの時点の読み出し・
形式の版の比べ方は spec-loop の外部の profile の決まり（spec-loop の `references/external-profile.md`）に従い、`check-screens.py` は spec-loop の `external-profile.py` を読み込んで使う（写さない）。

### 設定の行

案件ごとの設定（`settings.csv`）に `外部の profile` の行を 1 つ置く（`references/tables.md` の「案件ごとの設定」）。値は空白で区切った 3 つ:

```text
外部の profile,<持ち主>/<リポジトリ> <名前> <タグ>
```

- 案件に 1 つまで。行が無い・値が空なら、外部の profile を使わない（今までと同じに検査する）。
- 手元の clone は spec-loop の探し方で探す——環境変数 `SPEC_PROFILE_CLONE` か、案件の根の `CLAUDE.md` の `外部の profile の clone: <持ち主>/<リポジトリ> <パス>` の行。案件の根は `docs` ディレクトリの親。
- 外部の profile の画面の層の `重ねる先`（`profile.csv` の列）は、`settings.csv` の `profile` と同じでなければならない（`未設定` には重ねられない）。

### 画面の層

`profile.csv` の層 `画面` の表（例: `screens/*.csv`）。先頭の `ID,要約,リンク` は spec-loop の決まりで、その後ろに次の列を置く。

| 列 | 書くもの |
| --- | --- |
| `種類` | 下の「行の種類」のどれか |
| `表` | 掛ける表のファイルの名前（種類が答えの行は下の「既定の答え」）——`screens.csv`・`screen-items.csv`・`transitions.csv` |
| `列` | 掛ける列の名前（`種類` が `列` なら足す列の名前、`答え` なら答える項目の名前） |
| `種別` | `種類` が `既定` のとき、画面の種別（`references/tables.md` の「種別」）。ほかの種類では読まない |
| `値` | `種類` が `語彙`・`既定` のとき、その値。`答え` なら下の「既定の答え」。`列` では読まない |

#### 行の種類

| 種類 | 意味 |
| --- | --- |
| `列` | 表に列を足す。core と組み込みの profile の列の後ろに、宣言の順で見出し行に入る。既に在る列の名前は足せない |
| `語彙` | 列の値の語彙を 1 つ足す。語彙のある列のセルは、語彙のどれかでなければ違反（1） |
| `既定` | 種別ごとの既定の値。`screens.csv` の列にだけ書く。既定と違う値を書いた画面は、その行の `根拠` に Q&A の番号が要る（無ければ違反 1） |
| `答え` | 組み込みの profile の項目の既定の答え。決定ではなく推奨として、Q&A 表の起票の候補にする（下の「既定の答え」） |

- 語彙と既定は、core の列・組み込みの profile の列・足した列のどれにも掛けられる。
- 印のあるセル（未決定）・空のセル・`N/A。実現方式が未定` のセルには、語彙も既定も当てない。
- **既定の値は、その列に書ける値でなければならない**（#1571）——同じ列に `語彙` の行があればそのどれか、core の決まった値の列（`種別`・`ステータス`。`references/tables.md`）なら決まった値のどれか、`種別` の列ならその行の `種別` と同じ値。書けない既定を持つ種別の画面は、既定どおりに書けば語彙（決まった値）の外、ほかの値を書けば根拠の無い既定と違う値で、どの値を書いても違反になるので、検査の前に止める（下の「読めないとき」）。語彙も決まった値も無い列（足した列・`web-spa` の `パス`）の既定は照らさない——`パス` の形（`/` で始まる）に既定が合うかも見ない。語彙の行と既定の行の順に依らない。
- **画面の表の決まった値の列（`種別`・`ステータス`。`references/tables.md`）に `語彙` の行を置くなら、決まった値と 1 つは重ならなければならない**（#1581）——重ならなければ、語彙の外の値も決まった値の外の値も違反で、Q&A の根拠でも通らないので、その列にはどの値も書けない。検査の前に止める（下の「読めないとき」）。1 つでも重なれば止めない（重なる値を書けば、その列の違反は消える。`種別` の語彙が入口の種別 `top` を欠けば、表は入口の検査の違反になる——止めない）。語彙の行の順に依らない。`screen-items.csv`・`transitions.csv` の決まった値の列の語彙は照らさない。
- **本文を写さない。** 画面の層の行が持つのは ID・要約・リンクと、上の値だけで、規則の本文は外部の文書にリンクで置く。検査はリンク先を読まず、ファイルを書かない。

#### 既定の答え

組み込みの profile の「誰が決めるか」の表の項目（列と小見出し）について、外部の profile が既定の答えを持つ（#1314 の提案 3・#1459）。
**既定の答えは決定ではなく推奨である**——`check-screens.py` は起票の候補として出すだけで、表のセルと散文の節を埋めず、Q&A の番号を振らない（`references/spec-loop.md` の「Q&A の番号を振らない」）。

行の書き方（種類 `答え`）:

| 列 | 書くもの |
| --- | --- |
| `要約` | 既定の答えの 1 行の要約。空にしない（共有の候補の推奨になる）。本文は写さない |
| `リンク` | 既定の答えを書いた外部の文書の節。空にしない |
| `表` | 項目が列なら、その列のある表のファイル（`web-spa` なら `screens.csv`・`transitions.csv`）。小見出しなら `仕様書`（仕様書の小見出し）か `共通仕様`（共通仕様の小見出し） |
| `列` | 項目の名前——その `表` の組み込みの profile の列か小見出しで、「誰が決めるか」の表にあるもの |
| `値` | 空か、`利用者`・`開発者` のどちらか。空なら項目を決める人の全部の部分に、どちらかならその人が決める部分にだけ掛ける |
| `種別` | 読まない |

起票の候補（行の頭は `起票の候補: `。1 つの行の 1 つの部分ごとに 1 行）:

- 項目の「誰が決めるか」の起票する表が `shared/qa.csv` の部分——**共有の Q&A 表の候補**。外部の profile の既定を**推奨**として、行の ID・要約・リンクを付ける。利用者が確かめるまでは決まっていない。
- 起票する表が `spec/qa-dev.csv` の部分——**内部の Q&A 表の候補**。外部の profile の既定を採ったものとして、行の ID・要約・リンクを付ける。
- 決める人が 2 人の項目（`web-spa` の `ダイアログの実体`・`ファイル出力・印刷`）は、`値` が空なら両方の候補を出す。
- **起票したら、質問に行の ID を書く。** その候補の Q&A 表（共有の候補なら `shared/qa.csv`、内部の候補なら `spec/qa-dev.csv`。版を重ねた全体）の行のどれかの `質問` に行の ID があれば、その候補はもう出さない。
- 候補は終了コードを変えない（未決定の印の起票の候補と同じ）。画面の表が無い案件では出さない（検査そのものをしない）。

次のどれかなら、検査の前に止める（4。下の「読めないとき」）——`表` が上のどれでもない・`列` が空かその `表` の誰が決めるかの項目でない・`要約` か `リンク` が空・
`値` が空でなく `利用者`・`開発者` のどちらでもない・`値` の人がその項目を決めない・同じ項目の同じ部分の答えが 2 行・
ID・`要約`・`リンク`・`表`・`列`・`値` に改行か制御文字（Unicode のカテゴリ C と、行を割る U+2028・U+2029）か Q&A の番号の形がある（候補の行が割れて別の行ができる・振っていない番号が出るので。ID のときは止めた理由にも ID を出さない）。

#### 足す列と見出し行

足す列は表の見出し行に入り、**見出し行は版の間で変えない**（上の「選び方」——このファイルの最初の節）。だから外部の profile（とそのタグ）も、表を置く最初の版で決める。
後の版で外部の profile を足す・外す・足す列の違うタグに変えると、見出し行が決まりと違って違反（1）になる。
`init`（`write-screens.py init`）は、外部の profile を書くときに足す列を見出し行に入れる（#1460）。`add`・UI モックの生成器（`build-mock.py`）・MkDocs のフックは、外部の profile が足した列をまだ知らない——見出し行が決まりと違うとして断る。

### 基盤の profile から引く初期値

基盤の profile が「画面は `web-spa` + `<外部の profile>`」と名指せば、`init` の初期値はそれになる（#1314 の提案 5・#1460）。利用者に確かめて決めるのは今と同じ（`init` のスキルが `hint` の出力から推して訊く）。

- **基盤の profile**——platform-spec の案件の設定（重ねた全体の `shared/platform/settings.csv`。見出し行 `項目,値`、項目 `リポジトリ`・`profile`・`タグ`）が名指す外部の profile。
  置き場所・見出し・項目名は platform-spec の `references/infra-profile.md` の「案件の設定」の写しで、**screen-spec は platform-spec を読み込まない**（このプラグインを置いているリポジトリのテストが platform-spec の定数と突き合わせる）。
- **名指し**——基盤の profile のタグの時点の `profile.csv` の層 `画面` の `重ねる先`（spec-loop の `external-profile.py` で読む。探し方は上の「設定の行」と同じ）。
  名指しがあれば、初期値は `profile` がその値・`外部の profile` が同じリポジトリと名前とタグ（同じ束の画面の層を重ねる）。
- **効くのは `--profile` と `--external` を両方省いたときだけ**——どちらかを渡せば基盤の profile を読まず、省いた方は `未設定`・外部の profile なし。
- **名指しが無い**（`profile.csv` に層 `画面` が無い・`重ねる先` が空）・**基盤の profile が無い**（`shared/platform/settings.csv` が無い）なら、今までの初期値（`未設定`・外部の profile なし）。
- **初期値を決められなければ止める（4）**——設定の 3 つの項目が 1 行ずつ値つきで無い・見出し行が違う・spec-loop に `external-profile.py` が無い・clone が見つからない・タグが無い・`profile.csv` が読めない・
  `重ねる先` がこのプラグインの profile でない・名指しが在るのに値が `外部の profile` の行に写せない形（`リポジトリ` が `<持ち主>/<名前>` でない・profile とタグに空白——名指しが無ければ行に写さないので見ない）・画面の層が読めない（上の「読めないとき」と同じ確かめ。`hint` もこの確かめを通った値だけを初期値として出す）。今までの初期値に落とさない（落とすと profile の無い見出し行が置かれ、後の版で変えられない——上の「選び方」）。値を明示して渡せば進める——
  **ただし画面の層の行が決まりに合わない（下の「読めないとき」の 3 つ目。#1571・#1581 の止め方を含む）なら、同じ外部の profile を `--external` で明示しても止まる**。
  `hint` と引数を省いた `init` はそれを言い分け、外部の profile を直してタグを付け、基盤の profile の設定のタグをそれにする（外部の profile はタグの時点で読むので、直しても設定のタグが同じなら止まったまま）か、`--profile <重ねる先> --external なし` を渡すと案内する（#1582）。
  タグを変える道には 2 つを添える（#1590）——設定は `shared/` に在るので、タグを変えれば spec-loop の 2 つの承認を取り直すことになり、基盤の層（`infra.csv` の `profile の行` が指す行）もそのタグの時点で読むことになる（platform-spec の `references/infra-profile.md` の「案件の設定」）。
  `shared/` を触らずに進めるなら、直したタグを `--profile <重ねる先> --external "<リポジトリ> <名前> <新しいタグ>"` で明示して渡す（`--profile` か `--external` を明示すれば基盤の profile を読まない）。
- 設定の値の形（タグの名前に使える形など）の全部は platform-spec の `check-infra-profile.py` が見る。`init` が見るのは、3 つの項目があることと `外部の profile` の行に写せることだけで、ほかは `external-profile.py` が読むときに判定する。

### 読めないとき

次のどれかなら、`check-screens.py` は検査の前に止める（4）——外部の profile を外して検査を続けない。

- spec-loop に外部の profile を読む部分が無い（spec-loop の版が古い）・手元の clone が見つからない・タグが無い・画面の層が無い・形式の版が上の範囲の外
- 画面の層の `重ねる先` が `settings.csv` の `profile` と違う
- 画面の層の行が上の決まりに合わない（後ろの列・`種類`・`表`・空の `列`・既に在る列を足す・空の `値`・`screens.csv` でない既定・決まった種別でない既定・同じ列と種別の既定が 2 行・どの表にも無い列の語彙と既定・その列に書けない既定・決まった値と 1 つも重ならない `種別`・`ステータス` の語彙（上の「行の種類」）・上の「既定の答え」の行の決まり）。層のファイルの中身が spec-loop の層の表の決まりに合わない（UTF-8・CSV として読めない・先頭 3 列・見出しの同じ名前・列の数・空の ID・層の中で重なった ID——spec-loop の `references/external-profile.md` の「層の表」）のも、これに数える（#1589）——同じタグを名指し直しても止まるので

`settings.csv` の `外部の profile` の行の形が違う（3 つでない・2 行ある）のは、案件の設定の違反（1）である。

## `web-spa`

React などの SPA（ブラウザで動く 1 枚のページのアプリ）。

### 表の列

| 表 | 列 | 書くもの | 空でよい |
| --- | --- | --- | --- |
| `screens.csv` | `パス` | 画面のルート（`/` で始まる）。パスパラメータは `:id` などで書く。絞り込みなどの状態を URL のクエリに載せるなら、それも書く（`/orders?status=`） | 種別が `tab`・`dialog` のときだけ空でよい |
| `transitions.csv` | `種類` | 遷移先を `同じタブ`・`別タブ` のどちらで開くか | はい（空は同じタブ） |

### 仕様書の小見出し

| 小見出し | 書くこと |
| --- | --- |
| `ディープリンク・別タブ` | 他システム・メールから直に開く URL と、そのとき要るもの（ログイン・パラメータ）。別タブで開く画面 |
| `戻る・進む・再読み込み` | ブラウザの戻る・進む・再読み込みで残る状態と消える状態。未保存のまま離れるときの警告 |
| `ダイアログの実体` | モーダルにするか。URL を持つか。Esc・外側のクリックで閉じるか（種別 `dialog` の画面と、ダイアログを開く画面） |
| `一覧の送り方` | ページ番号か、無限スクロールか。表の横スクロール |
| `ファイル出力・印刷` | ダウンロードのしかた（署名付き URL など）・印刷 |
| `認証と権限の外れ` | セッションが切れたとき、権限の無い URL を直に開いたとき（403・404 の表示） |

### 共通仕様の小見出し

| 小見出し | 書くこと |
| --- | --- |
| `アプリの外枠` | 共通ヘッダー・左メニュー・パンくず |

### 誰が決めるか

各項目の未決のことは、決める人に合わせて Q&A 表に起票する（番号を振るのは spec-loop の req-loop・spec-review。`references/spec-loop.md`）。
利用者に見えるものは共有の Q&A 表（`shared/qa.csv`）、実現の手段だけのものは内部の Q&A 表（`spec/qa-dev.csv`）に起票する。

| 項目 | 決める人 | 起票する表 |
| --- | --- | --- |
| `パス` | 開発者 | `spec/qa-dev.csv` |
| `種類` | 利用者 | `shared/qa.csv` |
| `ディープリンク・別タブ` | 利用者 | `shared/qa.csv` |
| `戻る・進む・再読み込み` | 利用者 | `shared/qa.csv` |
| `ダイアログの実体` | 見た目と閉じ方は利用者、URL は開発者 | `shared/qa.csv`・`spec/qa-dev.csv` |
| `一覧の送り方` | 利用者 | `shared/qa.csv` |
| `ファイル出力・印刷` | 利用者の操作は利用者、ダウンロードの方式は開発者 | `shared/qa.csv`・`spec/qa-dev.csv` |
| `認証と権限の外れ` | 利用者 | `shared/qa.csv` |
| `アプリの外枠` | 利用者 | `shared/qa.csv` |
| `対象デバイスと画面幅` | 利用者 | `shared/qa.csv` |
