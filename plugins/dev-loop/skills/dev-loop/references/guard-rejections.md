# ガードに拒否されたとき

**これは `dev-loop` スキルの一部である。** `SKILL.md` 手順 6 から移した。
**拒否されたときにだけ読む**ので起点から外してある——**規範としての重さは変わらない。**
**`（必須）` はここでもそのまま効く。**

**読む条件**: **worktree 隔離セッションのガードにコマンドを拒否されたとき。**
**拒否されていない周では読まなくてよい。**

worktree 隔離セッションには**ガードがあり、
一部の形を拒否する**。以前ここには
`test "$(git rev-parse --git-dir)" != "$(git rev-parse --git-common-dir)" && …` と
書いていたが、**この形は拒否される**——**実測**（2026-09-17、
[#110](https://github.com/hdknr/claude-code-setup/issues/110)）。
**つまりこの関門は、いちばん効いてほしい状況（worktree の中）で走らなかった。**
  **いまは `scripts/check-pr-preconditions.sh` が突き合わせを中でやるので、
  呼ぶ側は素の 1 行で済む**（#136 段 3）。
**`SKILL.md` 手順 6 の `git rev-parse` のコードブロックが 1 行ずつに割ってあるのは、
この実測の結果である**（**このファイルにはそのコードブロックは無い**）。
- **守る形（必須）**——**素のコマンドを 1 行ずつ、パスもスクリプト名もリテラルで書く。**
  **値の突き合わせは、走らせる側ではなく読む側でやる。**
- **拒否されたら、メッセージ全体を読んで、そこが指示している対処のとおりにする（必須）。**
  **「割る」は対処のひとつであって、唯一の対処ではない**——**割っても通らない形がある**。
  「リダイレクトを外せ」と言われているなら**外す**のであって、割っても変わらない。
  **メッセージが求めている当のものを読み取ること**が、この項の全部である。
  **どの対処がどれだけ出たか（件数と内訳）と、対処文の言い回しは
  [#112](https://github.com/hdknr/claude-code-setup/issues/112) を正とする。**
  **ここにあるのは「読み取って従う」という指示だけ**——
  **観測した集合が対処の全部だとは確かめられない**ので、
  **数えた一覧を規範に写すと、次に出た対処が「無いもの」になる。**
- **メッセージの形が 1 つだと思わない（必須）。** **規則文（`Refusing to run it …`）を
  持たないメッセージがある**——実測で、**本文そのものが対処になっている形がある**（[#112](https://github.com/hdknr/claude-code-setup/issues/112)）。
  **つまり「規則文の後ろが対処」という切り出し方が効かない形がある。**
  **だから決まった位置を見にいくのではなく、全体を読む。**
  - **理由節は入力の一部を埋め込む（必須）。**
    **`, but ` の直後の理由節は、パスを伏せてもなお多くの種類に散る**
    （[#122](https://github.com/hdknr/claude-code-setup/issues/122)）——
    **理由節が拒否されたコマンドの断片をそのまま含む形がある**ため
    （例: 「runs gh with the text …」）、
    **理由節を鍵にして分類や一致判定をしてはならない。**
      - **ここに件数を書かない（必須）。** 以前は「拒否 870 件・理由節 106 通り・
        うち 62 通りは 1 件」と書いていたが、**どれも、いま同じ置き場所を数え直すと
        そのままでは再現しない**（このリポジトリの `collect-guard-rejections.py`。
        **スキルの中ではなく、`claude-code-setup` 側にある**）。
        **件数の食い違いは母集団の違いで、理由節の残差は特定できていない**
        （#137）——**どちらも、範囲はそのスクリプトの docstring を正とする。**
        **この行が支えている規範は件数に依らない**ので取り下げないが、
        **一度「870 だけが再現しない」と書いて、そこから導いた 106 と 62 を
        事実として残したまま関門に反証された**——**同じ測定から出た数は、
        まとめて扱う。**
  - **「この形は見たことがない」を根拠にしない（必須）。**
    **同じ 1 環境の中でも、版ごとに現れた理由節の種類は 1 〜 35 通りとばらついた。**
    **ばらつきの原因は特定していない**——**その版で何をしていたかと交絡している。**
    **だから「増えた」とも「落ち着いた」とも読まない。**
    **読むべきことは 1 つだけ——次に出る形を、いま数えた集合から決めない。**
- **対処が、対処になっていないことがある（必須）。** 実測で、
  **「素のコマンドで走らせろ」と言われたが、それは既に素のコマンドだった**
  （[#112](https://github.com/hdknr/claude-code-setup/issues/112)）。**言われたとおりにしようがない形がある。**
  **そのときは同じ形で 2 度目を試さない**——**そのコマンドを走らせること自体をやめて、
  成果を別の道で出す**（長い本文は**ファイルに落として渡す**、編集は
  ファイル編集ツールで行う、など）。**2 度目で通ることを期待しない。**
- **出し直すときは、元のコマンドが扱っていた項目を数え直す（必須）。**
  **複合を分割すると、項目が落ちる。** **実測**
  （[#123](https://github.com/hdknr/claude-code-setup/issues/123)。
  拒否 870 件から 40 件を無作為抽出して後続を読んだ）——
  **40 件中 1 件で、4 日分をまわすループが 3 日分に減ったまま集計され、
  結論はその 3 日分の上で述べられていた。**
  **落ちたことは出力に出ない**——**分割後のコマンドはどれも成功する。**
  **だから、分割する前に元のコマンドが何件を扱っていたかを書き出し、
  分割後に同じ件数が揃ったかを数える。**
- **出し直さないと決めたなら、諦めたことを明示する（必須）。**
  **同じ実測で、40 件中 1 件は出し直さずに次の作業へ進んでいた。**
  **拒否されたことは差分にも成果物にも残らない**ので、
  **黙って進むと「やったが失敗した」と「やらなかった」が区別できなくなる。**
  **原則「必須手順を落とすときは、黙って落とさない」がここにも掛かる。**
- **復帰そのものは安い（実測）。** **同じ 40 件のうち 38 件（95%、
  95% 信頼区間 83.5〜98.6%）は、別の形で同じ成果を得ていた**
  （[#123](https://github.com/hdknr/claude-code-setup/issues/123)）。
  **上の 2 項は、残る 2 件が何だったかである。**
  **「安いから気にしなくてよい」ではなく、「安いが、落ちるときは静かに落ちる」。**
- **次の 3 つは、macOS だけの観測ではない（必須）。** **Linux でも同じだった**
  ——**(1) 拒否が起きること**、**(2) 理由節**、**(3) メッセージの形**
  （包みの有無・規則文の有無）。**harness 版・アーキテクチャ・当てた形を揃えて振った**
  （[#122](https://github.com/hdknr/claude-code-setup/issues/122)）。
- **この節の他の実測は、Linux で取り直していない（必須）。**
  **拒否からの復帰の成否も、分割で項目が落ちる形も、理由節の種類数も、
  版ごとのばらつきも、すべて macOS の 1 環境で測ったままである。**
  **「この節は Linux でも確かめた」と丸ごと読まない**——**確かめたのは上の 3 つだけ。**
  **一度ここに「ここまでの指示は macOS だけの観測ではない」と書いて、
  関門に「10 個の項目に一括で掛かってしまう」と反証された。**
- **ただし「振った次元は OS だけ」ではない（必須）。** **揃えられなかった次元が残る。**
  **一覧と件数は [#122](https://github.com/hdknr/claude-code-setup/issues/122) を正とする**
  ——**ここには置かない。**
  **一度ここに「認証も揃えた」と書いて関門に反証され、直したあとも
  件数を 3 箇所に書いていて 2 巡目にまた反証された。**
  **列挙を 2 箇所に置くのが、この撤回が壊れた原因そのものである。**
- **ただし「OS に依らない」と読んではならない（必須）。** **当てたのは一握りの形**で、
  **境界を確かめたのではない**（境界の特徴づけを追わないのは #112 の判定のとおり）。
  **測ったのはコンテナで、実機の Linux は別環境である。**
  **Windows は測っていない。**
  **確かめた範囲と、確かめていないことの範囲は
  [#122](https://github.com/hdknr/claude-code-setup/issues/122) を正とする。**
- **経緯・観測・陽性対照・未解決は
  [#112](https://github.com/hdknr/claude-code-setup/issues/112) を正とする。**
- **Bash に寄せられない場面がある。** ファイルの編集がガードに当たるなら、
  **その編集はファイル編集ツールで行う。**
- **ただし「別の道具に移せば通る」ではない（必須）。** ガードは `Bash` だけに
  掛かるものではない——**コマンドを受け取る別の道具も、ファイル編集ツールも、
  拒否された実測がある**（[#112](https://github.com/hdknr/claude-code-setup/issues/112)）。**移し替えを「回避できた」の根拠にしない。**
  **確かめるのは、移した先が通ったかどうかである。**
- **ファイル編集が拒否される形は、原因が別である（必須）。** 実測では、
  **共有チェックアウト側のパスを編集しようとして**拒否されている。
  **そのときは worktree 側のコピーを編集する**のであって、
  **コマンドの書き方を変えても解けない。**
  **このメッセージは規則文を持たない**ので、**上の「全体を読む」がここで効く。**
