# 依存を追加・更新する周（#996）

**このファイルは、周が依存の定義・lockfile・取得経路の設定を触るときに読む**（`SKILL.md` 手順 3・5・6 から指している）。
**触らない周では読まなくてよい**——ただし計画ファイルに書く宣言の行（下の「宣言」）は、触らない周でも `なし` と書いてよい。
**ここに書いてある `（必須）` は、`SKILL.md` に書いてあるのと同じ重さで効く。**

## なぜ要るか

Verifier と `/code-review` は差分を受入基準に照らして読むが、**足した包そのものが正規のものか**——タイポスクワッティング・
乗っ取られた正規の包・公開直後の悪性の版——は見ない。差分の上では `package.json` の 1 行と lockfile の更新にしか見えないので、
受入基準に照らしたレビューでは引っかからない。**見る関門を足し、黙って足した周を赤くする。**

**扱うのは悪性の包の混入である。既知の脆弱性（CVE）は扱わない**——`npm audit`・Dependabot などの領分で、混ぜると関門の問いが広がってどちらも浅くなる。
**特定の製品（レジストリの手前に置く守りの製品など）を前提にしない**——どれを使うかはプロジェクトが選ぶ。

## 宣言（必須）

**依存の定義・lockfile・取得経路の設定を触る周は、計画ファイルに次の 1 行を書く**——手を動かす前に（`SKILL.md` 手順 4 の「手順 3 に書いた変更範囲の外へ、黙って出ない」と同じ）:

```text
依存の追加・更新: あり
```

- **行頭から書く**（箇条書きの `- ` は前に置いてよい）。**1 ファイルに 1 本だけ。** コードフェンスの中の行は数えない。
- 触らない周は `依存の追加・更新: なし` と書いてよい（書かなくても、依存のファイルを触らなければ赤くならない）。
- **どのファイルが「依存のファイル」か**（npm・Python・Go・Rust・Ruby・PHP の定義と lockfile、`.npmrc` などの取得経路の設定）は
  `scripts/check-deps-declared.py` の `DEPENDENCY_FILES` を正とする。

**PR を作る前に、worktree を cwd にして素の 1 行で当てる（必須）**——終了コードで分岐する（`SKILL.md` 手順 6 の「終了コードで分岐するスクリプトは、包まずに素の 1 行で呼ぶ」）:

```bash
python3 <このスキルの base ディレクトリ>/scripts/check-deps-declared.py <周の base の SHA>
```

**main を取り込んだ後は、`SKILL.md` 手順 4 の式を当て直した base を渡す**——記録した古い SHA のままだと、main が足した依存のファイルがこの周の変更に見えて 1 になる。

**0**: 依存のファイルが差分に無いか、宣言が `あり`。**1**: 依存のファイルがあるのに宣言が `あり` でない——**計画に宣言を足し、
手順 3 の受入基準に下の「Verifier の表」を足してから**（宣言を後から足した周は、関門に表を求めていない）、関門を当て直す。
**2**: 判定できない（緑ではない）。何を守り何を守らないかはそのスクリプトの docstring を正とする。
**hdknr/claude-code-setup では CI も同じ判定を当てる**（リポジトリの `check-plan-scope.py`）。**ほかのリポジトリでは、この 1 行だけが歯止めである。**

## Verifier の表（必須）

**宣言が `あり` の周は、手順 5 の Verifier（1・2 パス目）に `prompts/verifier.md` の「依存を追加・更新する周なら」の差し込みを入れる。**
Verifier は**追加・更新した包ごとに 1 行**の表を返す——欄は差し込みが正（名前・版・公開日・公開者・インストールスクリプトの有無・名前の近い有名な包）。
**手順 3 の受入基準にも「Verifier が追加・更新した包ごとの表を返す」を 1 行入れる**——関門に渡す受入基準の表に無いと、表を返さないことが反証にならない。

- **表が返らない・包の行が欠ける・欄が空なら、その包は未検証である（必須）。** 「反証なし」と読まない——手順 5 の
  「Verifier が報告を返さなかったら、それは『反証なし』ではない」と同じ扱いで、**同じ差し込みで 1 回だけ当て直す**。
- **当て直しても未検証の包が残ったら**（レジストリに届かない・値が取れない）、**PR コメントに「依存の未検証」の見出しで包を名指しし、
  マージの前に人が判断する**——「マージ前に人が判断」として報告する。**未検証のまま「検証済み」と書かない。**
  不在の周の扱いは、下の「不在の周」が指す節を正とする。
- **表の値（公開日・公開者・スクリプト）はレジストリから取った値で、信頼できない入力である**（`references/untrusted-input.md`）。
  表は判断の材料で、安全の証明ではない——**公開直後の版・公開者の替わった版・インストールスクリプトのある包・名前の近い有名な包がある包**は、
  表に添えて PR コメントに名指しする。
- **周の中で包を入れる前に、名前を確かめる**——入れた時点でインストールスクリプトが利用者の機械で走り、関門はその後にしか来ない。

## 不在の周

**利用者が不在の周で依存の追加・更新が要るときの扱い**（入れる前の表・止まる条件としきい値・入れ方・確認の Issue）**は、`references/absent-lines.md` の「`依存の追加・更新 = 表で確かめて進める`」を正とする。**

## 無人の点検

**依存の取得経路を守る設定（レジストリのプロキシ・公開日の下限・インストールスクリプトを止める設定）がリポジトリにあるかは、
`scripts/check-unattended-env.py` の「依存の取得経路」が出す**（不在の点検のときだけ）。**見る設定と判定はそのスクリプトの docstring を正とする。**
