# 委譲文の行を見直して刈り込む段（#1194）

**これは `dev-loop` スキルの一部である。** `SKILL.md` 手順 8 が、**効いた行を記録するときと、見直しの段を回すときにここを読め**と指示している。

委譲文（`prompts/*.md`）は、事故のたびに行が増える。各行に事故の番号が付いているのは強みだが、**行を外す条件と見直す段が無いと、
委譲文の長さそのものが Verifier の注意を薄め、どの行が今も効いているかが分からなくなる**（Claude Code チームも、ルールは放っておけば増える一方として刈り込む）。
**「削らない」を「黙って削らない」に置き換える**——外してよいのは、この段を通った行だけである。

## 行と台帳

- **行**は `prompts/*.md` の項（最初の `---` の後ろの、行頭が `数字. ` か `- ` の行）。**全部の項が台帳 `references/line-registry.csv` に載る（必須）**。
- **台帳の列と ID・引き・登録日の決まりは `scripts/line-effects.py` の docstring を正とする**（ここに列挙しない）。`SKILL.md` の行も、載せたいものは台帳に足してよい。
- **項を足したら台帳にも足す（必須）**。`python3 <このスキルの base ディレクトリ>/scripts/line-effects.py items` が、未登録の項の登録行の案を出す
  （`元の事故` は項の本文に現れた番号を機械で写した初期値で、事故の番号とは限らない——**人が直す**）。
  このリポジトリでは `check-prompt-lines.py` が CI で台帳と原文の食い違いを落とす。

## 効いた行を記録する（必須）

**周を閉じる前（手順 8 の件数の行と同じ時点）に、計画ファイルへ書く。** 関門（Verifier・`/code-review`）の指摘のうち、**採否の表に載せたもの 1 件ごとに、
その指摘を挙げさせた委譲文の行**を台帳から引く——Verifier は反証ごとに「とくに見てほしいこと」の番号を添えて返すので、その番号の項が台帳のどの行かを引く
（`/code-review` の指摘は `prompts/review-handoff.md` の項）。**行頭から装飾なしで 1 行 1 項**:

```
- 効いた行: V-05（実行されない主張を当てて、docstring の変異が赤にならないと示した）
- 効いた行: なし
```

- **どの行にも当たらない周は `- 効いた行: なし` を 1 行書く**（書かない周は「記録のある周」に数えず、効いていない周数の分母に入らない）。`なし` と ID は 1 ファイルに混ぜない。
- **関門を回さなかった周・`prompts/` を使わなかった周は書かない。**
- 指摘がどの行に当たるかが決められないときは、**当てずに `なし` と書き、採否の表に理由を残す**（近い行で代用しない）。

## 見直しの段

**いつ**: 台帳の行が増えたとき、または利用者が求めたとき（周の決まりには載せない——周ごとに回すものではない）。**誰が**: 人間が起こし、Claude が集計する。

```bash
python3 <このスキルの base ディレクトリ>/scripts/line-effects.py report docs/plans [--window N]
```

出るのは、**行ごとの最後に効いた周・効いた周数・効いていない周数・元の事故**と、**外す候補**（効いていない周数が窓 `N` 周以上の行。既定 30）と、
**まとめる候補**（同じ `同趣旨` を持つ行）である。**候補は根拠つきの一覧であって、削る判断ではない**——効いていない行は、事故が防がれ続けているだけかもしれない。
分母は記録のある周だけで、**この台帳より前の周には記録が無い**ので、候補は記録が貯まってからしか出ない（`line-effects.py` の「守らないもの」）。

### 外す（必須の手順）

1. **人間の承認を取る**。候補の行ごとに、根拠（効いていない周数・元の事故）と、外すと何が再発しうるかを添えて `AskUserQuestion`（不在の周では訊かず、確認の Issue の下書きにして外さない）。
2. **その行の元の事故を再現する eval を `plugins/dev-loop/evals/<名前>/` に足す**（`case.yaml` の冒頭のコメントに `# 外した行: <ID>` と `# 元の事故: <番号>`——台帳の `元の事故` の番号を全部入れる）。
   **eval は行を外した後の版で通る**ように書き、**行を外す前の版では赤になる陽性対照を取る**（ケースの冒頭に結果を書く。形は `evals/resume-no-new-worktree/case.yaml`）。
3. **PR で外す**——原文の項と台帳の行を同じ PR で消す。**PR に `run-dev-loop-evals.py` の要約を貼る**（外した後も eval が通ることを人間が見る。課金するので CI からは呼ばない）。
4. **台帳の行を消すだけにしない**——ID は再利用しない。**まとめる**場合は、残す行の `統合元` に外した行の ID を書き、**両方が同じ `同趣旨` を持っていた**ようにする（同趣旨の行が残るので eval は要らない）。

`check-prompt-lines.py` が、**外した行に eval の `case.yaml`（`外した行`・`元の事故`・`graders`）が差分に在ること**を CI で落とす。**eval が実際に元の事故を再現するか・通ったかは見ない**ので、
人間が PR の要約と陽性対照で見る。

## 守らないもの

- 周が `効いた行` を書き忘れたこと（申告の漏れ）と、どの行に当てるかの判断の誤り。
- 台帳に載っていない `SKILL.md` の行（`prompts/` 以外は載せた行だけが対象）。
- **効いていない行が不要であること**——見直しの段は候補を挙げるだけで、外す根拠は eval と人間の承認が持つ。
