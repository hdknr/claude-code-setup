# 関門の体の報告をファイルにも残す（#1503）

**これは `dev-loop` スキルの一部である。** `SKILL.md` 手順 5 の「関門の体には、報告をリポジトリの外の 1 つのファイルにも書かせ」の項が、**ここを正とする**と指している。
**手順 5・6 で関門の体を起こす周は、どの周も読む**（cruise の子に限らない）。

**なぜ要るか**: 関門の体（Verifier・`/code-review`）の終わりの報告は、起こした側に届かないことがある。
cruise（dev-loop 2.18.0・Claude Code 2.1.331）では、子（サブエージェント）が起こした体の報告が子ではなく cruise の親の会話に届き、
1 日に 30 回を超える転送・再送が要り、2 パス目の Verifier の報告が親にも子にも残らず失われて起こし直したことが 2 回あった
（[#1503](https://github.com/hdknr/claude-code-setup/issues/1503)）。体に報告をリポジトリの外のファイルにも書かせたら、子がそれを読んで回収できた。
**届く経路を 2 つにして、どちらかが残れば欠票にしない**のがこのファイルの決まりである。

## 起こす側がすること

1. **体を起こすたびに、報告のファイルのパスを 1 つ決める**——`<scratchpad の絶対パス>/gate-<周の Issue>-<関門>-<パス>-<UTC 時刻>.md`
   （関門は `verifier`・`code-review`・`narrow`（狭いパス）・`redo`（当て直し）・`lens-<名前>`（多レンズ・fan-out の体）、パスは `1`・`2`。時刻は `date -u +%Y%m%dT%H%M%SZ`）。
   - **リポジトリの外で、`~/.claude/` の配下でもない絶対パスにする**——体はリポジトリと `~/.claude/` を書かない（委譲文の「実環境を壊さないこと」）。scratchpad が無い環境では、
     `mktemp -d` で作ったリポジトリの外のディレクトリの下にする。
   - **起こすたびに新しい名前にする**（起こし直しも）——古いファイルに残った終わりの印で、待ちが抜けないように。
   - **計画ファイルの「関門の進捗（再開点）」に、関門とパスと一緒に書く**——割り目・圧縮の後に再開した側が、通知を待たずにそのファイルを読める。
2. **委譲文の `{{報告のファイルの絶対パス}}` にそのパスを入れて渡す**（`prompts/verifier.md`・`prompts/review-handoff.md`。狭いパス・当て直しも同じ `prompts/verifier.md`）。
   **体の `description` に周の Issue 番号を入れる**（例: `#1503 Verifier pass 1`）——報告が誤って別の会話に届いたとき、受け取った側が宛先の周を決める材料になる（cruise の `SKILL.md` §4 の 2）。
3. **完了は、通知の有無に依らず、報告のファイルの最後の行 `__DEV_LOOP_REPORT_DONE__` で判定する。** 呼び出しの結果か通知に報告が返ったら、それも報告である。
   **どちらかに報告があれば欠票ではない**——呼び出しの結果が空・「報告を届けずに終わった」の形でも、ファイルに終わりの印つきの報告があれば、それを報告として読む。
   **報告が 2 つあって食い違ったら、どちらかの反証も採否の表に載せる**（`SKILL.md` 手順 5 の「遅延票と再実行票が並立したら」と同じ——体数で打ち消さない）。
4. **ファイルを待つときは、前面のコマンドで区切って待つ**（ターンを終えない。cruise の `../cruise/references/parallel.md` の「通知だけを頼りに待たない」と同じ理由——前面の長い待ちは背景に移される）。
   2 つの呼び出しのどちらにも、同じ絶対パスをそのまま書く（シェルの変数は呼び出しをまたがない）:

   ```bash
   R=<報告のファイルの絶対パス>; end=$(( $(date +%s) + 100 )); until grep -qx '__DEV_LOOP_REPORT_DONE__' "$R" 2>/dev/null || [ "$(date +%s)" -ge "$end" ]; do sleep 10; done; if grep -qx '__DEV_LOOP_REPORT_DONE__' "$R" 2>/dev/null; then echo "待ち: 報告が届いた"; else echo "待ち: 区切りの時間"; fi
   ```

   - **`待ち: 報告が届いた`**——ファイルを読む（終わりの印の行は報告に含めない）。長ければ、反証の件数と反証の行だけを読む（`SKILL.md` 手順 5 の「道具の生出力を、親の文脈に積まない」）。
   - **`待ち: 区切りの時間`**——同じ待ちをもう一度走らせる。通知は呼び出しの合間に届くので、届いていればそれを読む。
5. **終わりの印が無いことだけでは、起こし直さない。** 体はまだ動いているかもしれない——起こし直すと同じ関門を 2 体が回し、報告が 2 つ並ぶ（#1503 では子が「まだ届かない」として起こし直そうとした）。
   **欠票として起こし直すのは、次のどちらかのときだけ**（`SKILL.md` 手順 5 の「Verifier が報告を返さなかったら、それは『反証なし』ではない」の再実行に当たる）:
   - **体が終わったと分かったのに、報告がどこにも無い**——呼び出しの結果・自分に届いた通知・親から知らされた通知（cruise）のどれかで体の終わりが分かり、その本文にも報告のファイルにも報告が無い。
     **体の宛先（`agentId`）が分かれば、まず 1 度だけ `SendMessage` で「報告を `<パス>` に書け」と頼み、上の待ちを 1 回（100 秒）走らせる。** それでもファイルに印が無ければ起こし直す。
   - **起こしてから 2 時間たっても、印も通知も無い**（2 時間は推奨で決めた値。`check-all.py` の順番待ちを含む重い段でも収まる目安）。
   **起こし直すときは新しいパスで起こし**、計画ファイルの再開点に、欠票と起こし直したことと古いパスを書く。古い体の報告が後で届いたら、届いた反証は採否の表に載せる（上の 3）。
6. **体が「書けなかった」と返したら、その返事が報告である**——ファイルが無くても欠票ではない。書けなかった理由を計画ファイルに書く。

## 体がすること

**文面は委譲文（`prompts/verifier.md` の「報告の形」・`prompts/review-handoff.md` の「報告のファイル」）が持ち、ここはその原本である。**

- **最後の返事と同じ全文を、渡されたパスにも書く。** 書き方は、全文を `<パス>.tmp` に書き（ヒアドキュメントの区切りを引用符で囲む——本文の `$`・バッククォートを展開させない）、
  最後の行に `__DEV_LOOP_REPORT_DONE__` を足してから `mv` で `<パス>` に置く——途中で切れた報告を、終わったと読ませない。
- **書いてよいのは、そのパスと `<パス>.tmp` の 2 つだけ。** リポジトリと `~/.claude/` を書かない禁止・副作用のある操作をしない禁止は変わらない——このファイルは起こした側が渡した報告の書き先で、検証の操作ではない。
- **報告を書き終える最後の手順にする**——書いた後に検証を足さない（足すとファイルと返事が食い違う）。
- **書けなかったら、最後の返事にその旨とコマンドの出力を書く。**

## cruise で親に届いたとき

**親の扱い（写してパスだけを子に知らせる）は cruise の `../cruise/SKILL.md` §4 の 2 の「子が起こした関門の体の報告が親に届いたら」を正とする。**
子の側は、親から知らされたパスのファイルを、自分の報告のファイルと同じに読む（上の 3〜5）。

## 確かめたこと

- **Claude Code 2.1.331・macOS、2026-11-24、#1503 の周**（cruise の親が起こしたサブエージェントの子）で観測した:
  - 子が `Agent` に `name` を付けると、「Teammates cannot spawn other teammates」で拒まれた（1 回）。`name` を付けずに起こすと通った。
  - `name` を付けずに起こした体 3 体（`Explore`・haiku が 2、`dev-loop:dev-loop-verifier`・haiku が 1。01:37〜01:39Z）は、どれも呼び出しの結果が
    「The subagent ended without delivering a report through SubagentHandback, so no report was delivered. Its unsent text is not shown.」で、返事の本文は子に届かなかった（3/3）。
    3 体目に `Bash` で scratchpad のファイルへ書かせたものは、書かせた 3 行がそのまま読めた。
- **確かめていないこと**: 届かなかった本文が親の会話に現れたか（子からは親の会話が見えない）・どの条件で届かないか・体が `SubagentHandback` を持っていたか。
  **原因は特定していない**——#1503 の「親に届く」とこの周の「届かずに結果だけが返る」が同じ原因かも分からない。**Claude Code への報告はしていない**（外への送信なので利用者が決める）。

## 守らないもの

- **体が指示に従ってファイルを書くか**——委譲文で頼むだけで、書かない体は防げない（そのときは上の 5 の欠票の判定に落ちる）。`/code-review` はスラッシュコマンドで、内部の体を選べない（`SKILL.md` 手順 6）。
- **ファイルの中身が体の書いたものか**——同じ scratchpad に書ける体はほかにもいる。パスを起こすたびに変えるのは古い印の取り違えを避けるためで、改ざんは防がない。
- **実装役（`prompts/implementer.md`）・spec-loop の判定役の報告**——このファイルの範囲の外。
- **ハーネスの通知の経路の修正**（Claude Code の側）。
